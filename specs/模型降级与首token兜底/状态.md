# 模型降级与首 token 兜底

## 模式

口径定稿。定义 agent 任务在模型层失败时的降级规则：什么算模型层失败、切什么模型、哪些任务允许切、报告怎么标注、model 8（deepseek-v4-pro）在链路里的定位。

口径定稿 2026-11-05；已实现并上线本地运行库（`be90324`，迁移 `0190`，应用 PID 35627，8787 正常）。真正的端到端验证是 2026-11-06 18:40 那轮板块机会筛选：截至 11-05 19:50，`agent_run_metric` 里降级事件为 0 条，链路尚未被真实失败触发过。

## 一、证据（本地 PG，只读）

`agent_run_metric`，2026-10-01 起：

| 模型 | 调用 | 成功 | 失败 | 成功率 |
| --- | --- | --- | --- | --- |
| model 8 `deepseek-v4-pro` | 33 | 17 | 16 | 51.5% |
| model 5 `glm-5.3` | 233 | 229 | 3 | 98.3% |
| model 6 `GLM-5.3-Flash` | 19 | 19 | 0 | 100% |

model 8 补充事实：

- 16 次失败 `first_text_ms` 全为空——从头到尾没有出现可见文本。
- 失败 `total_ms` 84.3–224.4 秒；成功首 token 中位 104.8 秒、p90 399.9 秒、最长 562.0 秒；成功总时长平均 281.9 秒。
- 2026-11-05 run 1075：18:40:13 首次调用 input 10561 / output 386 / first_text 空，104.9 秒 `terminated`；18:47:12 重试 input 与 output 均为 0，84.3 秒再次 `terminated`——第二次请求在连接层就被掐断，根本没有到达模型。
- 同一时段其他任务（model 5）全部 complete，只有绑定 model 8 的这条任务连续失败。
- 结论：失败发生在「出第一个字之前」，与输入规模无关（失败平均 input 32k，成功平均 140k）。上游行为，具体原因未定位，不做归因。

**推论：不能用「首 token 超时秒数」作为主要判据。** 失败在 84–224 秒就终止，而成功首字中位 105 秒、最长 562 秒；任何低于 562 秒的阈值都会杀掉大量本来能成功的运行。

## 二、模型层失败的三类判定

同时满足「是模型层」才触发降级，其他错误（工具校验、数据库、业务前置条件）不触发：

1. **零 token 终止**：请求已发出，但 input/output token 都为 0，或以 terminated 结束且从未收到任何文本增量。判定为「上游未接通」，立即切。
2. **已出字但流中断**：收到过文本增量后以 terminated/错误结束，且没有产出完整结果。判定为「中途掐断」，立即切，不再同模型重试。
3. **看门狗超时**：600 秒内没有收到任何文本增量、也没有报错（连接挂住不动）。600 秒 = 观测到的最长成功首字 562 秒 + 余量。超过即判卡死，切。

现状的「失败后等 5 分钟同模型重试」整条移除：1075 的第二次重试 input/output 全 0，说明等多久都没用。

## 三、降级执行规则

- 触发后**立即**切 fallback，不等待、不延后。
- 降级目标：`glm-5.3`（model 5，系统默认模型，233 次成功率 98.3%，同期其他任务全部成功）。model 5 不可用时才用 `GLM-5.3-Flash`（model 6，19/19）。
- **只降一次，不级联**：fallback 也失败就判任务 failed，不得再切第二个模型，不得进入无限重试。
- 降级是任务级策略，默认关闭；按第四节白名单逐任务开启。
- 降级不改变任务输入与口径：同一份数据、同一份提示词，只换模型。

## 四、哪些任务允许降级

- **允许**（非实时、次日可回看、产出为报告或观察，用户不会据此当刻下单）：
  - `nightly_sector_opportunity_scan`（板块机会筛选，本轮开启）
  - `pre_market_news_scan`、`limit_up_close_scan`、`swing_signal_scan`、`two_year_reversal_scan`、`value_anchor_opportunity_scan`、`value_monthly_rank`、`cross_strategy_selection`、`weekly_trading_review`、`daily_plan_flow`、`evening_plan_preview`
- **不允许**（盘中实时、与当刻执行直接相关，换模型会让口径漂或赶不上时点）：
  - `position_intraday_watch`、`ultra_short_exit_watch`、`ultra_short_watch_observe`、`ultra_short_auction_watch`、`first_board_intraday_scan`、`auction_opportunity_assessment`
- 数据同步类任务（`*_sync`、`daily_data_update`、`weekly_full_market_indicators`）不走模型，不涉及。
- 本轮只对实际绑定 model 8 的任务开启（当前只有板块机会筛选）。其他任务已用 model 5/6，成功率 98% 以上，不开启。

## 五、时效窗口约束

降级必须在任务自己的时效窗口内完成，过期不出报告：

- 盘前类（`pre_market_news_scan`、`daily_plan_flow`、`evening_plan_preview`）在 09:15 前没跑完，直接判 failed，不得产出过期报告。
- 收盘后类（板块机会筛选 18:40、`limit_up_close_scan`）当晚跑完即可，无额外截止。
- 降级前先估算剩余窗口；窗口不够就不切，直接 failed 并写明原因。

## 六、报告与消息标注

降级运行必须在产出里显式标注，放在报告开头与飞书摘要首行：

`降级运行：deepseek-v4-pro → glm-5.3（原因：零 token 终止，2026-11-05 18:40）`

- 标注原模型、降级模型、触发类别（零 token 终止 / 流中断 / 看门狗超时）、发生时间。
- 降级轮的报告不得作为策略口径变更依据，不得与主力运行结果混排比较；同一晚既有主力又有降级时，只保留一份最终报告并注明来源模型。
- 降级事件必须写入任务运行记录与当周复盘，不得只留在日志里。

## 七、model 8 的定位

- **只用于长文本、可容忍延迟的非实时报告任务**，不做系统默认模型，不进盘中链路。
- 依据：成功首 token 中位 104.8 秒、p90 399.9 秒，延迟高；同窗口成功率 51.5%。
- 报告类任务保留 model 8 的前提是降级兜底生效且降级率可控；不加兜底就把它从报告类任务里撤掉。

## 八、观测与退出条件

- 每周复盘统计：各任务降级次数、触发类别、降级后是否成功、报告质量差异。
- **一周内同一任务降级 ≥2 次**：重新评估该任务是否继续用 model 8，评估结论写进周报，不由代码自动切换。
- 连续两周零降级且 model 8 成功：保持现状，不调阈值。
- 看门狗 600 秒若误杀过成功运行（同一任务出现「超时切走后 fallback 也失败、原模型重跑成功」），才允许上调，且必须有该次记录作为依据。

## 九、验收

1. 构造「零 token 终止」：模拟首次调用 0 token + terminated，断言立即切 fallback、不等待、总耗时不含 5 分钟延迟。
2. 构造「已出字中断」：断言不重试同模型，直接走 fallback。
3. 构造「看门狗」：无文本增量超过 600 秒，断言判卡死并切 fallback。
4. fallback 也失败时任务状态为 failed，不产出空报告、不写关注池、不级联第三个模型。
5. 降级轮报告含首行标注与四个字段（原模型、降级模型、触发类别、时间）。
6. 不在白名单的任务（如 `position_intraday_watch`）遇到同样错误不走降级。
7. 时效窗口外不降级：盘前任务 09:15 之后判 failed。
8. 用 2026-11-05 run 1075 的实际形态做一次回放（只读构造），验证判定分支与现网错误分类一致。

## 十、不可变约束

- 不因降级改变任务输入、提示词、策略口径与数据来源。
- 降级不产生买卖指令、不绕过任何确认。
- 密钥仍只在设置表，降级日志不得记录 base_url 之外的凭据信息，不得打印 API Key。
- 不新增外部依赖；不引入「多模型投票」这类未验证机制。
