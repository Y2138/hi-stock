# AKShare 数据研究

把中文财经数据请求转换为可复现的 AKShare 获取、校验、整理与导出流程。AKShare 聚合公开网站，无需 Token，但上游网页变化可能导致接口、字段或可用历史区间变化。

## 固定原则

1. 项目内任务优先使用 PostgreSQL datasource 服务与受控工具；仅在扶摇不可用、缺少相应能力或用户明确指定 AKShare 时使用本 skill。降级必须显式报告来源、原因和数据边界。
2. 不凭记忆编写接口名、参数或字段。先用脚本 `search`/`describe`，必要时核对 [官方文档](https://akshare.akfamily.xyz/) 的当前说明。
3. 每次结果记录 AKShare 版本、接口名、参数、拉取时间、行数和字段。导出脚本会自动生成 `.meta.json`。
4. 只对超时、连接中断等瞬时错误重试一次；空表、参数错误、接口变更不得盲目重试。
5. 对关键数据执行主键去重、日期排序、字段存在性、数值类型、首末日期和样本数检查。缺失时说明影响，不补造数据。
6. 保留原始中文字段；只有下游契约明确要求时才重命名，并保存字段映射。
7. 不把实时快照、当前股票列表、当前 ST 名单或当前板块成分用于历史点时回测。
8. AKShare 的“A股”或“涨停池”不是本项目可交易池。获取后继续执行数据库当前投资总策略中的交易权限以及 ST、退市、上市初期等排除规则。

## 标准工作流

### 1. 明确请求

确定资产类型、代码、市场、日期范围、频率、复权方式、字段、输出格式和研究目的。默认口径：

- “最近走势”：20 个交易日；
- “最近一段时间”：3 个月；
- “财报趋势”：最近 8 个季度并保留公告/报告期；
- “市场情绪”：最近交易日，明确数据截止时间；
- A 股东财接口通常使用 6 位代码，如 `600519`；不同来源的代码格式不统一，必须以接口签名和文档为准。

### 2. 检查环境

AKShare 要求 64 位 Python 3.9+。优先使用项目现有虚拟环境，不静默修改系统 Python。

```bash
python3 .agents/skills/akshare/scripts/akshare_tool.py doctor
```

缺少依赖时，在选定虚拟环境中安装或升级：

```bash
python3 -m pip install --upgrade akshare
```

### 3. 查找并确认接口

先从 [references/接口指南.md](references/接口指南.md) 选择候选接口。涉及涨停/连板、历史回测、复权、板块成分或财务点时数据时，必须先读该参考文件的对应章节。

```bash
python3 .agents/skills/akshare/scripts/akshare_tool.py search 涨停
python3 .agents/skills/akshare/scripts/akshare_tool.py describe stock_zt_pool_em
```

如果本地函数签名与参考文件不同，以当前安装版本的签名和官方在线文档为准，并在结果中记录差异。

### 4. 小样本冒烟

先调用单标的、单日或短区间，确认非空、字段和日期都符合预期，再扩大范围。不要一开始并发抓取全市场。

```bash
python3 .agents/skills/akshare/scripts/akshare_tool.py call \
  stock_zh_a_hist \
  --params-json '{"symbol":"000001","period":"daily","start_date":"20260101","end_date":"20260131","adjust":""}' \
  --preview 5
```

### 5. 分批获取和落盘

- 单标的长历史：按标的分批，必要时再按年份分段；
- 全市场截面：按交易日归档，避免当天重复请求；
- 分钟数据：按标的和短日期窗口获取，先核对接口保留期；
- 中间文件写入 `支撑/tmp/` 并在任务结束清理；生产行情按项目规范写入 `支撑/data/`；
- CSV 用于人工检查和中小结果，Parquet 用于全市场或长期回测数据。

```bash
python3 .agents/skills/akshare/scripts/akshare_tool.py call \
  stock_zt_pool_em \
  --params-json '{"date":"20260722"}' \
  --output 支撑/tmp/涨停池_20260722.csv
```

### 6. 校验和交付

至少报告：数据源接口、AKShare 版本、时间范围、复权口径、样本数、缺失或失败区间、输出路径。研究结论必须区分事实、推导和数据限制。

## 涨停与打板数据

- `stock_zt_pool_em` 等东财涨停池提供近期涨停、连板数、首次/最后封板时间、炸板次数和行业字段；官方明确说明只能获取近期数据。
- 接口可能包含北交所、退市整理等本项目不可交易标的；不得只按接口名称或官方股池描述推断交易权限。
- 近期接口适合每日归档、盘后研究和短窗口验证，不足以单独构成多年无偏回测数据集。
- 多年回测需要历史全市场股票列表、退市股、历史 ST 状态、上市日期、停复牌、涨跌停制度和点时行业归属。缺少任一关键层时，明确标注不可验证的偏差。
- 判断涨跌停使用不复权价格或官方涨跌停价；技术指标和连续收益可另用一致复权序列。不得用复权收盘价直接判断是否涨停。
- 实际打板还需要分钟或逐笔成交与排队模型。仅有日线时，只能验证“收盘确认后次日开盘交易”等不依赖盘中顺序的版本。

## 错误处理

- `ModuleNotFoundError`：在所用解释器的虚拟环境安装 AKShare；
- 接口不存在：升级后用 `search` 查找更名接口，并核对官方 changelog；
- 空表：依次检查非交易日、日期超出保留期、标的未上市、参数格式和上游接口失效；
- `JSONDecodeError`、列数不匹配、连接关闭：通常是上游结构变化，记录版本和异常，有限重试后停止；
- IP 限制或频繁失败：降低并发、增加间隔、使用本地缓存，不绕过站点限制；
- 部分成功：保留成功分段与失败清单，不宣称完整完成。

## 工具说明

`scripts/akshare_tool.py` 提供四个只读命令：

- `doctor [--smoke]`：检查 Python、AKShare 版本，可选执行股票列表网络冒烟；
- `search <关键词>`：搜索当前安装版本暴露的接口名和文档首行；
- `describe <接口名>`：查看真实签名与 docstring；
- `call <接口名> --params-json ... [--output ...]`：调用接口、预览、导出并写元数据。

脚本不替代官方文档，也不自动判断某份数据是否具备点时有效性。
