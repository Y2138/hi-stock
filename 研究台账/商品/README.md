# 商品研究台账

商品侧的落点是 A 股：每个品种都要给出具体标的、当前价、相对均线的位置、盈亏比，以及今天是否值得入场。这里不给期货下单建议。

品种：黄金、铜、原油。**钢、锂本轮不在范围**（本地无数据、无目录、任务已停），见下方「未接入品种」。新增品种按规定 `品种/01-标的走势.png 02-进场推荐度.png 03-每日结论.md` 三件产物齐备后再建目录，命名不另创。

## 数据口径

只取本地 PostgreSQL，取不到就写「缺失」，不用记忆或推测补数字。**分析师不外部取数**：本地没有的品种或指标一律标缺失，数据够不够是数据层的事，接入由数据层加同步任务完成，分析师只读库。

| 内容 | 来源 |
|---|---|
| 商品主力连续日线（铜、黄金、原油） | `market_bar`，`freq='futures_day'`，沪铜为 `CU0` |
| 商品分合约当日行情与持仓 | `market_bar` + `market_futures_daily_detail`（`open_interest`/`settlement`） |
| 商品库存 | `market_factor_series` / `market_factor_observation`，`series_code='shfe.cu.inventory.total'`（周度） |
| A 股代表标的后复权日线 | `market_bar`，`freq='day'`，`adjustment='forward'` |
| A 股当日价与估值 | `hithink-finance market snapshot` / `valuation snapshot` / `financials income --period quarterly` |

本目录不写外采端点、不存 Key、不直接调数据源客户端。本地缺数据的品种就标缺失，什么时候接入由数据层决定。

## 主推荐度公式（1%–100%，可复现）

**主推荐度只用股票侧技术面，商品端不计入主分。** 这样三个品种口径一致、可以横向比较，也符合「落点在 A 股」。

`norm(x, k) = tanh(x / k)`，输出落在 −1…1。

```
t = 0.40·norm(close/MA20 − 1, 0.08)
  + 0.35·norm(close/MA60 − 1, 0.12)
  + 0.25·norm(20日涨跌幅, 0.20)

主推荐度 = clip( round(50 + 49 × t) , 1 , 100 )
```

- 三项权重固定 0.40 / 0.35 / 0.25，不随品种变化，也没有商品端权重。
- **留档从 2026-11-16 开始，不倒填。** 2026-11-16 当天的铜是旧口径（含商品端 20% 权重），已在当日结论里注明并回改为主分口径值；`02-进场推荐度.png` 里已画的点保留旧口径、不回改，2026-11-17 起按新口径累积。
- PNG 上的长曲线是用同一公式回算的「回溯曲线」，仅作位置参照，不是当时的留档评分；真实留档以 `03-每日结论.md` 的「推荐度」列为准。

## 盈亏比公式

```
止损 = 近 20 个交易日最低价 × 0.98
目标 = 近 20 个交易日最高价
盈亏比 = (目标 − 现价) / (现价 − 止损)，写成 1:x（风险 1、收益 x）
```

止损贴着近 20 日低点时，盈亏比会算出很高的值（如 1:8），这类数字是下跌趋势里的机械结果，一根阴线就能打掉止损，解读时按当日结论里的说明来，不要只看数字。

## 是否值得入场

| 条件 | 结论 |
|---|---|
| 推荐度 ≥ 60 且收盘价 > MA20 且盈亏比 ≥ 1:2 | 是 |
| 推荐度 < 40，或收盘价在 MA60 之下且 20 日跌幅 > 15% | 否 |
| 其余 | 观察，给出具体触发位 |

## 任务拆分

一个品种一个独立任务，时间互相错开。三条硬约束：

1. **全部排在 17:00 之后**：系统每日数据获取任务在 17:00 跑，早于它取数拿到的是前一交易日数据。
2. 相邻任务至少间隔 10 分钟，避免同时抢数据源和模型。
3. 避开 18:25 `two_year_reversal_scan` 与 18:40 板块机会筛选。

| 任务名 | 品种 | 时间 | 产出目录 |
|---|---|---|---|
| `research_desk_商品_黄金` | 黄金 | 17:25 | `研究台账/商品/黄金/` |
| `research_desk_商品_铜` | 铜 | 17:35 | `研究台账/商品/铜/` |
| `research_desk_商品_原油` | 原油 | 17:40 | `研究台账/商品/原油/` |

**为什么是 17:25 起**：`daily_data_update` 的 cron 是 `15 17 * * 1-5`，当日日线 17:15 才写进 `market_bar`。原排期 17:10/17:15 与它撞车，会出现「股价取到当日、MA 还是前一交易日」的混算。现在三条都在 17:20 之后，留了 10 分钟缓冲。

**三条在用户私聊会话串行执行**（2026-11-16）。DSH 任务按会话隔离：不同会话并行、同一会话排队。串行后前一条没跑完后一条会等，名义间隔只决定最早投递时点。

**顺延风险要记着**：末条名义 17:40，若单条跑满 5 分钟会拖到 17:45 之后，正好撞 A 股半导体（另一个会话，跨会话并行、不受商品串行保护）。按单条 3–4 分钟估算有余量；一旦实测超时，把三条压到 5 分钟间隔（17:25 / 17:30 / 17:35）。等首轮真实耗时出来再定。

每个任务只跑自己那一个目录，三件产物写齐；商品端缺数的品种要在 01 图标题和 03 表里都标「缺失」。调度落地（`job_definition` + 迁移）由 DM 负责，本目录只定义任务边界、时间与产出。
