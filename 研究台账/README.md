# 研究台账

每日研究留档：走势图、进场推荐度、每日结论表。目的是把「今天看到了什么、值不值得做」按行业沉淀成可回看的记录，而不是只看当天的一次对话。

## 目录结构

```
研究台账/
  A股/
    半导体/      01-标的走势.png  02-进场推荐度.png  03-每日结论.md
    光伏设备/    同上三件
    消费电子/    同上三件
  商品/
    黄金/        同上三件
    铜/          同上三件
    原油/        同上三件
  模板/          结论表与推荐度表的空白模板
```

新增行业/品种时，在同一层级加子目录，三件产物同名，不要另创命名。

## 三件产物

| 文件 | 内容 | 口径 |
|---|---|---|
| `01-标的走势.png` | 标的走势图 | A 股用行业指数叠加代表标的；商品用主力连续价格 |
| `02-进场推荐度.png` | 当日进场推荐度走势 | 折线，纵轴固定 0–100，按 1%–100% 计；从首次留档日起累积，**不倒填历史评分** |
| `03-每日结论.md` | 每日结论表 | 列固定：日期 / 标的 / 当前价 / 位置 / 盈亏比 / 推荐度 / 是否值得入场 |

`位置`写相对 MA20、MA60 的高低关系，不要只写「强势」「偏弱」这类形容词。
`是否值得入场`必须是一句可判断的话，不能只给分数。

## 数据口径

- 只取本地 PostgreSQL；取不到就如实写「缺失」并注明缺口，不许用记忆或推测补数字。
- 推荐度从首次留档当天开始记，历史日期不补算、不倒填。
- 商品分析的落点是 A 股：必须给出具体标的、当前价、位置和盈亏比，说明现在是否值得入场；不给期货下单建议。

## 编码约定

- CSV 统一用 UTF-8 带 BOM 写入（兼容 Excel 直接打开中文）。
- 任何脚本读取台账 CSV，一律按 `utf-8-sig` 打开，并把它写进脚本，而不是靠人记得。
- 图片统一 PNG，文件名不随日期变，日期体现在内容与结论表里。

## 任务与时间

一个行业/品种一个独立任务，任务名格式 `research_desk_A股_半导体`、`research_desk_商品_黄金`，时间互相错开：

| 任务 | 时间 | 状态 |
|---|---|---|
| A 股 半导体 | 17:45 | 已确认 |
| A 股 光伏设备 | 17:51 | 已确认 |
| A 股 消费电子 | 17:57 | 已确认 |
| 商品 黄金 | 18:03 | 已确认 |
| 商品 铜 | 18:09 | 已确认 |
| 商品 原油 | 18:15 | 已确认 |

排期约束（主管 2026-11-16 核定）：`daily_data_update` 的 cron 是 `15 17 * * 1-5`，17:15 起写当日数据、约 17:30 结束。六条任务统一从 17:45 起、每档隔 6 分钟：17:45 / 17:51 / 17:57（A 股）与 18:03 / 18:09 / 18:15（商品），末档距 18:25 的 `two_year_reversal_scan` 留 10 分钟。间隔只减少碰撞，不能当保证；数据没写完时靠数据门禁兜底——目标日缺数就记缺失、不写旧价、不产正常评分。

任务实际创建在 DSH 侧，真实任务 ID 与启用状态以各目录的 `任务账本.md` 为准；`job_definition` 不重复建同名任务。

## Git 边界

本目录整体入库：README、`模板/`、各行业/品种的三件产物（图、结论表、评分历史）。用户 2026-11-16 明确要求台账每天更新并纳入 Git，`.gitignore` 里原先的三条忽略规则已取消。

每日流程：分析师生成当日产物 → 由 DM 随当日改动一起提交。台账内容只含图表、结论与评分，不含行情原始数据、持仓、账户或密钥。
