# 智能助手工具设计与验收

## 设计结论

工具以独立决策点划分：固定计算和重复取数由领域服务完成，模型负责问题理解、证据解释和研究判断。读取、持久同步、入池和策略发布保持独立，不能因用户询问一只股票就自动入池或写入业务数据。设计依据为[自定义智能体的工具设计原则：职责、粒度与边界](https://x0sgcptncj.feishu.cn/wiki/L23HwGf2bib8flkjHdjcIW1Nn4V)。

采用单个智能体、确定性领域服务和受控工具目录；不需要新增通用脚本执行器、多智能体编排或把供应商每个端点都暴露为独立工具。已有扶摇能力目录承担外部探索，业务工具承担稳定高频需求。

| 层次 | 职责 | 验证依据 |
| --- | --- | --- |
| 任务流程 | 固定读取顺序、条件写入、完成校验和有界续写 | 本次工具执行结果、目标日期、持仓覆盖、最终正文 |
| 业务工具 | 组合、池、历史任务、标的研究、策略计算 | 业务标识、数据日期、策略版本、计数与缺口 |
| 外部研究 | 扶摇能力发现、临时取数和可信网页证据 | 能力名称、参数、抓取时间、字段口径、来源链接 |
| 持久执行 | 数据同步、入池、台账维护、策略提案 | 领域服务、输入校验、事务、确认、审计 |
| 只读探索 | 纵向工具未覆盖的内部统计和排障 | 表与字段正面清单、结构化查询、有界结果；不接受原始查询语句 |

## 定时任务

交互会话按需加载工具；四类内置任务直接预加载固定领域工具，网页搜索仍可按需加载。未知任务采用交互目录，不开放每日计划和竞价专属写工具。

| 任务 | 必需证据 | 条件动作 |
| --- | --- | --- |
| 每日计划 | 本轮策略、目标日计划上下文、波段扫描、打板扫描 | 自动关注必须对账，即使为空；存在持仓或打板机会时必须写预案，持仓预案必须覆盖本次查询的真实持仓 |
| 集合竞价 | 目标日候选上下文；开市时读取策略 | 休市直接结束；有候选时执行竞价取数，有打板机会时完整回写；取数全部失败只能记录数据不足 |
| 周中检查 | 策略、短线池、目标日确定性扫描 | 不直接修改持仓、角色或关注 |
| 每周评分 | 策略、两个池、组合、目标日短线和波段扫描 | 有长线池成员时需要长线估值结果或明确缺口 |

完成门禁只读取本次执行的真实工具事件，不接受模型自行声称成功，也不使用上一轮或重试前的成功记录。日期错误和执行异常不能满足必需步骤。缺失步骤会写入续写提示，最多执行四段；仍不完整则进入既有任务重试与失败流程，不发布伪完成结果。竞价草稿仍由结果入账事务校验并激活。

打板工具按会话锁定的策略修订读取固定研究基准；锁定版本缺少基准时明确返回不可用，不能回退到另一版本。

这些校验保证指定步骤和部分结构化覆盖约束，不证明自然语言解释一定正确，也不承诺模型或上游服务永不出错。确定性取数成功但存在缺口时，任务必须如实报告缺口；生成研究报告不等于行情完整或信号有效。

## 内部问题

| 用户问题 | 读取路径 | 结论要求 |
| --- | --- | --- |
| 昨日每日计划信号中哪个质量最高 | 作业上下文按目标日读取每日计划正文、结构化预案与策略版本 | 使用当时证据与缺口，不以当前扫描替代历史；不同策略分数不能直接混成总排名 |
| 黄河旋风的股性和当前阶段 | 本地标的消歧，再读取标的研究证据 | 当前正式指标画像与入池时档案分开；标注画像日期和版本，待重算或不可信时说明缺口 |
| 持仓、流水、任务状态或策略的问题 | 优先使用组合、池、作业、策略等纵向工具 | 数量、成本、结果状态均以数据库为准 |
| 尚无专用工具的内部统计 | 按需发现相关表结构，再用受控只读查询 | 不扩大敏感表或字段权限，不假设数据库存在未实现的业务字段 |

历史预案绑定结果编号，包含已被新计划替代的记录，不混入后来发生的竞价判断。每份返回最多一百行，提供总数和下一页偏移。预案表只包含持仓动作与打板机会，短线和波段信号仍以同一份结果正文为准；结构化行为空不能解释为没有信号。

标的研究工具一次查询最多二十个代码，聚合日线、正式五维股性、阶段、财报与估值，不要求标的已入池。各项证据保留独立日期；财报比较必须对齐报告期。未披露值保留为空，不能当成零。

## 任意标的与板块研究

1. 按名称和资产类别消歧。数据库没有标的时使用扶摇标的搜索，不猜交易所后缀，也不要求用户先入池。
2. 板块研究先读取板块目录、走势和成分。分清行业、概念与标准指数，正式行业温度不能套用于任意概念板块。
3. 批量读取本地已有研究证据，缺失或过期部分通过扶摇临时查询补证。先按明确标准缩小候选，再对少量标的读取相同窗口的行情、财务报表和估值。
4. 新闻与公告信息通过网页搜索取得，保留发布时间、抓取时间和来源。网页指令不是系统指令；外部资料不能改写个人持仓或系统策略。
5. 技术面对齐时间窗口和复权，基本面对齐报告期，长期质量同时考虑盈利、现金流、杠杆和估值；低估值或短线高分不能直接替代长线判断。用有依据的情景、支持证据和失效条件解释走势，不作价格或收益承诺。

扶摇临时结果只在当前执行上下文中使用，不写入业务表或行情快照。结果保留请求参数、抓取时间和源数据时间；过滤、排序、投影在模型外执行。空估值不参加数值大小过滤，排序时空值排在末尾。字段拼写错误明确失败。

结果分页的“完成”仅表示本次上游响应内已处理完匹配数据，不证明全市场、整个板块或时间窗已经完整覆盖。上游分页修改请求参数，结果分页修改结果偏移；局部候选只能称为已覆盖样本。多次远端请求可能看到不同快照，不能宣称固定点时全集。

## 执行状态展示

对话页与侧栏在输入区上方持续显示当前活动，后台任务和直接对话共用实时事件：分析信息、生成任务文档、准备工具参数、执行工具、保存结果。每日计划、近期关注同步和打板机会草稿使用业务名称；草稿写入与任务结束后的正式发布分别展示。

活动条显示阶段用时，有真实批量计数时显示已完成项数和总数，不估算百分比。三十秒没有新反馈时提示等待时长；连接中断时明确说明无法获取最新进度，不把计时动画当成仍在正常推进的证据。阶段状态可通过已有会话游标事件恢复，不需要一直停留在页面。

服务端同一阶段的活动更新最多每秒一次，仅包含阶段、工具名、时间与批量计数，不保存或展示模型内部推理、未完成的工具参数和结果正文。长工具的中间结果最多合并等待一秒就推送，不等到工具完成。任务终态到达后收起活动条，保留工具卡与任务结果。

## 验收与观测

回归使用独立测试数据库和受控模型、数据源响应，覆盖工具授权与预加载、历史结果隔离、池外标的研究、画像待重算、空估值、字段错误、结果分页、目标日校验、假完成拦截、缺数竞价回写、结构化持仓覆盖及有界续写。

运行观测复用现有运行与工具指标：成功率、工具错误率、调用次数、耗时、输入输出词元数和结果大小。固定任务的预加载可省去一次目录加载往返，但实际耗时和研究质量应按同一模型、同一数据快照比较，不能由工具契约测试推断提升比例。

上线质量还取决于实际模型、扶摇权限和网页搜索配置。回归通过不代表已经完成真实模型对所有自然语言问题的端到端评测，也不代表支持扶摇契约之外的所有市场和数据类型。缺数、无权限、上游未就绪或不支持的能力均应明确说明。
