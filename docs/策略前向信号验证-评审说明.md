# 策略前向信号验证评审说明

> 文档状态：待评审
> 评审对象：产品、研发、测试
> 最后更新：2026-08-28

## 一、结论摘要

- 目标只回答“每日计划实际选出的入场信号，在后续真实行情中的表现如何”。
- 不维护虚拟账户、现金、持仓、卖出、组合净值或退出状态机。
- 每日计划继续按现有工作日定时执行，通过扩展 `daily_plan_write` 一次性提交计划和合格入场信号，不新增 Agent 工具或定时任务。
- 信号只保存产生时的事实；1、3、5、10、20、60 个交易日收益、MFE 和 MAE 在查询时从 `market_bar` 派生。
- 结果统一称为“N 日正收益率”，不能称为完整策略胜率。完整退出规则、收益和回撤继续由历史回测评价。
- 旧账户式验证功能已经完整退役，新方案不复用其代码、表、API、路由或历史数据。

## 二、范围

### 2.1 范围内

- 每日计划提交实际选中的结构化入场信号。
- 入场类型固定为 `short_right`、`short_probe`、`short_left`、`swing`、`long`。
- 观察入场价使用目标交易日开盘价加每股固定 0.10 元。
- 计算 1、3、5、10、20、60 个市场交易日的周期末收益、MFE 和 MAE。
- 按入场类型、策略序号和策略快照哈希分别统计完成样本数、正收益率、平均收益和中位收益。
- 显示样本不足、行情缺口和策略版本来源。

### 2.2 范围外

- 止损、止盈、部分卖出、移动保护、时间退出和基本面退出。
- 虚拟现金、持仓、已实现盈亏、组合净值、最大回撤和资金竞争。
- 通用规则 DSL、逐日评估台账、独立执行器或新的定时任务。
- 历史数据回填和自然语言原因推断。
- 打板策略观察期信号；其是否纳入需在策略允许实际入场后单独评审。
- 全市场理论信号；本功能只评价每日计划最终选中的信号。

## 三、数据流

```mermaid
flowchart LR
    A["每日计划定时运行"] --> B["daily_plan_write"]
    B --> C["计划结果成功后激活入场信号"]
    C --> D["目标日与后续日线落库"]
    D --> E["查询时计算固定周期指标"]
    E --> F["按类型和策略版本统计"]
    G["历史回测"] --> H["完整策略收益与回撤"]
```

每日计划仍使用现有 `daily_plan_flow` 定时定义。信号写入随任务结果原子生效：任务失败、中断或没有生成结果时，不留下有效样本。行情日更只负责现有日线落库，不承担信号执行或状态推进。

## 四、数据与接口

### 4.1 新表

新增 `strategy_forward_signal`：

| 字段 | 用途 |
|---|---|
| `id` | 信号主键 |
| `source_job_run_id` | 来源每日计划运行 |
| `plan_output_id` | 成功后关联的计划结果 |
| `instrument_id` | 标的 |
| `signal_date` | 信号产生日 |
| `entry_date` | 计划入场日，必须是信号日后的下一开市日 |
| `entry_rule` | 五类固定入场类型 |
| `reason` | 计划中的入场依据 |
| `status` | `draft` 或 `active` |
| `strategy_change_seq` | 已批准策略序号 |
| `strategy_snapshot_hash` | 已批准策略快照哈希 |
| `created_at` | 创建时间 |

同一计划运行、同一标的最多一条信号。不同交易日再次出现同一标的时保留为独立样本，不做跨日去重。

### 4.2 写入契约

`daily_plan_write` 增加可选的 `forward_signals` 数组，不新增第二个工具。每条信号必须满足：

- 是本次每日计划最终选中的明确入场动作，而不是“即将符合”、池外待验证或盘中再判断候选。
- 标的是当前策略允许覆盖的范围，`entry_rule` 与当前策略分支一致。
- `entry_date` 是下一开市日，原因和策略快照完整。
- 工具先写 `draft`；计划结果与任务成功终态同事务入账后转为 `active`。

### 4.3 查询契约

新增只读接口：

- `GET /api/signal-validation/summary`
- `GET /api/signal-validation/signals`

API 使用 `market_trading_day` 定位入场日起第 1、3、5、10、20、60 个市场交易日，并连接 `market_bar` 的日线 OHLC：

```text
入场价 = 入场日开盘价 + 0.10
N日收益 = (第N日收盘价 - 0.10) / 入场价 - 1
MFE_N = 区间最高价 / 入场价 - 1
MAE_N = 区间最低价 / 入场价 - 1
正收益 = N日收益 > 0
```

不足 N 个交易日时，该周期显示“观察中”且不进入分母。目标日无有效开盘价，或第 N 日无有效行情时，显示数据缺口，不顺延到其他日期。

## 五、页面

新增 `/signal-validation` 页面和“信号验证”导航，不复用已退役路由。

页面顶部按筛选条件展示总信号数、已成熟样本数、N 日正收益率、平均收益和中位收益。明细展示标的、入场类型、信号日、入场日、入场价、各周期收益、MFE、MAE、策略版本和缺口。

用户可按入场类型、策略版本和观察周期筛选。样本数少于 30 时明确显示“样本不足”；没有成熟样本时显示空状态，不显示 `0%`。

## 六、成本与收益

| 范围 | 预计新增或实质修改行数 |

不新增第三方依赖，不新增 cron，不建设交易引擎。维护成本主要集中在统计口径和数据缺口处理；收益是获得真实时间向前推进、可按策略版本复算的入场信号样本。

## 七、验收

| 验收行为 | 完成信号 |
|---|---|
| 任务原子性 | 计划成功后信号激活；失败、中断和重试不留下有效样本 |
| 日期门禁 | 只接受信号日后的下一开市日 |
| 重跑幂等 | 同一运行、同一标的不产生重复信号 |
| 周期选择 | 正确定位 1、3、5、10、20、60 个市场交易日 |
| 指标计算 | 收益、MFE、MAE 与手工可算样本一致 |
| 统计分组 | 不混合不同入场类型或策略版本 |
| 缺口处理 | 缺开盘价或周期行情时不伪造、不顺延、不进入分母 |
| 小样本提示 | 少于 30 个成熟样本时不输出无提示的比例结论 |
| 回归 | 服务端类型检查、相关 Vitest、前端类型检查和构建通过 |

## 八、发布边界

- 本文只定义后续实现，不随旧功能退役自动上线。
- 上线时只新增信号事实表和只读页面，不恢复任何账户式验证代码。
- 出现统计口径问题时可隐藏新页面并停止写入新信号；历史信号事实保留，修正查询后可重新计算。
- 只有未来明确需要评价资金路径时，才重新评审确定性交易引擎。
