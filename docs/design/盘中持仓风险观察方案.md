# 盘中加减仓价位观察方案

## 判断目标

交易日交易时段每 60 秒采样真实持仓、所属行业和核心指数，使用已配置的 `GLM-5.3-Flash` 寻找当日加仓、减仓时机。每只持仓分别给出加仓区间、减仓区间、量价确认条件和取消条件，当前动作分为加仓触发、减仓触发、等待。系统只提醒，不执行交易、不修改持仓和每日计划。

## 量价与情绪依据

- 个股当日量价是主要依据：开盘、日内高低、分时平台、冲高回落、承接及增量成交量；行业和大盘当日走势作为辅助。
- 模型输入不提供成本、旧止损位、历史每日计划、策略正文或历史日线，不以固定止损价格作为加减仓判断锚点。
- 当天采样提供全日摘要、最近 20 个时点和当日五分钟采样分段，保持完整盘面；通过 60 秒调用间隔控制 token，不裁剪各角色的日内路径。采样分段只描述采到的价格路径，不能视为完整五分钟 K 线；成交量与成交额使用累计值的差分，缺失或重置不补零。
- 情绪依据为当日涨停、跌停、炸板池的点时总数及同日多次变化；按供应商总数元数据获取，每五分钟采集一次，全部账户共享并保存 PostgreSQL。来源日期或时效不符、任一总数缺失时不判断冰点。
- 冰点优先寻找反向加仓机会：结合个股不再创新低、缩量止跌或放量回收、真实承接及板块率先修复。持续放量下跌或承接未形成时等待。情绪偏热、冲高量价背离、平台失守后回收失败时评估减仓。

## 触发与失效

- 至少三个不同来源时间的有效量价采样、近期真实成交且最新来源不超过 90 秒，才能标记已触发；最新价必须位于对应区间。
- 加仓与减仓分别保留条件预案，但同一时刻只能触发一个动作。价格未进入区间、确认条件未出现时等待；缺少可靠量价数据时不提供臆测点位。
- 输出容量采用模型配置，不设观察器专属 token 上限。调用失败、空正文、无效 JSON、截断、缺项或重复持仓均不覆盖已有判断。
- 权限与配置错误暂停对应账户分析，更新或重新保存模型/厂商配置后恢复；临时错误至少五分钟后重试；供应商余额不足按可恢复错误每五分钟重试，并在任务中心心跳中标记失败和原因。错误正文与凭据不进入日志。

## 页面与个人提醒

- 持仓页默认只显示一行盘中加减仓摘要（加仓/减仓触发数、观察状态与最近采样），按需展开每只持仓的动作、情绪、简短量价依据、两侧价区间与确认、取消条件，区分等待条件和已触发。
- 只有新触发加仓/减仓或有效价区间明显变化时进入个人通知。相同方向的微小价区间抖动去重，退出触发后再次成立可以重新提醒。
- 条件失效或方向变化取消尚未发送的旧通知；超过 90 秒、非交易时段或不再持有的提醒不再补发。
- 旧版纯风险记录保留在数据库，不作为新版价位提醒展示。行情采样、情绪快照和判断均为本机运行数据，只进入私有完整备份，不进入 Git 固定资产包。
- 每轮模型判断按采样时刻追加保存一条历史（动作、情绪、价区间、判断依据、当时最新价和模型输入哈希），最新判断仍覆盖保存在原表；历史用于事后复盘和信号胜率评估，不参与提醒去重，也不因新判断改写旧行。
