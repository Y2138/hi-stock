## 一、架构结论

采用“构建时领域适配器 + 内嵌结构化数据 + 单文件静态前端”。浏览器只消费构建时已经校验的领域模型，不解析 Markdown，不访问 CSV，不承担事实源映射，也不发起网络请求。

```text
仓库事实文件（只读）
  -> 必需输入预检
  -> Markdown / CSV 领域适配与严格校验
  -> 来源、哈希、截止日、状态、问题清单
  -> Vite + TypeScript + ECharts 单文件打包
  -> dist/stock-viewer/index.html
  -> file:// 本地只读运行
```

不引入数据服务或数据库，理由如下：

| 方案 | 收益 | 成本与风险 | 结论 |
|------|------|------------|------|
| 构建时预处理 + 单文件 | 符合离线、只读、可复建和低运维要求；浏览器不依赖文件格式 | 每次事实更新需重建；单文件含敏感副本 | 本期采用 |
| 浏览器直接解析仓库文件 | 实现入口看似简单 | `file://` 跨文件访问不稳定，展示层耦合 Markdown，错误恢复与来源边界差 | 拒绝 |
| 本地 Server / API | 可提供稳定查询契约和增量更新 | 扩大部署、权限、进程和运维范围，违背已确认 MVP | 本期拒绝 |
| SQLite / 独立数据库 | 适合更大历史查询、事件模型和版本化 | 当前查询规模没有抵消迁移、对账和事实源切换成本 | 后续有明确服务化需求再评审 |

## 二、事实分类与边界

| 类型 | 当前输入 | 系统处理 |
|------|----------|----------|
| 原始行情事实 | P0 所需行情 CSV | 校验并嵌入 OHLC、可空成交量和源均线，不二次复权 |
| 当前账户状态 | `当前持仓.md` | 解析资金摘要与持仓主行，保留多成本口径、约数与实盘例外 |
| 历史账户记录 | 2026 年 7 月持仓流水 | 只抽取明确总资产金额及可用拆分，形成离散点 |
| 展示派生数据 | 单日价格变化、日期缺口、归一化比较 | 依据受控公式计算，保留输入日期与状态 |
| 业务规则 | 产品方案中的映射、状态和禁止表达 | 以受控配置和校验实现，不复制交易策略参数 |
| 人工判断、计划、量化结果 | 策略、计划、说明段落 | MVP 不抽取、不展示、不推断 |

Markdown 和文件路径不是前端 API。它们只属于构建适配层；前端契约是下述版本化领域模型。

## 三、领域模型

顶层 `StockData` 包含：

- `schemaVersion`、`builtAt`、`targetDate` 与隐私提示；
- `global`：行情共同截止日、账户截止日、全局主状态、各状态数量与全局问题；
- `account.summary`：保留原始文本和精度的当前资金字段；
- `account.holdings`：当前持仓、成本口径、累计盈亏、角色、实盘例外和最近有效日价格变化；
- `account.history`：明确记录日期的总资产、证券市值、现金、原始金额文本和精度；
- `benchmark`、`instruments`、`sectors`：已校验的行情行与受控品种信息；
- `manifests`：每个数据集的仓库证据、上游元数据状态、覆盖范围、单位、主状态和问题清单。

每个数据集只有一个主状态：

```text
loading | available | delayed | partial_available |
not_comparable | unavailable | render_error
```

全局严重度按 `unavailable > render_error > not_comparable > partial_available > delayed > available` 聚合。未知元数据与约数是可见警告，不单独降低主状态。

问题对象包含 `code`、`message`、`impact`、`evidence` 和 `recovery`。支持的代码覆盖 `EMPTY_DATA`、`INVALID_ROW`、`SOURCE_CONFLICT`、`STALE_DATA`、`MISSING_DATE`、`VOLUME_MISSING`、`METADATA_UNKNOWN`、`APPROXIMATE_VALUE`、`MAPPING_CHANGED` 和 `RENDER_INIT_FAILED`。

本期没有运行时 API。若后续进入服务化，服务端应复用这些领域语义，而不是暴露 Markdown 行或数据库表。

## 四、解析与校验

### 4.1 当前持仓

- 只读取“实时持仓总览”主行，忽略“股性”等从属行；
- 要求资金摘要、更新日期、持仓名称、六位代码、数量、现价、市值和角色可解析；
- 多成本行与多盈亏口径作为原始数组保存，不合并为精确单值；
- 证券市值与逐只市值合计冲突时两者均保留并报告；
- 每只持仓行情按六位代码唯一映射，零个或多个匹配都使构建失败。

### 4.2 账户流水

- 金额行优先使用显式 `M/D` 日期，否则使用所属日期标题；
- `~`、`约` 和 `K` 转换为坐标元值时保留原始文本及 `approximate`；
- 同日唯一有效值可去重并警告；多个不同有效值冲突时该日不绘制；
- 缺失交易日来自上证交易日日历，只形成缺口标记，不产生金额。

### 4.3 行情

- CSV 使用结构化解析器，不按字符串拆列；
- `time` 必须是唯一合法日期；OHLC 必须为正且满足高低关系；
- 无效 OHLC 行不绘制；负成交量转为 `null` 并报告，不补零；
- 源 `MA5/10/20/60` 可空，浏览器不补造；
- `thscode` 必须与受控映射一致；冲突数据集不可用；
- 上游提供方、方式、抓取时间、复权和成交量单位没有明确元数据时保持 `null`。

### 4.4 日期比较

日期范围先分别过滤两条有效序列。共同起止、区间变化和价格表现差只读取日期交集；图表横轴读取日期并集。单边缺日对应序列为 `null`，ECharts `connectNulls` 固定为 `false`。

## 五、构建、隐私与恢复

1. 构建开始前在终端显示敏感数据提示。
2. 预检所有必需文件并完成核心 Markdown 解析；失败时不创建也不覆盖产物。
3. 每个源文件计算 SHA-256，所有嵌入路径转换为仓库相对路径。
4. Vite 在 `.build/` 生成临时输出，单文件插件内联 JS、CSS 与数据。
5. 检查临时目录只有 `index.html`，且 HTML 没有绝对用户路径或外部脚本/样式标签。
6. 全部通过后以重命名原子替换 `dist/stock-viewer/index.html`，随后清理临时目录。

`dist/`、本地依赖、临时构建、浏览器报告和截图均由 Git 忽略。页面没有导出或网络入口。事实更新后的恢复方式是重新构建，不是修改内嵌数据。

## 六、前端交互

- 固定页头先显示行情截止、账户截止、构建时间和全局状态；
- 总览默认按单日价格涨跌幅绝对值排序，每行分别下钻到对比与 K 线；
- 对比和个股 K 线共享所选持仓与日期范围；默认范围为三个月，复位回到三个月；
- K 线默认打开 MA5、MA20，成交量与价格使用联动日期轴；
- 板块选择器固定为 15 项，CPO 与航空航天的 ETF 代理身份同时使用文字和样式表达；
- 图表悬停内容均有键盘范围控件与文本输出；
- 单图异常只替换该图容器，重试成功后恢复，其他视图状态不变；
- 任一图下方的“来源与口径”一次展开即可看到仓库证据与上游口径两组信息。

## 七、测试与对账

- 单元测试使用合成非敏感夹具覆盖批准时的 8 只持仓、13 个账户快照、缺日、重复标题、15 板块、异常 OHLC/成交量、重复冲突和日期对齐；
- 门禁测试删除必需输入并预置旧产物，验证非零退出和旧文件不被覆盖；
- Playwright 直接打开 `file://`，监听并禁止 HTTP(S) 请求，检查画布非空、核心下钻、键盘读取、代理标签、来源展开、两种桌面宽度和错误恢复；
- 验收脚本核对源 SHA-256、转换结果、生成物边界和 Git 忽略状态。

## 八、当前数据差异与限制

批准方案以 2026-07-29 的 8 只持仓和 13 个账户快照为验收夹具。开发期间真实事实源已更新到 2026-07-30：半导体设备 ETF 清仓后当前持仓为 7 只，账户流水增加 2026-07-30 快照，而上证及部分必需行情的共同截止仍为 2026-07-29。

实现不回滚、不复制、不改写这些事实。当前本机构建显示真实的 7 只持仓、14 个账户离散快照和截止差异；批准时口径由合成夹具持续验证。该差异是上游事实演进，不是页面自行调整产品口径。

> 2026-08-16 备注：事实源继续演进，`当前持仓.md` 现行为 5 只持仓（亨通光电、深科技、航天电子、鹭燕医药、格林美，截至 2026-08-14）、20 个账户离散快照；本文 8 只/7 只表述均为对应日期的历史口径，验收夹具不变。策略演进系统二期起持仓事实以数据库 `position_change` 事件流为准（见技术设计 v2.0）。

其余已知限制：

- 上游行情提供方、获取方式、抓取时间、复权和成交量单位没有结构化元数据，因此显示未记录或未知；
- 账户历史仍不能支持历史组合收益率、净值、回撤或基准比较；
- 当前事实源没有可靠的持仓到板块映射，个股与板块选择不自动联动；
- 本期不支持小于 1024 像素的移动布局，也不提供受支持的分发流程。
