> 更新日期：2026-09-11。
> 范围：数据、计算口径、策略规则、执行能力及验收条件。
> 关联：[优化预案](../系统策略优化方案预案.md)、[回测架构规划](../系统回测能力架构规划-评审说明.md)、[市场状态口径草案](市场状态同花顺板块口径_策略修订案.md)。
> 证据边界：库存数字引用 2026-09-11 本地实例盘点，本次文档完善未重新查询数据库；源码事实按当前仓库核对。供应商能力声明不等于已验证的逐标的历史覆盖，实施前须通过服务层重新盘点和抽样获取。

> 实施边界：全市场历史数据同步由用户在系统外部维护，系统只读取 PostgreSQL、预检和冻结输入，不新增全市场同步或导入任务。本文“回填”事项表示数据前置要求，不构成系统自动采集授权。

## 一、结论与适用范围

**仅补齐数据不能获得完整回测能力。正式验证需要同时满足历史数据可用、决策时点正确、规则可执行、成交与组合记账统一、结果可追溯五项条件。**

1. 实盘账户净值用于真实账户复盘；策略回测的净值、回撤、连亏和熔断状态由本次模拟交易逐日生成。不得将真实净值作为新策略模拟熔断的共同输入。
2. 指标和确定性历史信号可以重算。ATR、ADX 未落库不是回测的硬性阻塞，公式、输入对象、预热和历史时点才是必要条件。
3. 使用当前股票池、当前行业归属回看历史，必须标明研究近似，不得宣称重现了当时的可选集合。
4. 日频回测、盘中执行研究、实盘归因和打板毕业是不同证据；不能相互替代。
5. 各策略按必需数据的共同覆盖区间分别验收，不强求一次补全所有品种和交易粒度。

| 能力层级 | 必须具备 | 可作出的结论 | 不可作出的结论 |
|---|---|---|---|
| 价格与信号研究 | 合格历史行情、固定样本与公式 | 指定样本内信号及后续价格表现 | 真实可成交的组合收益 |
| 日频组合验证 | 时点数据、规则、撮合、账户、费用、风控、审计 | 约定执行假设下的日频策略表现 | 未建模的盘中顺序和排队成交 |
| 竞价与盘中验证 | 日频底座、所需竞价/盘中历史、时间顺序与成交模型 | 指定粒度和模型下的执行表现 | 对实盘成交的保证 |
| 实盘验证 | 真实信号、成交、费用、归因和结算 | 实际执行与策略约束的符合度 | 用模拟样本代替实盘毕业样本 |

### 2.2 当前回测能力

证据：`server/backtest/agent-contract.ts`、`server/backtest/agent-workspace.ts`、`server/backtest/worker-runner.mjs`、`server/agent/tool-validation.ts`。

- 显式代码最多 100 个，也可由整个区间涨停事件扩展候选；扩展集合不得被误用成每个历史日都已知的可交易池。
- 传入 OHLCV 日线与部分涨跌停事件字段，不传成交额、复权信息、完整打板评分字段、历史财务等。
- 日线只取请求起止日期，不自动取起点之前的预热历史。
- Agent 自行生成收益序列；系统校验结果契约并计算部分汇总指标，不从统一成交账本核验收益。
- SDK 暴露全区间数组，不提供强制历史时点访问边界，也没有统一成交、组合和风控状态机。
- 已有源码/输入哈希、源码固化、比较关系、最终化和隔离执行基础；哈希不等于输入数据已持久冻结。
- 单次日线与事件分别上限 50 万行，输入 128 MiB、工作器内存 1 GiB、执行超时 60 秒。全市场多年验证需要独立容量验收。

## 三、数据与能力缺口清单

| 编号 | 必需项 | 分类 | 补齐要求 | 验收判据 |
|---|---|---|---|---|
| 数一 | 个股历史 OHLCV、成交额 | 原始数据 | **已回填**：扶摇全市场批量导出经 `scripts/market-backfill.ts` 灌入 `market_bar`（5,562 只 / 10,283,203 行 / 2016-09-12 起）；日常增量仍走逐标的接口 | 每标的覆盖报告；缺失不得填零；合法 OHLC、重复与日历检查通过 |
| 数二 | 交易原价、复权及公司行为 | 原始数据与记账 | 信号价与成交价分离：`market_bar` 同行并列 `open_raw/high_raw/low_raw/close_raw`（原始价）与 `open/high/low/close`（前复权），`prev_close` 为交易所前收盘；前复权由 `server/datasource/adjustment.ts` 按固定锚点计算 | 分红送转前后信号连续、数量现金核对，收益不重复计分红 |
| 数三 | 历史可选池和可交易状态 | 时点数据 | 明确上市退市、停牌、风险警示、池角色及生效区间 | 每日仅使用当时有资格的标的；无法恢复则标研究近似 |
| 数四 | 881 日线和参与集合 | 数据与口径 | 逐板块回填；区分今日固定集合回看与历史集合；定义新增/缺数处理 | 组成、分母和缺数策略冻结；完整日窗可按生产公式复算 |
| 数五 | 市场/行业宽度 | 数据或派生 | 从足够历史个股数据计算，或采集已验证的历史统计；定义平盘、停牌、新股及前收盘口径 | 分子分母可追溯；除权不制造虚假下跌家数；覆盖不足不得当弱市 |
| 数六 | ATR、ADX、均线、股性画像 | 派生计算 | 固定公式、平滑初始化、预热、计算对象；股性参数只使用决策日前信息 | 同输入同结果；未来行情变化不改变过去特征 |
| 数七 | 涨跌停与打板评分输入 | 原始数据与时点 | 补成交额、封单金额、换手、事件时间、连板信息及评分所需字段；固定评分基准训练区间 | 生产与回测评分一致；全日最终事件不得提前可见；训练区间不进入样本外 |
| 数八 | 竞价/盘中观测 | 分支数据 | 保存交易日、观察时刻、可用时刻、来源、竞价价量及分支所需字段 | 不用开盘价冒充竞价观测；不根据当日高低价推断唯一盘中顺序 |
| 数九 | 财务、估值历史 | 分支时点数据 | 报告期、公告时刻、修订、价格、股本及盈利口径对齐 | 公告前不可见；晚到修订不覆盖当时已知值 |

## 四、必须固定的策略口径

下列均为设计建议或待确认研究参数，不代表已发布策略。每次实验必须冻结完整取值，不允许 Agent 临场补规则。[回测架构规划](../系统回测能力架构规划-评审说明.md)第四节已规定第一轮日频实验的时序、计数、恢复、排名和预算默认值；这些值只用于可执行实验，进入生产仍须审核。

| 规则 | 必须定义 | 建议边界 |
|---|---|---|
| 震荡判定 | MA20 斜率窗口及归一化；ADX 对象；反复穿越次数；宽度与涨跌停条件；组合方式及确认天数 | 先单因素消融，再组合；不得把所有条件默认为同时满足 |
| 综合指数 | 基准点、日收益、参与集合、缺数策略 | 采用连续共同基准计算序列；生产目前滚动 21 日重置为 100，跨日斜率不可直接相减两个重置后的 MA20 |
| ADX14 | 使用哪个有高低收价格的指数或股票，还是聚合行业 ADX | 当前 881 合成仅有收盘收益，不直接套标准 ADX；对象未定不启用该条件 |
| 同类前 1—2 名 | 同类定义、排名、并列、持有同类仓位、跨策略重复信号 | 全候选统一排序后分配组合预算，不对每只股票各自独立限仓 |
| 止损 | 收紧/放宽、价格档位、盘中/收盘触发、跳空与不可卖处理 | 止损触发价不是保证成交价；日频执行假设明确披露 |
| 20 日高点回撤 | 窗口是否含当日、预热不足处理、净值口径、触发时刻 | 模拟账户收盘后计算含当日在内最近 20 个交易日高点；不足 20 日用自起点已有序列并披露 |
| 连续三笔止损 | 全组合或分策略、闭环与部分卖出、同时平仓排序、重置 | 用退出原因计数，不把三笔一般亏损等同三笔策略止损；同日顺序固定 |
| 恢复开仓 | 恢复定义、滞回、最短暂停期、触发和恢复冲突 | “综合指数 MA20 斜率非负”为待确认候选；同一决策时点触发优先于恢复 |
| 波段仓位乘 0.8 | 仅新开仓还是含存量减仓、与总仓位上限的关系 | 推荐首轮只作用于新开仓目标金额，不隐含强制卖出 |
| 试盘 T+1 复核 | 收盘确认条件、确认后最早执行时点、失败处理 | 日频首版在 T+1 收盘确认，最早下一可交易日执行；不得回填为 T+1 早盘买入 |
| 左侧/打板保留 | “保留”是否豁免全组合熔断 | 推荐保留模块资格但不豁免总现金、可交易性与组合熔断 |
| 长线季度处理 | 信号与财报公告关系、调仓日、短线环境豁免范围 | 短线情绪不直接决定长线信号，组合总风险边界仍须明确 |

波段数据必须逐标的核验。40—119 根并不等于不足 40 根；40 根只满足箱体最低窗口，不保证 RSI、股性画像和多年验证充分。`server/modules/plans/swing-signals.ts` 还依赖股性防守参数，不能用今天算出的画像回填所有历史日。

## 五、历史时点与近似规则

1. 外部数据区分经济归属日期、公开/可用时刻和本机采集时刻。今天采集的历史日线可以用于历史回测，但其历史内容和公开时点须有依据；今天的分类快照不能因换个日期就变成历史分类。
2. 财报以公开可用时刻进入策略，不以报告期末提前进入。仅有公告日期时，首版保守地从下一交易日开放，并披露该约定。
3. 当前行业归属可作为首轮研究近似，必须冻结映射并展示“当前成分回看”；不能与历史时点行业版本混为同一口径。
4. 历史股票池不可恢复时，可做“固定样本历史研究”，不能宣称复现当时全市场选股。宽度分母不允许仅使用被跟踪的约 10% 样本却称为全市场。
5. 881 今日集合回看、历史动态集合、今日个股行业归属是三个独立选择。当前供应商集合中缺早期数据时，不自动减少分母或用未来新行业填补过去。
6. 真实信号留痕起点之前的实际买入意图保持“不可归因”。允许重算确定性研究信号，但字段和页面必须区分研究生成与实际历史证据。多信号命中时只预填候选，由录入者明确选择，不自动伪造唯一归因。
7. 模型自由判断、新闻理解、主观入池等非确定性决策，不因价格历史齐全就变得可回放；缺当时证据时只测确定性子集。评分基准、股性统计和调参训练窗口不得看向验证区间未来。
8. 事件接口无返回必须区分“当日确认零事件”和“采集失败/未覆盖”；后者不能用于宽度或情绪判断。

## 六、分阶段补齐与验收

### 第一阶段：可复现的日频底座

- 固定研究范围、股票池近似、候选参数、执行时间、价格/费用口径与基准。
- 回填该范围的个股、881 及所启用过滤器所需历史；分别报告起止、预热、缺数和共同窗口。
- 建立输入冻结、逐日访问、确定性信号、模拟账本、费用和组合风控；先覆盖右侧基线与震荡/止损/熔断变体。
- 基线与变体共用同一输入集、成本、初始资金及样本划分；未启用的 ADX/事件规则不得在结论中宣称已验证。
- 验收：可以追溯每次买卖及未买原因；每日净值可从现金和持仓复算；未通过时点或质量门槛的结果不得标正式证据。

### 第二阶段：多策略日频验证

- 接入左侧、波段和明确执行时点的试盘规则；按日重建股性画像、候选排序与组合资金竞争。
- 对无法通过日线还原的突破/止损顺序使用固定、保守且可审计的假设；若其影响会改变结论，则转入盘中验证，不假称精确回放。
- 验收：独立策略与组合模式分开报告；同类限仓、重复信号和多策略归属一致。

### 第三阶段：打板与长线分支

- 打板：补完整评分字段和竞价观察；分钟粒度只有在对应规则确实需要时建设。队列位置与成交不可识别时披露敏感性或不可验证。
- 长线：补公告时点财务、修订和历史估值，按季度规则执行。
- 验收：两类分支各自按可用窗口验收，不因日频底座完成而自动通过。

### 并行实盘线

- 每日真实账户结算、出入金调整、信号归因、退出原因、竞价留存和执行对账。
- 打板按 `server/migrations/0067_打板小额实盘验证与成交归因.sql` 的现有口径：至少 20 个交易日、30 笔归因明确的实盘闭环，拟毕业分支各至少 10 笔；还须满足收益、滚动中位数、毒药单及费用披露等条件，并经真实用户批准策略版本。
- 历史模拟样本不抵扣实盘毕业样本，7 笔一般闭环不直接计入打板。

## 七、统一验收清单

| 项目 | 通过信号 |
|---|---|
| 数据完整 | 必需字段和预热在声明范围内覆盖；不可交易与缺数已区分；未静默缩窗 |
| 输入时点 | 修改未来行情、未来事件或晚到财报，不改变过去信号和成交意图 |
| 同口径 | 相同截止时点与输入下，生产纯函数和回测输出一致；环境、股性、评分基准一致 |
| 组合记账 | 现金、持仓、分红、费用、成交闭环与每日权益一致；熔断来自本次模拟状态 |
| 执行边界 | 不可成交订单有原因；跳空、涨跌停、停牌、不可卖及同日顺序均有固定规则 |
| 比较有效 | 相同输入集、资金和成本，明确唯一变更因素；不同口径只能并列解释，不能直接归因 |
| 样本外 | 训练/调参/验证边界固定；有跨环境子区间、参数敏感性和交易数量披露 |
| 结果充分 | 净收益、绝对/滚动回撤、暴露、换手、费用、交易分布、拒单和错失信号同时披露 |
| 可复现 | 输入载荷、执行计划、引擎构建标识均可获取；只有哈希而材料缺失时标记不可精确重放 |
| 实盘边界 | 研究信号不冒充真实归因；回测结果不作为自动毕业或自动发布授权 |

**交付结论：数据、规则、引擎和验收必须分别完成。第一阶段目标是“声明边界内可审计的日频组合验证”，不是宣称所有策略、全部历史和盘中执行已经完整回测。**
