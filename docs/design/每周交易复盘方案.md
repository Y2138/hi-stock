# 每周交易复盘方案

## 目标与边界

- 目标：每周六对刚结束的完整交易周做一次只读复盘，覆盖账户与持仓、本周产出的机会标的、指数与行业板块、市场情绪与宽度，解释盈亏原因与决策质量，并对下周给出条件式风险预估。
- 只读事实：任务只读取数据库事实，不修改持仓、成交、策略、关注池、每日计划或任何业务数据；快照表只保存复盘自身输入。
- 不构成买卖建议，不承诺收益，不给买卖指令；下周风险预估只是条件式判断，不保证方向。
- 不做自动交易、不改写策略、不新增预测模型；网页资料只作为带来源的补充材料，不得覆盖数据库中的行情、持仓与成交事实。

## 任务定义

| 字段 | 值 |
|---|---|
| code | `weekly_trading_review` |
| 名称 | 每周交易复盘 |
| job_type | `agent_flow` |
| cron | `0 9 * * 6`（每周六 09:00，Asia/Shanghai） |
| phase | 周末 |
| priority | 190 |
| trading_day_only | `false`（周六非交易日，任务照常入队；手动触发不受限） |
| execution_scope | `global`（一次运行覆盖全部 `active` 账户，不按账户拆成多次运行） |
| enabled | `true` |

任务提示词随迁移写入 `job_prompt` / `job_prompt_revision`，运行时固化实际版本；任务在任务中心只读展示，启用状态、cron 与提示词维护仍走既有任务管理边界。

## 数据输入

模型运行前，服务端用确定性 SQL 构建周快照并持久化到 `weekly_review_snapshot`（主键为任务运行，每个任务运行一条，重试覆盖同一行），同时向提示词注入紧凑事实摘要；完整结构由任务工具 `weekly_review_context_query` 读取。模型只负责归因、比较和风险预估，不重复查询通用业务表。

- 复盘窗口：以目标日当日或之前最近开市日为周结束，向前取该自然周的周一至周结束之间的开市日作为统计日（周一可能因节假日休市）；周末、节假日与日历缺行按交易日历显式判定，窗口内每个开市日都参与统计。
- 账户与净值：全部 `active` 账户的现金、持仓市值、净值及其周变化。净值快照 `portfolio_equity_daily` 由每日计划盘前物化，目标日键使用上一交易日收盘估值，存在一日口径差；变化还包含现金变动，不等于收益率。
- 当前持仓：每只持仓的数量、成本、收盘价、本周涨跌与浮动盈亏。
- 本周买卖与调整事件：本周发生的买入、卖出、加减仓与调整记录，逐笔保留归因，并按账户汇总本周已实现盈亏及缺失笔数。
- 本周机会标的：盘后统一精选推荐、盘后策略初筛、超短 T+1 关注池、收盘打板机会、策略关注条目五类来源，记录来源、信号日、标的与当时判断；以信号日开盘价为基准统计信号日开盘后的走势（区间涨跌、期间最大涨幅与最大回撤、样本数），并区分已评价、下周生效和缺行情，用于区分信号有效性与执行时点。
- 指数与成交：核心指数周涨跌与成交额变化；指数日线缺少成交额字段时记缺口，不用空值冒充。
- 板块：881 一级行业板块周涨跌排名，用于识别本周主线、扩散与退潮。
- 市场情绪与宽度：逐日涨停、跌停、炸板数量、最高连板高度及上涨/下跌家数宽度。
- 数据缺口：快照无法取到的账户、行情、板块、宽度或事件，逐项记录到 `gaps`（scope 与原因），并使任务运行状态为 `partial`（快照缺口进入任务 `data_gaps`）；快照构建失败时同样记为缺口并继续按可用事实产出。

快照结构带版本号，口径演进时可识别旧快照；快照只读，不写回业务表。

## 报告固定结构

正文按以下二级标题组织，顺序固定：

1. `## 一周市场与板块`：指数周涨跌与成交额、板块强弱与轮动、涨停/跌停/炸板/最高连板与涨跌家数反映的情绪，指出本周主线和扩散或退潮信号。
2. `## 持仓复盘`：逐账户说明本周已实现与浮动盈亏、买卖与调整动作、持仓理由是否仍成立；亏损拆分为策略判断错误、执行偏差（追高、迟滞止损、违反仓位）和市场环境。
3. `## 机会标的复盘`：按来源给出本周机会标的的命中、落空、未生效分布，解释为什么盈或亏，区分信号本身失效、入场时点或执行问题、环境不配合；策略判断与执行分开评价。
4. `## 做得好的与做得不好的`：各写 2–4 条具体做法，带日期、标的或板块和可核对数字，并说明下周可复用的做法与必须纠正的错误。
5. `## 下周风险预估`：分大盘、板块、持仓、机会四层，给出关键价位、情景、触发与失效条件、需要观察的指标与事件；只做条件式判断，不给买卖指令。
6. `## 结论摘要`：放在正文结尾，只列最终持仓动作与重点观察标的，不重复推理、不凑数，没有内容时明确说明；不超过 600 个中文字符，作为通知正文的取用段落。

每个判断引用快照字段、工具结果或网页来源；数据缺失列为缺口，不猜价格、指标或盈亏。信号在最后一个交易日之后才生效的机会标的写入“下周生效”，不计入本周评价；不得事后挑选标的，也不得把未触发机会算作命中。

## 产出与通知

- 复盘正文写入任务中心任务结果（`job_run_output`），与本次运行关联保存，带“不代表策略发布或交易执行”的既有标识。
- 结论通过通知设置中的「通用消息 · 策略任务」通道推送，取 `## 结论摘要` 段落并限长；受通道开关、Webhook 与签名密钥、`job_codes` 订阅范围约束，未配置时不绕过配置直接发送。
- 运行状态为 `partial`（存在数据缺口）时，每周交易复盘任务仍允许推送。任务运行状态为 partial 时，任务中心与通知标题标注部分覆盖并提示正文查看缺口；完整正文必须列明缺口。
- 通知按输出编号幂等入队，重复运行同一结果不重复推送；显式选择任务的用户在迁移中把本任务加入原订阅范围，选择“全部策略任务”的用户无需额外配置。

## 数据缺口与失败

- 快照生成失败、无行情、缺账户净值、缺板块或宽度数据时逐项写入缺口，不得编造价格、指标或盈亏，也不得用上一周数据冒充本周。
- 缺口可用行情、板块、市场事件与标的研究工具补读（补拉行情会写入行情缓存，但不写持仓、成交、策略、关注与计划），本周消息用近七日网页检索与正文核验补齐；补读只补充事实并注明来源，不覆盖快照、不伪造已评价结果。
- 缺口不导致任务失败：快照构建失败时把原因注入上下文并列为缺口，任务仍按可用事实完成正文；有可用事实和完整正文时按 `partial` 结束，只有模型调用失败或没有可比对正文时才失败。
- 缺口须在正文中对应章节说明影响范围，不得把“未核验”写成“未命中”，也不得把部分覆盖写成全部完成。

## 验收要点

| 验收项 | 判定 |
|---|---|
| 任务在任务中心显示 | 出现“每周交易复盘”，编码、cron、phase、priority、作用域与启用状态与本文一致 |
| 周六自动入队 | `trading_day_only=false`，非交易日照常入队；手动触发可用 |
| 快照 | 每次运行一条 `weekly_review_snapshot`，重试覆盖同一运行；含窗口、账户、持仓、成交、机会标的走势、指数、板块、宽度与缺口 |
| 产出 | 任务结果为 Markdown，六个二级标题齐全，结尾 `## 结论摘要` 不超过 600 字 |
| 通知 | 结论可推送；`partial` 仍推送并标注缺口；通知设置可选全部任务或指定任务 |
| 只读 | 运行前后持仓、成交、策略、关注池与每日计划无变化；快照表只进私有完整备份，不进入固定资产包 |
| 缺口 | 无行情或数据缺失时如实列明，不编造、不误判失败 |
