# 独立邮件通知通道

## 目标与边界

- 目标：把已完成任务的完整报告通过 SMTP 邮件发送到固定收件人列表，覆盖每周交易复盘、盘后统一标的精选等默认任务，并在设置页支持保存、测试、清除配置以及查看最近投递、补发失败记录。
- 独立通道：邮件与飞书推送完全解耦，各自拥有独立的设置表、投递队列表、后台 worker 与凭据版本；飞书的配置、开关、订阅范围、凭据变更不影响邮件，反之亦然。同一任务结果可以同时进入两个通道，互不去重、互不取消。
- 只读副本：邮件只是任务结果（`job_run_output`）的发送副本，不产生新的分析结论，不改写持仓、成交、策略、关注池、每日计划或任务结果。发送失败不影响任务运行与结果保存。
- 个人范围：收件人来自设置页保存的固定白名单，发送时只读取该白名单，不接受请求侧临时指定收件人；不提供群发、抄送、密送或收件人动态扩展。
- 不构成策略发布、买卖建议或交易执行；邮件内容与页脚都必须保留该边界。
- 明文 25 端口、SMTP 未加密连接、任意转发中继不在支持范围内；不允许把本机无认证服务通过邮件链接暴露出去。

## 为什么独立于飞书

- 凭据类型不同。飞书自定义机器人使用 Webhook 与签名密钥；邮件使用 SMTP 主机、端口、账号与专用密码或授权码。两者没有可复用的凭据语义。
- 失效语义不同。独立 `revision` 才能实现“只取消本通道旧待发、另一通道继续发送”，避免修改邮件密码时误取消飞书队列，或关闭飞书时误停邮件。
- 订阅与开关语义不同。飞书的“个人通道 / 策略通道”按任务类型分组，邮件是单一通道加任务多选；共用设置表会把两套开关、任务范围和测试入口耦合在一起。
- 失败模式不同。Webhook 是 HTTPS 请求，邮件是 SMTP 会话（认证、端口、TLS、投递延迟、对方反垃圾）；独立 worker 与独立重试状态可以让一种通道故障不阻塞另一种。
- 数据边界不同。邮件配置与投递记录属于本机私有数据，只进入完整私有备份；与飞书共用表会让固定资产排除规则和恢复语义更模糊。

## 架构与数据表

一条邮件的生命周期：

1. 任务结果在保存事务内写入 `job_run_output`，同一事务判断邮件入队条件并写入 `email_delivery`（`status=pending`）。
2. 独立邮件 worker 每约五秒领取一条到期的待发记录，校验开关、凭据版本、结果是否仍为最新后，用当前 SMTP 配置发送。
3. 发送成功写 `status=sent` 与 `sent_at`；失败按重试策略回到 `pending` 并推进 `next_attempt_at`，超过次数、过期或被取消时写 `cancelled`/`failed` 与脱敏原因。
4. 设置页“最近邮件投递”折叠区读取投递记录；失败记录可在满足条件下补发，补发复用原记录与正文。

设置页（保存/测试/清除/投递记录）→ 设置表 → 任务结果保存事务 → 投递队列 → 邮件 worker → 第三方 SMTP 服务 → 收件邮箱。worker 与飞书通知 worker 相互独立，任一通道不可用时另一个照常投递。

### `email_notification_setting`（singleton，单行）

| 字段 | 类型/约束 | 说明 |
|---|---|---|
| `enabled` | boolean | 邮件通道总开关；关闭后不再入队 |
| `smtp_host` | text | SMTP 主机名，只存主机，不含协议、端口或路径 |
| `smtp_port` | integer | 只允许 465 或 587 |
| `smtp_secure` | boolean | `true` 对应 465 隐式 TLS；`false` 对应 587 STARTTLS（强制 `requireTLS`） |
| `smtp_user` | text | 登录账号，通常为完整邮箱地址 |
| `smtp_password` | text | 专用密码或授权码；只写不读，接口只回显是否已配置 |
| `from_address` | text | 发件地址，启用时必填 |
| `recipients` | text[] | 固定收件人白名单，去重后 1–20 个合法邮箱 |
| `job_codes` | text[] | 订阅的任务编码；默认 `cross_strategy_selection`、`weekly_trading_review` |
| `revision` | integer | 配置/凭据版本；主机、账号、密码、发件人或收件人变化时递增，用于取消旧待发 |
| `updated_at` | timestamptz | 最后更新时间 |

单行约束保证不存在多套邮件配置；读取接口返回的密码状态只有“已配置/未配置”，不返回密码、密码长度或哈希。

### `email_delivery`（投递队列）

| 字段 | 类型/约束 | 说明 |
|---|---|---|
| `id` | 主键 | 投递记录编号 |
| `output_id` | 唯一，外键（`ON DELETE CASCADE`），可空 | 任务结果编号；`test` 记录为空；一个结果最多一封邮件（唯一约束允许多个空值） |
| `kind` | text | `agent_result`（任务结果）或 `test`（设置页测试邮件） |
| `subject` | text | 已渲染的邮件主题 |
| `content` | text | 已渲染的邮件正文（完整报告 Markdown） |
| `status` | text | `pending` / `sending` / `sent` / `failed` / `cancelled` |
| `attempts` | integer | 已尝试次数，最多 3 |
| `next_attempt_at` | timestamptz | 下次可领取时间，用于一分钟、五分钟退避 |
| `lease_until` | timestamptz | 发送租约，避免并发重复发送 |
| `error` | text | 脱敏后的失败原因 |
| `channel_revision` | integer | 入队时的邮件配置版本 |
| `created_at` | timestamptz | 入队时间，用于一天过期判定 |
| `sent_at` | timestamptz | 发送成功时间 |

`output_id` 唯一约束配合事务内插入实现幂等：同一 `output_id` 的重复保存与 worker 重试复用同一行；任务重跑会产生新的 `job_run_output`，从而新增一封邮件并取代旧待发，旧已发邮件无法撤回。

## SMTP 设置与校验

- 保存时即校验，不等到发送才报错：主机非空且不含 `://`、空格或路径；端口只能是 465 或 587；`smtp_secure` 与端口匹配（465 为隐式 TLS，587 走 STARTTLS 且要求 `requireTLS`）；账号通常为完整邮箱地址（服务端只校验非空与长度，不强制邮箱格式），发件人与收件人必须是合法邮箱格式；收件人去重后 1–20 个；任务范围只能选择当前存在的 `agent_flow` 任务。
- 密码输入是可写不可读字段：页面留空表示保持原密码，只有明确输入才替换；清除配置需要显式操作并二次确认，清除后 `revision` 递增。
- 主机、账号、密码、发件人或收件人发生变化时 `revision` 递增并取消本通道旧待发，等待新的任务结果；只改启用开关或任务范围不递增、不取消。
- 默认按 QQ 邮箱配置：`smtp.qq.com`，端口 465，SSL。账号为完整 QQ 邮箱地址（如 `xxx@qq.com`），密码为在 QQ 邮箱“设置 → 账户 → POP3/IMAP/SMTP 服务”中开启 SMTP 后生成的授权码，不是 QQ 登录密码；发件人与账号一致。也支持 587 STARTTLS 与 163、企业自建等其它 SMTP 服务商，按其 465/587 参数填写，默认配置按 QQ 邮箱给出。
- 587 使用 STARTTLS 且必须要求 TLS（`requireTLS`），不允许降级到明文；其它服务商按其 465/587 参数填写，密码一栏使用授权码或专用密码。
- 拒绝明文 25：既不在页面提供该选项，也在服务端校验中拒绝；不提供“关闭 TLS 继续发送”的绕过开关。

## 任务范围与入队规则

- 默认任务范围：`cross_strategy_selection`（盘后统一标的精选）与 `weekly_trading_review`（每周交易复盘）。设置页可在此基础上多选其它 `agent_flow` 任务；数据同步、维护类任务不在可选范围。
- 入队时机：任务结果保存的同一数据库事务内判断并入队，保证“结果已保存但从未进入队列”不会发生；网络发送始终在事务提交后由 worker 执行。
- 状态条件：运行状态为 `success` 时入队；`partial` 只在默认两个任务或明确允许部分覆盖的任务上入队，避免把缺数据的半成品报告当成完整结论外发。
- 开关条件：`enabled=false`、未保存有效 SMTP 凭据、收件人为空或任务不在 `job_codes` 内时，只保存任务结果，不入队。
- 幂等条件：一个任务结果最多一封邮件；同一 `output_id` 的重复保存与 worker 重试复用同一 `email_delivery` 行；任务重跑产生新结果时新增邮件并取代旧待发。
- 取代条件：同一任务、同一目标日期出现更新版结果时，旧结果的待发邮件被取消，新结果按规则重新入队；更新版自身仍是一封邮件。
- 关闭启用只影响之后产生的结果：关闭后不再入队，重新开启不补推关闭期间的历史结果。该行为只作用于邮件，不影响飞书推送。

## 邮件内容与主题

- 主题固定为 `Stock｜任务名｜目标日`，例如 `Stock｜每周交易复盘｜2026-10-17`；任务名与任务中心一致，目标日为任务的目标交易日。
- 正文为该任务结果的完整报告，不截断为摘要、不附加其他任务的推荐内容。邮件同时提供纯文本与 HTML 两部分：纯文本保留报告 Markdown 原文；HTML 用 markdown-it 渲染标题、列表、表格与代码块并附内联样式（不执行内嵌 HTML），不支持 HTML 的客户端自动回退纯文本。
- 发送前为正文中的标的代码补全本地档案名称：`600519.SH` 这类带后缀代码与可命中本地档案的 6 位裸代码补为“名称（代码）”，报告里已带名称的写法保持原文；查不到名称的代码与普通 6 位数字不改写，档案查询失败不阻断投递。
- 页脚统一注明：结果编号、目标日、“AI 生成，不代表策略发布或交易执行”。结果编号用于回到 Stock 工作台任务中心核对原文。
- `partial` 结果只在允许的任务上发送，正文须保留原报告中的数据缺口说明，不把部分覆盖改写成完整完成。
- 不附不可达的本机地址详情链接（如 `127.0.0.1`），不要求收件人访问本机服务才能读懂邮件；完整结论回工作台按结果编号查看。
- 测试邮件使用固定文案，只验证 SMTP 认证与连通，不读取、不附带任何任务结论或持仓数据。

## 投递重试、过期与取消

- 独立 worker 约每五秒领取一条到期记录；领取时写 `status=sending` 与约一分钟的 `lease_until`，租约过期可被重新领取，避免进程中断后记录永久卡住。
- 最多 3 次尝试：首次失败后至少间隔一分钟重试，第二次失败后至少间隔五分钟重试；`attempts` 与 `next_attempt_at` 持久化，重启不丢退避。
- 超过一天未发出的记录取消；入队时记录的 `channel_revision` 与当前配置版本不一致时取消（凭据或配置已变更）；任务结果已被更新版取代时取消。取消记录保留原正文与原因，供设置页“最近邮件投递”核对。
- 达到 3 次仍未成功记为 `failed`，不再自动重试，只能由用户在设置页补发。
- 失败原因脱敏：只保留可操作类别（认证失败、端口或 TLS 不可用、收件人被拒、临时超时等）与必要的服务端响应摘要；密码、授权码、完整凭据、含凭据的连接串和完整错误正文不进入 `error`、日志或页面。
- 已发出的 SMTP 请求不能撤回；对方已接收但本机未收到响应时，重试可能造成重复邮件。“已发送”不代表已读，也不保证进入收件箱。

## 测试与投递记录

- 设置页提供“发送测试邮件”：只使用已保存的 SMTP 凭据，与任务结果和任务范围无关，只新增一条测试投递记录，不写持仓、任务结果等业务数据；测试成功即证明主机、端口、TLS 与认证可用。
- “最近邮件投递”折叠区按时间倒序展示：结果编号、任务名、目标日、状态、尝试次数、入队时间、发送时间与脱敏失败原因；正文按需读取，避免列表直接铺开持仓内容。
- 失败记录可补发：仅“失败”状态、未超过一天、当前凭据版本与记录一致、邮件通道已启用且任务仍在订阅范围时允许；补发复用原记录、原正文与原结果编号，不新建第二封，仍受过期与版本约束。修正设置并重新保存会取消本通道旧失败记录，请发送测试邮件或等待新的任务结果；补发只适用于当前配置版本下一天内的失败记录。
- 投递记录保留历史；若任务结果本身被删除（通常仅恢复/清理场景），对应投递记录随外键级联删除。“最近邮件投递”折叠区不提供跨收件人、跨实例的查询。

## 安全与数据边界

- SMTP 密码或授权码只存 PostgreSQL `email_notification_setting`；接口只回显是否已配置，不写日志、URL、错误、审计、投递记录或固定资产包。
- 收件人为保存时固定的白名单（最多 20 个），发送流程不读取请求参数中的收件人，杜绝把任务报告转发给任意地址。
- 强制 TLS：465 隐式 TLS、587 STARTTLS 且要求 TLS；禁止 25 明文与任何降级开关。
- 邮件主题与正文会经第三方邮箱服务商（QQ 邮箱、163 或企业 SMTP）传输和留存；正文可能包含持仓、交易与策略判断，因此收件人应限定为本人或明确知情的可信地址，并在页面上明示该边界。
- 邮件配置、收件人、订阅范围、投递记录与邮件正文属于本机私有数据，进入完整私有备份，不进入可移植固定资产包。换机后只恢复固定资产包时不带邮件配置；即使恢复完整私有备份带回了配置，也应在目标电脑重新核对 SMTP 参数、重新生成或确认专用密码，并发送测试邮件验证，不能把“备份里有配置”当成“换机后可直接发送”。
- 本机服务无认证，邮件不得附带指向 `127.0.0.1` 的详情链接，也不得为邮件跳转暴露未认证端口。
- 邮件只是通知副本：发送失败、取消或过期都不影响任务结果保存、页面展示与飞书推送。

## 验收要点

| 验收项 | 判定 |
|---|---|
| 设置页 | 可保存、发送测试邮件、清除配置；密码只回显是否已配置，收件人与任务范围可编辑并校验 |
| 任务完成收信 | 默认两个任务成功后收到一封主题为 `Stock｜任务名｜目标日`、正文为完整报告的邮件 |
| 关闭启用 | 关闭后不再入队；飞书开关、订阅与凭据变更不影响邮件，反之亦然 |
| 凭据变更 | 修改主机、账号、密码、发件人或收件人后，旧待发邮件被取消，等待新的任务结果 |
| 幂等与重试 | 同一结果最多一封；失败在一分钟、五分钟退避重试，3 次后转失败可补发 |
| 过期与取代 | 超过一天、结果被更新版取代时取消，不在后续重启中补发 |
| 错误脱敏 | 页面、日志与投递记录不含密码、授权码或含凭据的完整错误正文 |
| 数据边界 | 配置与投递记录进入完整私有备份，不进入固定资产包；换机后重新配置并测试 |
| 工程验证 | `npm run typecheck`、邮件定向测试与全量回归通过；验证证据由实现负责人补齐后回填状态账本 |

验证证据（typecheck、定向测试、全量回归与迁移执行结果）由后端与前端负责人完成后补入 `specs/邮件任务通知/状态.md`；本文只描述目标行为与边界，不把未执行的验证写成已通过。
