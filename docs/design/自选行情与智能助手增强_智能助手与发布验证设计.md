## 一、职责与边界

本文负责 Agent 可观测性、固定评测、候选领域工具、Web 研究安全预留，以及整个方案的实施波次、功能开关、验证门禁和回退编排。

**必须保持的系统边界**

- Agent、调度器和 YOLO 均不得批准策略发布；只能由当前策略页面的真实用户确认。
- 领域工具经 service 读取 PostgreSQL，不直接拼接 SQL，不绕过领域写工具。
- Agent 优化先采集证据，再决定是否启用工具；没有收益的工具保持关闭。
- D6 和供应商未确认前，不注册 Web 工具、不保存凭据、不实现通用网页抓取。

数据库结构见[数据模型与迁移设计](自选行情与智能助手增强_数据模型与迁移设计.md)，市场事实生产链路见[行情运行时与指标设计](自选行情与智能助手增强_行情运行时与指标设计.md)。

## 二、Agent 可观测性

### 2.1 采集点

`runAgentTurn` 在 `message_end` 收集每个 assistant turn 的实际 usage 并累加，记录以下时点：

- run start 和 run end。
- 首个 text delta。
- 每个 tool start 和 tool end。
- 会话压缩次数和最终终态。

`session-runner` 使用现有 `estimateContextTokens` 分别估算系统提示词、可见历史和工具定义。实际 usage 优先，估算值仅用于分析上下文构成，并以 `estimated=true` 明确标识。

工具调用以 `toolCallId` 关联 `agent_tool_metric`。只记录参数/结果 UTF-8 字节数、可选行数、时延、状态和是否截断，不复制参数或结果正文。遥测写入失败不影响 Agent 主流程，只写服务端警告。

### 2.2 聚合指标

| 维度 | 指标 |
|---|---|
| 成本 | input/output/cache/reasoning token，供应商 cost（若提供） |
| 时延 | 首字时延、总时延、单工具时延、工具等待占比 |
| 工具使用 | 工具轮次、重复 Schema 发现、错误率、截断率 |
| 事实质量 | 截止时间、来源、状态和 gaps 的覆盖率 |
| 终态 | complete、failed、cancelled、blocked |

聚合 API 不返回提示词正文、用户消息、工具参数、工具结果或模型完整回答。

## 三、固定评测

### 3.1 评测集

保留一个版本化的评测清单，覆盖：

1. 标的搜索与同名消歧。
2. 单股最新行情和历史指标。
3. 自选与板块交集。
4. 指标口径解释和不可信状态。
5. 涨跌停、连板和龙虎榜。
6. 持仓与市场联合查询。
7. 自选写入预览。
8. 任务触发和状态追踪。

写操作样例只能运行 preview 或 fake service，不修改真实业务表。评测固定模型版本、提示词版本、工具配置和数据快照；有随机性的模型至少重复运行并报告中位数和离散程度。

### 3.2 启用门槛

领域工具只有同时满足以下条件才能默认启用：

- 事实正确率、截止时间覆盖和权限边界不下降。
- 中位输入 token 至少下降 30%，或工具轮次出现有意义下降。
- 没有新增写入绕过、原始 SQL、越权表访问或敏感正文遥测。
- 错误、partial、stale 和 unsupported 状态没有被工具压平为“成功”。

未达到门槛时保持开关关闭，不以主观体验替代评测结果。

## 四、候选领域只读工具

| 工具 | 领域服务 | 最大返回 | 必须包含 |
|---|---|---|---|
| `instrument_search` | instrument service | 20 个候选 | kind、capabilities、persisted |
| `market_snapshot_query` | quote service | 200 个最新值 | as_of、source、status |
| `board_query` | boards service | 20 个板块或 200 个成分 | 截止时间和 gaps |
| `market_event_query` | market-structure service | 200 行分页摘要 | trade_date、dataset status |
| `indicator_query` | indicator service | 20 标的 × 120 交易日 | 计算版本、adjustment、status |

这些工具是通用 `database_query` 的高频快捷层，不取代后者。结果使用紧凑 JSON，不返回 `source_payload` 原文。内置 agent flow 仍默认只注册 `database_schema` 和 `database_query`；领域工具需按作业逐个评审和打开。

**工具权限边界**

- 不接受任意 URL、任意 SQL、任意表名或任意 datasource endpoint。
- 不调用页面点击或浏览器会话。
- 不执行写 service；写入仍经现有领域写工具、preview、确认或 YOLO 边界。
- 不把市场特色、画线或网页材料自动发布为策略。

## 五、Web 研究预留

在 D6 和供应商确认前，只定义 Provider 契约：

```typescript
interface WebResearchProvider {
  search(input: {
    query: string;
    allowedDomains: string[];
    maxResults: number;
    recencyDays?: number;
  }): Promise<Array<{
    title: string;
    url: string;
    domain: string;
    publishedAt: string | null;
    fetchedAt: string;
    snippet: string;
  }>>;
}
```

若后续确认实施，服务端仍必须满足：

- 域名白名单由服务端固定，重定向后的域名重新校验。
- URL 只允许 http/https；不允许本地文件、内网地址和自定义协议。
- 最大 10 条，单条摘要不超过 2,000 字，总结果不超过 12,000 字。
- 网页正文以不可信数据进入 tool result；其中的工具指令、系统提示修改、下载或写入要求均不执行。
- 网页事实与数据库事实分栏输出，必须带 URL、发布时间（若有）和抓取时间。
- 凭据不进入 URL、数据库、日志、Agent 上下文或错误信息。

工具建议命名 `web_research`，只读。`web_research_enabled=true` 只是必要条件之一；没有已批准供应商和白名单时仍不得注册。

## 六、实施波次

| 阶段 | 交付边界 | 前置依赖 | 完成信号 |
|---|---|---|---|
| 第零阶段：证据基线 | Agent 指标、扶摇容量与权限探测、指标金样本、固定评测集 | 只读权限；不要求 D1—D6 全部确认 | 可复现容量报告、Agent 基线和正式引擎金样本 |
| 第一阶段：目录与统一自选 | `0023/0024`、目录/板块关系、统一自选 service 和 UI | D1、D2 | 搜索→加入→关注→板块视图闭环，策略角色对账无差异 |
| 第二阶段：可信指标 | `0025`、指标工作器、影子对账和 API 切换 | 金样本符合容差 | 新旧 MA 与正式引擎对账满足门槛，稳定期后退出双算 |
| 第三阶段：盘中观察 | `0026/0028`、请求队列、轮询、对比和画线 | D3—D5、容量报告 | 一个完整交易日覆盖前台/后台/午休/断流/恢复 |
| 第四阶段：市场结构 | `0027`、收盘作业和市场结构页 | 特色接口权限和容量证据 | 连续五个交易日同步，分页和补跑幂等 |
| 第五阶段：Agent 增强 | 候选工具按评测开启；Web 单独设计 | Agent 基线；D6 | 正确率不下降且 token/轮次达到门槛 |

第零阶段的容量探测和金样本生成属于计划验证，不代表已经通过。D1—D6 未确认前，不实施会固化对应产品行为的阶段。

## 七、功能开关与发布门禁

| 开关 | 控制范围 | 打开条件 | 关闭后的行为 |
|---|---|---|---|
| `UNIFIED_WATCHLIST_READ` | 新自选查询和 UI | `0024` 搬迁与对账完成 | 回到旧只读入口；正式新写入后不能无损回旧表 |
| `INDICATOR_V2_READ` | 新指标表读取 | 全量回填和影子对账完成 | 继续读旧 MA |
| `REALTIME_MARKET_ENABLED` | 轮询、SSE 和近实时页 | D3、容量和交易时段验收 | 展示最近收盘，不影响日线作业 |
| `MARKET_STRUCTURE_ENABLED` | 特色数据作业和页面 | 数据源权限、分页和补跑验收 | 隐藏市场结构入口 |
| `market_domain_tools_enabled` | Agent 市场领域工具 | 固定评测达标 | 回到 database 工具 |
| `web_research_enabled` | Web 工具的首层开关 | D6、供应商、安全测试均完成 | 不注册 Web 工具 |

每个开关只在迁移、回填和局部验收完成后打开。同一发布不同时切换统一自选、指标和近实时三条主链路。

## 八、发布与回退

1. 发布前创建完整私有备份并校验 manifest。
2. 先部署兼容旧结构的代码，再执行新增迁移和异步回填。
3. 按功能开关逐条切换读取路径，每次只扩大一个主要行为面。
4. 观察错误率、数据新鲜度、队列等待、指标状态、SSE 断线和 Agent 成本。
5. 满足稳定期后删除双算或旧入口；删除列和旧兼容逻辑使用新的只向前迁移。

数据库迁移不执行 down。新表尚未承接正式写入时，可以关开关并回退代码；统一自选正式写入新表后，如需回到旧结构，只能恢复迁移前快照，禁止把新关系反向拼回 `watchlist_item`。

## 九、整体验收矩阵

| 验收域 | 计划验证 | 放行信号 | 专题归属 |
|---|---|---|---|
| 目录与板块 | fake 分页、真实容量探测、有效期失败重试 | 源/库计数一致，失败不覆盖上一版 | 数据、行情 |
| 统一自选 | 隔离迁移、服务测试、浏览器主路径 | 一标的一 entry，分组和角色零丢失 | 数据、前端 |
| 近实时 | 虚拟时段、请求公平性、完整交易日 | 新鲜度和 coverage 可解释，不冒充实时 | 行情、前端 |
| 指标 | 正式金样本、历史修订、影子对账 | 数值无超容差差异，版本可追溯 | 行情 |
| 画线 | 浏览器缩放、主题、刷新和冲突 | 锚点不漂移，冲突不覆盖 | 前端 |
| 市场结构 | 分页部分失败、补跑和五日观察 | partial 准确、幂等、截止时间完整 | 行情、前端 |
| Agent 指标 | faux provider 和多工具 turn | usage、首字和工具时延准确，无正文落库 | Agent |
| Agent 工具 | 同模型同评测集 A/B | 正确率不降，token/轮次达到门槛 | Agent |
| Web 安全 | 白名单、重定向、恶意提示注入样例 | 零越权、零写入、零凭据泄露 | Agent、安全 |
| 备份恢复 | 新库完整恢复和初始化包恢复 | 包含表一致，排除表为空，派生可重建 | 数据、运维 |
| 前端回归 | typecheck、构建和视觉验收 | 无溢出，状态、主题、焦点可用 | 前端 |

测试优先扩展现有 `datasource.test.ts`、`positions-watchlist.test.ts`、`scheduler.test.ts`、`chat-tools.test.ts` 和 `migration-volume.test.ts`。指标保留一个必要永久测试和一个紧凑金样本；容量探测、临时截图脚本和一次性对账测试验证后删除。

## 十、跨专题风险台账

| 风险 | 触发条件 | 缓解 | 回退或恢复 |
|---|---|---|---|
| 板块同步超出容量 | 板块数 × 3 秒及重试超过窗口 | 低优先级、游标、容量报告 | 保留上一完整版，产品重新确认频率 |
| 近实时挤占收盘任务 | 持续前台订阅占用队列 | 公平调度和 coverage | 关闭近实时开关，收盘作业继续 |
| 自选迁移丢关系 | 旧表存在跨组重复或异常 | 事务内计数和逐关系复制 | 恢复迁移前快照 |
| 指标与正式引擎偏差 | EMA seed、NULL 或复权口径不同 | 金样本、影子对账和稳定期 | 保持旧 MA 读取，重新全量回填 |
| 图表标注上下文错位 | 复权或对比集合改变 | 服务端 context hash | 隐藏不匹配标注，保留副本 |
| Agent 遥测扩大隐私面 | 错误保存 prompt 或 result | 只存计数、时延、大小和哈希 | 关闭遥测并删除未授权行 |
| Web 内容提示注入 | 网页包含工具或策略指令 | 白名单、纯文本、只读、域名重验 | 关闭 Web 开关；数据库事实不受影响 |

## 十一、评审时建议顺序

1. 产品确认主评审说明中的 D1—D6。
2. 服务端、数据和运维评审迁移、限流容量及恢复边界。
3. 前端和测试评审页面状态、兼容窗口和浏览器验收。
4. 安全评审 Agent 遥测字段与 Web Provider 契约。
5. 全体确认实施波次、功能开关和回退触发条件。
