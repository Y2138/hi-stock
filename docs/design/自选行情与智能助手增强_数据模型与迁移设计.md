## 一、职责与边界

本文是主评审说明的数据专题，负责定义数据库迁移顺序、表职责、约束、数据搬迁、备份恢复和一致性边界。

**本文负责**

- 标的目录、板块及成分关系。
- 统一自选、近实时行情、特色数据、指标、图表标注和 Agent 遥测的持久化结构。
- `0022`—`0028` 迁移顺序、数据搬迁、完整备份与初始化包规则。

**本文不负责**

- 扶摇请求调度、轮询频率和指标公式，见[行情运行时与指标设计](自选行情与智能助手增强_行情运行时与指标设计.md)。
- 页面交互和 HTTP 契约，见[前端交互与接口设计](自选行情与智能助手增强_前端交互与接口设计.md)。
- Agent 工具启用、评测门槛和发布波次，见[智能助手与发布验证设计](自选行情与智能助手增强_智能助手与发布验证设计.md)。

## 二、数据原则

1. **PostgreSQL 仍是运行时唯一业务事实源。** 页面、Agent 和调度器只经领域服务读写。
2. **目录、关注、分组和策略角色分层。** `market_instrument` 描述标的，`watchlist_entry` 描述是否自选，`watchlist_group_membership` 描述自定义组织，`pool_membership` 继续描述策略研究角色。
3. **盘中事实与日线事实物理分离。** 近实时值只写 `market_quote_latest` 和 `market_quote_sample`，不得写入 `market_bar` 或冒充分钟 K。
4. **原始行情与派生指标分离。** `market_bar` 保留标准化行情；权威指标写入 `market_indicator_value`，计算批次写入 `market_indicator_run`。
5. **迁移只向前。** 不改历史迁移；需要去除旧列或旧表时另加迁移，不在兼容期内破坏回退窗口。

## 三、迁移顺序

当前最新迁移为 `0021_chat_first_agent_jobs.sql`，新增迁移按下表追加：

| 迁移 | 主要变化 | 数据搬迁 | 失败行为 |
|---|---|---|---|
| `0022_agent_observability.sql` | Agent 运行、工具和评测指标；能力开关 | 无 | 整体事务回滚 |
| `0023_market_universe_boards.sql` | 标的类型与元数据；板块、成分、交易日历、系统跟踪 | 为既有标的填默认能力 | 非法类型或重复代码时回滚并输出差异 |
| `0024_unified_watchlist.sql` | 自选主记录与分组成员关系 | 从旧 `watchlist_item` 去重搬迁 | 数量或关系对账失败则整体回滚 |
| `0025_market_indicators.sql` | 指标批次、当前值和脏标记 | 只标记待算，不在 DDL 中执行算法 | DDL 回滚；派生回填由作业重试 |
| `0026_realtime_quotes.sql` | 最新快照、盘中采样和保留设置 | 无 | 整体事务回滚 |
| `0027_market_structure.sql` | 特色数据同步批次、涨跌停、龙虎榜、连板快照 | 无 | 整体事务回滚 |
| `0028_chart_annotations.sql` | 图表标注与乐观版本 | 无 | 整体事务回滚 |

迁移文件沿用现有英文代码标识；SQL 注释、迁移说明和对账报告使用中文。迁移前必须创建并校验完整私有备份。

## 四、标的目录与板块

### 4.1 `market_instrument` 扩展

`kind` 从 `stock/etf/index/futures` 扩展为：

```text
stock / etf / index / board / fund / futures
```

新增字段：

| 字段 | 类型 | 规则 |
|---|---|---|
| `ticker` | text | 纯代码，可空；唯一性仍以完整 `code` 为准 |
| `exchange` | text | SH/SZ/BJ 或空；`.OF` 不作为交易所 |
| `source_asset_type` | text | 供应商资产类型白名单 |
| `currency` | text | 当前默认 CNY，但不限制为唯一币种 |
| `lifecycle_status` | text | active/inactive/delisted/unknown |
| `capabilities` | jsonb | 由服务端白名单生成，不接受前端自由写入 |
| `source_updated_at` | timestamptz | 供应商目录时间 |
| `updated_at` | timestamptz | 本地档案更新时间 |

既有 `sector_code` 进入只读废弃期。板块查询切换完成并确认无消费者后，再通过新的只向前迁移删除。

### 4.2 板块关系

| 表 | 主键或唯一键 | 用途 |
|---|---|---|
| `market_instrument_alias` | `(instrument_id, alias)` | 历史名称和检索别名 |
| `market_board` | `instrument_id` | 板块一对一扩展；类型为 industry/concept/region/special |
| `market_board_membership` | `(board_instrument_id, member_instrument_id, effective_from)` | 带有效期的板块成分；当前关系使用部分唯一约束 |
| `market_trading_day` | `trade_date` | 交易日状态、来源和同步时间 |
| `market_system_tracking` | `(instrument_id, reason)` | 上证等系统基准和分析必需指数 |

成分同步仅在单个板块完整成功后比较集合：新增关系以目标日为 `effective_from`，消失关系的 `effective_to` 设为目标日且不含端点。失败、异常空集合或分页不完整时，不关闭上一版关系。

`opened_fetch_run_id` 和 `closed_fetch_run_id` 关联 `market_fetch_run`，用于回答“这条关系由哪次抓取打开或关闭”。源只提供当前成分，因此启用日前的历史关系明确不可用，不能用今天的数据反推。

## 五、统一自选

| 表 | 核心字段 | 约束 |
|---|---|---|
| `watchlist_entry` | instrument_id、focused、note、sort、added_at、updated_at | `instrument_id` 唯一 |
| `watchlist_group_membership` | group_id、entry_id、sort、added_at | `(group_id, entry_id)` 唯一；删除组只级联关系 |
| `watchlist_group` | 沿用现表 | 只保存自定义分组；全部、关注和板块属于动态视图 |

`0024` 在一个事务内完成：

1. 建立新表。
2. 按 `instrument_id` 聚合旧条目，以最早加入时间创建 entry。
3. 逐条复制旧分组关系。
4. 断言 entry 数等于旧表 distinct instrument 数，成员关系数等于旧表行数。
5. 对账通过后删除旧 `watchlist_item`；任一断言失败则整体回滚。

删除自选只删除 entry 及自定义分组关系，不修改 `pool_membership`、持仓或历史事件。D1 若确认兼容一版，旧 API 和只读策略角色入口在一个版本内继续读取新 service，不再双写旧表。

## 六、行情、指标与特色数据表

### 6.1 近实时行情

| 表 | 核心字段 | 约束 |
|---|---|---|
| `market_quote_latest` | instrument_id、trade_date、quote_time、fetched_at、last/prev/open/high/low、volume/turnover、source、request_id | 每标的一行；只有更晚时点或同时间修订可覆盖 |
| `market_quote_sample` | instrument_id、quote_time、价格和量额、fetched_at、source | `(instrument_id, quote_time)` 唯一；不表达 OHLC K 线 |

采样只在 `prev_close > 0` 且价格为有限值时写入。相同行情时间的修订更新同一行并刷新抓取留痕。保留期按 `market_trading_day` 计算，不用自然日近似。

### 6.2 指标

| 表 | 核心字段 | 说明 |
|---|---|---|
| `market_indicator_dirty` | instrument_id、freq、earliest_date、generation、reason、updated_at | 行情写入时合并脏标记 |
| `market_indicator_run` | calculation_version、input_sha256、日期范围、adjustment、status、gaps、起止时间 | 每次计算的审计批次 |
| `market_indicator_value` | market_bar 复合键、run_id、ma5/10/20/60、dif、dea、macd_hist、status、computed_at | 当前权威派生值；随行情删除 |

数值使用 `double precision`。当前值只有一份；历史复现依靠输入哈希、run 和版本化代码，不长期保存每个版本的全量派生行。指标公式、全量重算和双算退出条件由行情指标专题定义。

### 6.3 每日特色数据

| 表 | 用途 | 幂等键 |
|---|---|---|
| `market_special_sync_run` | 目标日、数据集、分页、状态、行数、gaps 和 job_run | `(job_run_id, dataset)`；手动同步允许无 job_run |
| `market_limit_event` | up/down/break 规范字段及受限源 payload | `(trade_date, event_type, instrument_id)` |
| `market_limit_ladder_snapshot` | 近 30 个交易日梯队矩阵和覆盖范围 | `(target_date, source_sha256)` |
| `market_dragon_tiger_entry` | all/org/hot_money 规范字段、range_days 和源行哈希 | `(trade_date, board_type, source_row_sha256)` |

`source_payload` 只保存该行业务字段，最大 32 KiB；禁止保存响应头、API Key 或完整请求 URL。供应商新增字段先进入适配器白名单，不自动暴露给 Agent Schema。

## 七、图表标注与 Agent 遥测

### 7.1 图表标注

`chart_annotation` 保存主标的、视图类型、坐标单位、复权口径、上下文、标注类型、数据锚点、文本、白名单样式、乐观版本、软删除和时间戳。

- `context_sha256` 由服务端根据主标的、频率、复权和排序后的对比代码生成，拒绝客户端自报哈希。
- horizontal、trend、text 分别要求 1、2、1 个锚点；趋势线的两个时间锚点必须不同。
- 文本最多 500 字；样式只允许颜色令牌、线型和线宽范围。
- PATCH 携带 `expected_version`；冲突返回当前服务端版本。DELETE 为软删除，批量清空必须二次确认。

### 7.2 Agent 遥测

| 表 | 保存内容 | 明确不保存 |
|---|---|---|
| `agent_run_metric` | session/run/model、usage/cost、提示词构成估算、首字/总时延、终态、压缩次数 | 系统提示词、用户全文和工具结果正文 |
| `agent_tool_metric` | tool_call_id、名称、顺序、时延、状态、参数/结果字节数、结果行数、截断状态 | args/result 明文 |
| `agent_evaluation_run` | 评测集版本、模型、工具配置、汇总指标、结论和时间 | API Key 和完整敏感回答 |

`agent_setting` 增加 `market_domain_tools_enabled` 和 `web_research_enabled`，默认均为 false。Web 开关打开仍不代表可以注册工具；供应商和白名单配置也是必要条件。

## 八、一致性、锁与保留

| 锁名 | 保护范围 |
|---|---|
| `agent:business-write` | 持仓、自选、标的池、作业和确认执行 |
| `market:daily-bars` | 日线写入 |
| `market:catalog` | 标的和交易日目录 |
| `market:boards` | 板块目录与成分 |
| `market:special:<date>` | 指定交易日特色数据 |
| `market:realtime-poller` | 多进程下单一近实时轮询器 |
| `market:indicator:<instrument>:<freq>` | 单行情序列指标计算 |

市场长任务不占 `agent:business-write`。档案 upsert 依靠 code 唯一约束；加入自选在事务内重新查询 instrument，网络请求在事务外完成，避免长事务和孤立外键。

D4 若确认保留 30 个交易日，盘中采样每日按交易日边界清理。图表标注和 Agent 指标不做自动长期扩散：前者只进入完整私有备份，后者按后续合规决策确定保留周期。

## 九、备份与恢复

完整私有备份由 `pg_dump` 包含全部新表，并由 manifest 行数校验覆盖。安全初始化包版本升为 3：

| 数据 | 初始化包 | 恢复行为 |
|---|---|---|
| 标的、alias、板块、成分、交易日、系统基准 | 包含 | 校验代码、关系和截止时间 |
| 统一自选及自定义分组 | 包含 | 只从新表恢复 |
| `market_bar` | 包含 | 沿用 coverage 校验 |
| 指标 current/run/dirty | 不包含 current/run | 恢复后全量标 dirty 并异步重建 |
| 最新快照和盘中采样 | 不包含 | 从新交易日重新采样，不展示备份时旧实时值 |
| 特色数据 | 默认不包含 | 按供应商可用窗口补拉，缺失明确显示 |
| 图表标注 | 不包含 | 仅完整私有备份保留 |
| Agent 指标和评测 | 不包含 | 不影响业务恢复 |

portable restore 的 RESET 顺序先删除引用表再删除 instrument。恢复事务只创建 dirty，不在事务内执行长时间指标计算。

## 十、计划验证

| 验证对象 | 计划方法 | 通过信号 |
|---|---|---|
| `0023` 目录迁移 | 隔离数据库执行迁移并统计 kind、code、能力 | 非法类型为 0，既有标的无丢失 |
| `0024` 自选迁移 | 对比 distinct instrument、旧行与新分组关系 | entry 和关系计数断言全部成立 |
| 板块有效期 | 构造新增、移除、异常空、失败和重试 | 只有完整成功批次开闭关系 |
| 快照和采样幂等 | 重放同 quote_time、修订和乱序数据 | latest 不倒退，sample 不重复，market_bar 不变 |
| 指标并发修订 | 计算期间更新历史行情 | 旧 generation 不提交，最终值来自最新输入 |
| 特色数据分页 | 模拟分页失败和重复 run | partial 状态准确，幂等键无重复 |
| 备份恢复 | 新库恢复完整备份和初始化包 | 包含表对账一致，排除表为空，派生值可重建 |

## 十一、专题风险与回退

| 风险 | 缓解 | 回退或恢复 |
|---|---|---|
| 自选去重时丢失跨组关系 | 事务内双计数和逐关系复制 | 迁移失败自动回滚；正式写入前不开新读取开关 |
| 完整目录让旧日更范围爆炸 | 日更范围只取持仓、角色、自选、系统基准和关联板块 | 关闭目录驱动 scope，恢复显式跟踪清单 |
| 指标表回填时间过长 | DDL 只建表和标 dirty，算法异步执行 | 继续读取旧 MA，待回填后再切换 |
| 初始化恢复后指标暂不可用 | 页面显示重建进度，其他模块不阻塞 | 使用完整私有备份恢复派生表；不得用不可信旧值冒充 |
