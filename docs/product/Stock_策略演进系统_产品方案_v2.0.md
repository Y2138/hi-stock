> **范围声明**：本文是策略演进系统二期的唯一产品范围入口，取代 v1.0 成为当前有效方案。v1.0 已交付的一期能力（任务运行、回测台账、数据集登记）保留沿用。本文不改变既有交易策略内容；Agent 负责理解用户意图、完成业务校验并通过领域工具写入，但不自主形成或执行买卖决定，策略事实仍以 PostgreSQL 当前策略为准。
>
> **v2.1 修订**：① 行情数据迁移入库，数据库成为行情唯一数据源，配套本地数据卷保证跨服务器可移植；② 确立"GUI 优先、AI 增强"交互原则，高频操作一律有页面快捷入口，新增自选功能。
>
> **v2.2 修订**：行情获取改为**服务端原生直连**（E11）——server 自行实现扶摇/AKShare 通道直接获取落库，不再经过本地 Python 脚本与 CSV 中转；历史 CSV 迁移入库后即停用。
>
> **v2.3 修订**：M2 按 pi 设计边界拆成 AI / core / UI 三层；LLM 厂商、API Key 与模型目录改由 PostgreSQL 统一管理；AI 对话改为全局悬浮入口与可缩放侧栏，不再占用独立业务导航。
>
> **v2.4 修订**：agent 数据库能力收敛为一个批量查询工具和一个确认制批量变更工具，覆盖全部业务数据表；表名按领域统一前缀；行情获取与工具卡改为批量执行和聚合展示。
>
> **v2.5 修订**：新增可持久化 YOLO 模式；用户在设置页明确开启后，`database_change` 跳过确认卡直接执行，但 schema 校验、事务、保护表、敏感列、影响上限与审计不关闭；系统提示词同步声明全部工具、主要数据领域与当前执行模式。
>
> **v2.6 修订**：LLM 工具参数按不可信输入处理，服务端在 pi loop 校验之外再次执行严格结构与业务语义校验；所有会改变业务数据的对话工具共用 PostgreSQL 数据库级写锁，确认提案在执行前复核目标状态，防止多会话并发写入、重复确认和旧提案覆盖新状态。
>
> **v2.7 实现同步**：M3 已交付 `job_definition` / `job_run`、Asia/Shanghai 30 秒调度、停机漏跑留痕、一次延迟重试、datasource/script/只读 agent_flow Runner、作业 API、Agent `trigger_job` 与任务中心结果预览。作业配置和 LLM 工具输入均由服务端再次校验；脚本仅可选择固定白名单 argv，agent_flow 只生成“未经确认”的 Markdown 预览，不写入事实文件。
>
> **v2.8 修订**：数据库读取改为 `database_schema` 渐进发现 + 携带逐表 `schema_hash` 的 `database_query`；删除通用 `database_change`，写入按持仓、自选、标的池、任务运行、回测五个领域工具划分并强制经过领域 service。确认制、YOLO、事务、审计、数据库写锁、敏感数据保护和状态冲突检测保持生效；旧 `database_change` 记录及 pending 提案不兼容。
>
> **v2.9 修订**：在 M4 前插入 M3.5“独立维护”。策略、指引、交易计划、Markdown 归档、作业提示词和作业定义改由 PostgreSQL 直接维护；页面与 Agent 均可追加版本、比较、回滚和维护作业。必要分析与回测执行内化到 Node 服务，不再调用外部 Python。数据交付采用可移植初始化包与完整私有备份双轨，旧纯前端 MVP 构建在事实源切换后删除。
>
> **v2.10 修订**：`portfolio_write` 从单一持仓事件扩展为组合账户领域工具：除成交/调整/备注外，可按日期维护总资产、证券市值、可用资金与累计清仓收益；未提供证券市值时由组合账户 service 按总资产减可用资金推导。确认制、YOLO、事务、审计、写锁和状态冲突检测保持不变。
>
> **v2.11 修订**：三个内置 agent_flow 的当前提示词改为数据库原生版本。流程提示词从 `job_prompt_revision` 固化，业务规则从 `content_document.current_revision_id` 对应正文读取，持仓、标的池、行情和分析从结构化业务表读取；运行时只注册 `database_schema` 与 `database_query`，不再读取 `定时任务/*.md` 或任何仓库文件。
>
> **v2.12 修订**：内容库只保留策略、指引、当前交易计划及交易计划归档。标的池、持仓流水和任务模板等 7 份已迁移副本由 0014 物理移除；内置 Agent 系统提示词按单一事实源映射和任务路由读取数据库，并动态注入最新资金摘要。迁移证据表不再向 Agent 暴露。
>
> **v2.13 收口**：扶摇 datasource 增加估值快照与利润表、资产负债表、现金流量表批量获取，只选择三表共同存在的最新报告期并幂等落库；最终安全初始化包包含该财务/估值样本。M3.5 已在全新目录与空数据库中完成恢复、内容/作业/分析/回测/Agent 与页面路由验收，旧同步器、摄取器、外部 Python Runner 和纯前端 MVP 生产入口全部退役。
>
> **v2.14 修订**：进入 M4 后先交付非 CLI 增强：内容版本/版本变化、作业运行和回测结论均可一键把数据库记录标识带入全局 AI 侧栏，由用户检查后发送；新增浅色、深色、跟随系统三种外观和完整动效/键盘焦点收口。外部 CLI 探测、`delegate_to_cli`、命令执行和审计写入按用户决定暂缓，当前生产不注册、不探测、不调用。
>
> **v2.15 修订**：仪表盘改为面向每日决策的状态工作台。首屏按“数据可信度与待处理异常 → 账户和持仓 → 账户趋势 → 数据与任务健康”排序；失败/部分失败/错过任务、持仓行情缺口和资金快照滞后自动聚合为待处理项。资金快照与持仓行情分别标注日期，不把不同时点金额混作同一快照；快捷操作收敛到页头，取消四张异构卡片同排造成的拥挤。

> **v2.16 修订**：AI 对话支持在会话内选择可用模型，模型选择随 `chat_session` 持久化，不同会话互不影响；新会话继承设置页的全局当前模型。流式文本在前端平滑呈现，输入区聚焦态收敛为单层强调描边，不再叠加外圈阴影。经审计，pi 依赖具备上下文压缩能力，但当前系统未接入自动压缩，本轮不实施。
>
> **v2.17 修订**：新增全局 message 提示层，统一成功、错误、警告和信息四类提示。所有普通 JSON 请求、SSE 建流/中断和附件上传的接口失败都会即时显示错误 message；同类重复错误在短时间内合并，最多同时显示四条。加载区域继续保留原位错误与重试，业务操作成功使用全局短提示，表单校验和风险前置条件使用警告。
>
> **v2.18 修订**：策略产品模型收敛为“当前最终策略 + 简要演进记录”，不再建设用户可见的历史策略全文与回测代码版本链；每日计划和其他 Agent 作业结果归具体任务运行。每个 Agent 作业建立独立、可重放的 session，Agent 与业务模块改为可收放的常驻分栏，并通过受控 `ui_refresh` 事件让页面重新取数。回测改为 Agent 自驱的临时代码验证，代码正文不持久化；策略发布永远由真实用户人工批准，不受 YOLO 影响。整体按 session 基础、工作台、领域归位、自驱回测四阶段实施。
>
> **v2.19 实现同步**：第一阶段已完成。真实数据库应用 `0016_agent_session.sql`；交互对话与 `agent_flow` 已共用统一 session 执行器，作业排队前原子创建唯一 session，自动重试复用 session 并新增 attempt，低频过程支持按游标补发后续流，任务 session 保持只读。功能开关关闭时既有对话与调度路径可回退；本阶段未迁移策略、计划或回测事实，也未引入临时代码工作区。

> **v2.20 实现同步**：第二阶段已完成。旧悬浮 `ChatDrawer` 已由布局内 `AgentWorkspace` 取代；左侧导航可在 188/56px 间收放，右侧工作区可收起为 48px 轨道、拖动并记忆宽度，收起不卸载对话或丢失草稿。任务运行详情可查看只读 Agent session 的 attempt、事件时间线和完成消息；白名单 `ui_refresh` 事件先持久化再推送，页面按模块局部重新取数。小于 1100px 时 Agent 改为页面下方分区，不使用悬浮遮罩。本阶段未迁移策略、任务结果或回测事实。

> **v2.21 实现同步**：第三阶段已完成。`0017_strategy_job_outputs.sql` 建立 8 份当前策略/核心指引、整体策略状态、简要演进、真人发布提案与 `job_run_output`；19 份历史每日计划已归每日计划任务。Agent 每轮与 Agent Flow 都使用同一当前策略快照，YOLO 只能创建待审核提案；批准/拒绝必须由当前策略页面领取一次性令牌后执行。旧内容写入口已关闭，内容导航退役；任务中心可直接预览关联结果。真实库迁移、全量回归、1280×720 运行时验收和迁移上限 17 的空库恢复均通过。

> **v2.22 修订**：Agent 运行控制与会话形态统一。停止操作通过服务端运行注册表调用当前 pi Agent，不再只是断开浏览器 SSE；运行中可把补充消息按 `steer` 投递到下一执行边界，或按 `follow_up` 排到本轮自然结束后。控制请求必须携带当前 `run_id` 防止误投。任务来源继续以 `session_type/source` 标注，但不再只读或另建关联对话，用户可在原任务会话直接追问、切模型、归档和重命名。上下文达到模型输入预算约 80% 时自动摘要旧前缀并保留近期完整消息；原始 `chat_message` 永不因压缩删除。

## 二、产品定位与用户问题

**定位**：从一期“台账系统”升级为 **Agent 协作的个人策略演进工作台**——本机运行的单用户系统，当前策略、短线/长线池、行情、持仓、回测最终结论、任务和可复用记忆统一入库、可视化、可追溯；页面负责查询和治理，Agent 负责需要理解上下文的业务写入。

**用户与场景**：有一定交易经验、时间有限的 A 股个人投资者（本人），盘后复盘与策略迭代场景，桌面浏览器使用。

| 场景 | 用户要回答的问题 | 二期输出 |
|------|------------------|----------|
| 打开系统 | 今天数据齐不齐、什么必须先处理、账户与持仓什么状态 | 仪表盘：数据可信度、待处理异常、账户/持仓关键指标、离散趋势、数据与任务健康、快捷操作 |
| 研究一只票 | 想评估某标的是否进入短线池或长线池，并查看 K 线 | Agent 完整评估后发起入池提案；页面从池、板块或搜索下钻行情 |
| 想问就问 | 某只持仓什么成本、哪个策略章节怎么规定的、上次回测改了什么 | AI 对话：工具直达库内事实，答案带来源 |
| 复盘持仓 | 收益怎么走、持仓怎么变的、个股 K 线什么结构 | 持仓页：收益曲线、变化时间线、个股 K 线 |

## 三、目标与非目标

### 3.1 目标

- 七类当前资产全部入库可查：当前策略、短线/长线池、行情与财务估值、持仓及成交归因、回测最终结论、定时任务及结果、Agent 可复用记忆。
- **行情数据以数据库为唯一数据源**（E9）：所有页面、API、AI 工具一律从库读取；本地数据卷提供一键导出/导入快照，支持跨服务器迁移。
- **服务端原生数据获取**（E11）：server 内置 datasource 模块直连数据源，获取即落库；不依赖 `支撑/scripts/` 的 Python 获取链路；历史 CSV 一次性迁移入库、对账通过后停用。
- **Agent 主导业务写入、页面负责查询与治理**（E36）：标的入池、成交/资金、作业定义/提示词和记忆只能经 Agent 领域工具写入；页面保留确认、策略发布、任务控制、模型设置与备份等治理入口。
- Agent 对话支持图片输入，答案可追溯到数据库内容版本或结构化记录；持仓变更走“理解与复述→提案→确认”，页面不提供旁路表单。
- 定时任务可自动执行数据更新作业与 AI 流程作业；每个 Agent 运行有独立 session，计划与复盘结果归具体运行并可直接预览。
- 策略和核心指引由数据库维护当前最终正文；用户可见演进历史只保留大纲、结论、调整点和是否采纳。交易计划与其他任务结果归任务中心，不再作为通用内容库文档浏览。
- agent_flow 提示词作为独立业务维护并版本化；作业运行固化实际提示词版本，Agent 可通过受控工具创建或修改，页面只控制启停、立即运行和失败处理。
- 板块温度、关键位与长线估值由服务读取数据库执行；回测由 Agent 在受控 TypeScript 临时工作区编写验证逻辑并交给独立 Node 工作器执行，不依赖 Python 环境，代码正文不入库。
- 整体 UI 为非商务个人灵动风格，交互有呼吸感。

### 3.2 非目标（二期）

- 不做交易下单、券商连接、实时/盘中行情。
- 不做多用户、权限体系、公网/局域网暴露、云同步。
- 不做 AI 自主买卖建议；AI 对话内容不进入策略事实源。
- 不做 DB→旧根目录 Markdown 回写；旧文件完成一次性导入后只作迁移证据，不再参与生产运行。不做移动端（先行桌面）。
- 不把回测代码正文、中间脚本或临时产物当作数据库资产；数据库只保存可复查请求、输入摘要、指标、结论、缺口和服务版本。

## 四、总体架构

```
浏览器 Vue 3 SPA（server 静态托管构建产物）
   │ REST + SSE（AI 流式输出）+ multipart（图片上传）
server/
   agent/ai/      pi-ai 供应商/模型统一适配与 PostgreSQL 凭据存取
   agent/core/    pi-agent-core 核心 loop、历史恢复与领域无关事件映射
   agent/         工具注册表、会话管理、确认制、系统提示词与 HTTP/SSE 接入
   agent/bridge/  M4 预留的外部 CLI 桥（当前生产未实现）
   datasource/    服务端原生数据获取：hithink 通道（扶摇 HTTP API 直连）+
                  akshare 通道（底层公开 HTTP 接口直连）；获取即落库
   analysis/      板块温度、关键位、长线估值等数据库内计算
   backtest/      受控回测执行；只持久化请求、输入摘要、指标与结论
   volume/        完整私有备份 + 可移植初始化包（白名单导出、清单校验）
   scheduler/     进程内调度器：cron 匹配、作业执行、结果入库
   modules/       job-prompts / backtests / positions / market /
                  pools / memory；作业在 scheduler，聊天在 agent
   uploads/       对话图片附件（gitignored）
PostgreSQL        事实源：一期 6 表 + 二期新增表（见第九章）
datavolume/  本地数据卷（gitignored）：可携带快照，随迁移拷贝
```

- 服务仍只绑定 `127.0.0.1`；LLM API Key 只存 PostgreSQL（并随数据卷快照保存），扶摇 API Key 仍从本机 `.env.local` 读取。
- 前端构建产物由 server 托管，单一端口；开发期用 Vite dev server 代理 `/api`。
- 调度器随 server 进程运行，不做独立守护进程；server 停了调度即停，启动时补记缺口。

## 五、交互原则与页面信息架构

### 5.1 Agent 主导业务写入、页面负责查询与治理（E36）

- **业务事实由 Agent 写入**：标的入池、成交/资金、作业定义/提示词与记忆维护必须先理解上下文，再通过固定领域工具提案或在 YOLO 下执行；页面不维护并行录入表单。
- **页面承担查询与治理**：行情、池、持仓、回测、任务和记忆可查询下钻；确认卡、策略真人发布、任务启停/触发/失败处理、模型设置与备份仍保留直接入口。
- **研究型回测由 Agent 驱动**：Agent 读取当前策略、编写临时代码、解释缺口并显式晋升最终结论；页面只展示最终结论。
- **全局命令面板**（Cmd/Ctrl+K）：搜索标的、页面、任务和记忆，回车进入只读页面或行情详情；需要改变业务事实时转入 Agent。

### 5.2 页面结构

左侧为可在约 188px 完整菜单和 56px 图标栏间切换的导航，顶栏为全局状态条（行情截止日、今日任务状态圆点、刷新入口、AI 通道状态）。右侧 Agent 工作区支持收起和拖动分栏，收起不终止 session 或任务。

| 页面 | 首要问题 | 主要内容 |
|------|----------|----------|
| 仪表盘 | 今天系统是否可信、什么必须先处理 | 状态总览、**异常聚合（失败任务/行情缺口/资金快照滞后）**、账户与持仓关键指标、总资产离散记录、数据与任务健康；业务变更转入 Agent |
| 当前策略 | 当前最终策略是什么、最近为什么调整 | 策略与核心指引当前正文、最后更新时间、简要演进记录；待发布提案摘要与可展开 diff、真人发布按钮 |
| 短线池 | 当前短线研究对象和关注顺序是什么 | 近期关注、板块视图、角色/分级/评分/股性/阶段/标签、行情下钻 |
| 长线池 | 当前波段与长线研究对象是什么 | 近期关注、板块视图、角色/分级/评分/股性/阶段/标签、行情下钻 |
| 持仓 | 账户和持仓什么状态、各次变更因何发生 | 资金摘要、持仓表、收益曲线、归因构成、带策略/计划/会话来源的变化时间线；写入转入 Agent |
| 行情 | 多个标的在同一日线区间表现如何、单个标的日线结构如何 | 主标的加最多三个对比标的的区间归一化曲线、日线/期货日线 K 线与可信指标；图表显示中文价量口径、单位和单日涨跌幅，不提供画线，不展示盘中或分时行情 |
| 市场结构 | 目标交易日的市场情绪与活跃资金结构如何 | 涨停、跌停、炸板、连板天梯和龙虎榜 Tab，中文表头、同步状态、覆盖进度与数据缺口 |
| 回测 | 已确认的研究结论和适用边界是什么 | 每个研究会话当前最终结论、输入摘要、指标、缺口、适用边界与来源会话；工作运行默认隐藏 |
| 任务中心 | 任务跑没跑、失败如何处理 | 作业定义只读、运行状态、结果预览、来源会话、**启停/立即运行/失败重试**；不编辑定义或提示词 |
| Agent 记忆 | 哪些已验证方法可以复用 | 有效/待复核/已替代/已废弃记忆的只读列表与详情，按类型、标签和验证时间筛选 |
| 数据与备份 | 数据获取与数据卷健康吗 | 数据源通道、行情覆盖、缺口、完整私有备份与安全初始化包的导出/恢复 |
| 设置 | 系统配置 | LLM 厂商/API 协议/Base URL/API Key/模型目录与当前模型（key 不回显）、确认制/YOLO |

视图切换保留各自选择状态；所有金额/数量表支持复制；颜色不作为涨跌与状态的唯一表达（图标+文字并行）。

Agent 不占用左侧业务导航项，也不再以悬浮层遮挡主页面。桌面端业务模块与 Agent 工作区处于同一布局流，默认约 42%/58%，分隔条可拖动；右侧收起为约 48px 状态轨道，重新展开恢复原 session、滚动、草稿和宽度。小于约 1100px 时固定使用上下分区，不恢复悬浮抽屉。旧 `/chat` 仅保留为打开当前工作区的兼容重定向，`ChatDrawer` 已删除。

### 6.1 行情数据：服务端原生获取 + 库为唯一数据源 + 本地数据卷（E9 + E11）

**数据获取（服务端原生，不再依赖本地 Python 获取脚本）**：

| 项目 | 定义 |
|------|------|
| hithink 通道 | TypeScript 直连扶摇 HTTP API（fuyao.aicubes.cn）：日线 K 线、按股票/指数/ETF 分组路由的行情快照、通用端点（涨停池/估值/财务/交易日历）；key 只读 PostgreSQL `system_setting`，由设置页维护且不回显；信封 `code==0`、限流退避（429/code=4001，串行间隔 ≥3 秒）、单次范围 ≤3 年、代码带 `.SH/.SZ` 后缀、股票默认前复权——口径与 `数据获取规范.md` 第一章一致，规范仍是唯一维护处，本系统引用不复制 |
| akshare 通道 | 扶摇缺能力的数据（30 分钟线、期货主力连续、个股资金流），服务端直接实现其底层公开 HTTP 接口（新浪分钟线/期货、东财 push2delay 资金流），**不经过 Python/akshare 库**；降级与失败处理规则继续遵守 `数据获取规范.md` 第二章 |
| 优先级与降级 | 扶摇 → AKShare 的优先级与"不得静默切换"原则不变；每次获取记录实际使用通道与降级原因，任务结果与页面可见 |
| 落库 | 获取即写 `market_bar`（含复权/成交量单位口径字段）；同一标的同一日期幂等覆盖；写入结果（新增/更新行数、缺口、失败清单）进任务运行记录 |
| 指标 | MA5/10/20/60 等基础指标由服务端在落库时计算入库（或查询时计算，技术设计定）；板块温度、关键位、估值快照等复合计算随 M3 任务系统逐步内化为服务端模块，过渡期可继续调用既有 calc 脚本（读库适配） |

**本地数据卷（可移植性）**：

| 项目 | 定义 |
|------|------|
| 位置 | `datavolume/`（gitignored），与数据库卷分离，专为用户可携带的导出快照 |
| 导出 | 一键/定时（每日任务成功后）：`pg_dump` 自定义格式全量快照 + `manifest.json`（导出时间、各表行数、行情 coverage、校验和）；按日期滚动保留最近 N 份（默认 14） |

### 6.3 AI 对话

| 项目 | 定义 |
|------|------|
| 分层 | AI 层 `agent/ai/` 用 pi-ai 统一不同服务商与协议；core 层 `agent/core/` 用 pi-agent-core 承载核心 loop；统一会话执行器只持久化 `chat_session`、`chat_message` 与低频 `chat_session_event`；UI 层由布局内 `AgentWorkspace` 与对话组件承载 |
| 模型配置 | PostgreSQL 为唯一事实源；设置页可维护厂商、API 协议、Base URL、API Key、模型能力与全局默认模型；对话框可为当前会话选择模型并写入 `chat_session.model_id`，不同会话互不影响；不读取 pi 本地凭据库或 LLM 环境变量，接口只返回 `api_key_configured` |
| 入口 | 所有业务页面共享常驻 Agent 工作区；支持收起、拖动分栏和宽度记忆，旧悬浮抽屉已删除，`/chat` 只作兼容重定向 |
| 会话 | 交互与作业统一使用 `chat_session`。每次 Agent 作业触发新建一个任务对话，首轮执行和最多一次重试都在其中追加消息；`session_type/source` 只描述来源，完成、失败或中断后可继续追问。任务状态仍以 `job_run` 为准，不建立 attempt/resource 第二套状态 |
| 流式与控制 | SSE 增量输出，前端以短缓冲平滑追加文本并显示流式光标。运行中输入保持可用：默认干预当前任务，也可排到下一轮；停止会取消服务端 Agent。`steer` 在下一执行边界生效，不能修改已经生成的 token，也不会回滚已完成的工具写入 |
| 上下文 | 每轮读取完整原始消息，但只向模型发送“持久摘要 + 摘要边界后的近期原文”。输入估算达到模型预算约 80% 时更新摘要，保留约 18% 的近期上下文；先裁剪过大的旧工具结果，工具调用与结果成对保留。压缩不删除或改写 `chat_message` |
| 图片 | multipart 上传到 `server/uploads/`（gitignored），消息内缩略图；要求模型具备 vision 能力，未配置 vision 模型时上传入口禁用并说明 |
| 系统提示词 | 服务端组装：角色/安全边界、单一事实源映射、数据库化任务读取路由、完整工具契约、动态轻量表索引（表名/领域/业务说明/schema_hash）、当前确认/YOLO 模式、并发写规则、持仓与最新资金摘要、今日任务和数据截止时间；不允许模型猜测字段或事实，忙锁/Schema 漂移/状态冲突时不得盲重试 |
| 执行模式 | 设置页可切换确认制/YOLO；确认制产生 pending 卡，YOLO 校验后直接事务执行；顶栏和对话持续显示 YOLO 警示 |
| 执行轨迹与工具卡片 | 同一用户轮次只有一张 Agent 执行轨迹卡，内部区分思考进展、工具调用和最终回答；批量调用显示项目数、成功/失败数与写入行数；连续同名调用聚合为一张摘要卡并默认折叠明细；确认卡始终独立完整展示 |
| 通道 | 当前仅启用 pi 直连；外部 codex/claude 委派按 E24 暂缓，不注册 `delegate_to_cli` |
| 结果协作 | Agent 产生的任务结果、回测和策略提案写入对应领域表；任务完成后在对话追加可点击的结果入口，领域表通过 `session_id` 直接关联对话，不建立通用资源引用表；主模块自动刷新但不抢占用户锁定的记录 |
| 快捷对话 | 回测延续、回测对比、策略演进、任务解读等页面快捷入口先要求用户二次确认；确认后新建独立会话并预填数据库记录 ID、目标和边界。延续型入口可记录 `parent_session_id`，但不向原会话追加消息，也不自动发送 |
| 页面刷新 | Agent 可调用白名单 `ui_refresh` 发布模块刷新事件；前端局部重新取数并保留路由、session、滚动、输入草稿和未提交编辑，不执行整页重载或任意浏览器控制 |

**工具目录（M2 收敛版）**：

| 类别 | 工具 | 说明 |
|------|------|------|
| 只读 | `database_schema` | `list_tables` 获取轻量索引；`describe_tables` 按需获取字段、主外键、唯一键、枚举、关系、业务约束与写策略；哈希未变化时会话内复用 |
| 只读 | `database_query` | 每项携带相关表 `schema_hash` 的结构化查询计划；服务端执行前重验并构建参数化只读 SQL，支持过滤、排序、计数与分页；敏感列不暴露 |
| 只读 | `memory_query` | 按关键词、类型和标签检索有效或指定状态的可复用记忆；默认不注入全部正文 |
| 写 | `portfolio_write` | `record_position_change` 经持仓 service 维护带归因的事件流、当前态与资金台账；`upsert_account_snapshot` 按日期维护账户锚点 |
| 写 | `pool_write` | 通过标的池 service 完整校验研究属性、股票官方行业关系和唯一当前角色后新增/更新/结束角色；拒绝本地板块标签和自行指定行业字段 |
| 写 | `job_write` | 通过作业 service 维护受控作业定义和版本化提示词，不修改运行历史 |
| 写 | `memory_write` | 创建、更新、替代或废弃已验证的长期可复用产物；拒绝密钥、临时代码和业务事实副本 |
| 写 | `strategy_publish_request` | 只创建待真人审核的当前策略发布提案；YOLO、Agent 和调度器均不能批准 |
| 写 | `finalize_backtest` | 把当前研究会话中的一次成功/部分成功工作运行晋升为最终结论；同会话旧最终结论标记为已替代 |
| 动作 | `analysis_run` | 批量运行板块温度、关键位或长线估值并登记结果与缺口 |
| 动作 | `run_backtest` | Agent 把临时 TypeScript 只放在本次工具参数，经隔离工作器执行；数据库只保存哈希、输入摘要、指标、结论和缺口 |
| 动作 | `fetch_market_data` | 一次接收最多 200 项行情请求，顺序执行、进度汇总、单项失败默认不阻断其余项 |
| 动作 | `trigger_job` | 只按现有作业 code 排队；queued 不代表运行成功 |
| 动作 | `ui_refresh` | 只向白名单业务模块发送重新取数事件，不执行点击、输入、导航或任意浏览器控制 |
| 预留委派（未注册） | `delegate_to_cli` | 按 E24 暂缓；当前生产不探测或调用本地 codex/claude |

旧通用 `database_change`、`watchlist_write`、`content_write`、`backtest_write` 和固定服务版 `run_backtest` 均不再注册，历史 pending 提案不得借兼容路径执行。`delegate_to_cli` 仅保留设计预留，须经用户重新确认后才进入实施和注册。

| 持仓表 | 标的、数量、成本、最新收盘、市值、累计盈亏金额与收益率、占比、角色、执行位（止损/止盈结果值+规则引用） |
| 变化时间线 | `portfolio_position_change` 事件流：成交、执行位调整、备注；每次事件固化决策来源、执行符合度、策略序号/哈希、可选计划结果、来源会话、归因说明与偏离原因 |
| 归因构成 | 当前持仓只聚合展示各类事件归因数量，不保存会覆盖历史的“是否策略持仓”布尔值 |
| Agent 更新 | 口述成交/变动使用 `record_position_change`；口述总资产、可用资金或清仓收益使用 `upsert_account_snapshot`。两者均由 `portfolio_write` 产出提案，确认后调用组合账户 service；页面无直接录入表单 |

资金台账以新快照校准、以锚点后成交连续推进：买入按成交金额扣减现金，现金不足则整笔成交回滚；卖出按成交金额回补现金；只有完全清仓时才删除当前持仓行，并按“卖出数量 ×（成交价－持仓成本）”累加清仓收益，部分卖出只回补现金。清仓后的历史成本与成交继续由事件流追溯。锚点日及以前成交视为已被快照吸收；从未同步快照时现金未知，系统不猜测且不阻塞持仓事件。

持仓、账户与持仓流水已经完成事实源移交，页面、Agent 和作业只读写 `portfolio_*`；`当前持仓.md` 与历史流水文件不再进入内容库或生产读取链路。

### 6.7 定时任务系统

| 项目 | 定义 |
|------|------|
| 作业定义 | `job_definition`：code、cron、job_type（`datasource`/`analysis`/`agent_flow`）、enabled、config |
| 调度 | server 进程内每 30 秒 tick，固定按 Asia/Shanghai 匹配 cron；页面支持手动触发、暂停、立即运行 |
| 运行记录 | `job_run`：状态机 queued→running→success/failed/partial/missed；日志、数据缺口、起止时间；真正运行 Agent 的记录通过 `session_id` 一对一关联普通对话 |
| datasource 作业 | 内置数据更新链路：datasource 拉取落库 → 指标计算 → 数据卷导出；不经过任何外部脚本 |
| analysis 作业 | 只接受板块温度、关键位、长线估值三种结构化请求，复用 `analysis/` 服务读数据库执行；不接受命令、脚本路径或用户 argv |
| agent_flow 作业 | 固化绑定的 `job_prompt_revision` 和实际策略状态，把任务说明作为对话首条用户消息，调用普通会话执行器并限制为只读工具；重试继续使用同一对话历史 |
| 结果预览 | 每日计划等产物进入 `job_run_output`；结果和运行终态同事务提交，随后在任务对话追加“查看任务结果”入口。任务结果、最终回测和 Agent 记忆共用全局单例阅读器，URL 可恢复；其他落库结果直接导航并定位到所属业务页面。任务中心历史抽屉只保留列表与运行详情，不再在底部内联 Markdown |
| 失败处理 | 失败运行保留日志；server 重启后补记停机期间缺口为 `missed`；不做无限重试（最多 1 次自动重试） |
| 页面边界 | 任务中心只读定义、提示词版本、运行和结果；只允许启停、立即运行、失败重试及打开来源会话。创建、cron/类型/config 修改和提示词维护只经 `job_write` |

初始作业清单：`daily_data_update`（工作日 15:45，datasource：拉取→MA 指标→scheduled 数据卷导出）、`daily_plan_flow`（每日 17:15，agent_flow）、`midweek_check`（周二 17:30，agent_flow）、`weekly_review`（周日 20:00，agent_flow）。后三者绑定数据库提示词并在运行时固化实际版本；提示词只规定流程和读取范围，策略参数来自 `strategy_state + strategy_document + strategy_document_revision` 当前最终版本。暂停只停止 cron，用户仍可手动触发。

### 6.8 Agent 自驱回测边界（E30，第四阶段已完成）

| 项目 | 定义 |
|------|------|
| 发起 | 用户在 Agent 中提出策略演进或验证思路；回测页不提供新建服务回测表单，只展示最终确认结论 |
| 执行 | Agent 在有过期时间的 TypeScript 临时工作区编写验证代码，经固定回测 SDK、类型检查和导入白名单后交给独立 Node 进程/容器执行；主服务只传结构化只读数据 |
| 持久化 | `backtest_run` 保存目的、策略状态哈希、输入摘要、SDK/工作器版本、参数、代码哈希、指标、缺口、终态和结论状态；聊天、审计、确认、备份均不保存代码正文、补丁或工作区路径 |
| 清理 | 成功、失败、超时、中断和服务重启恢复都必须删除临时代码；日志只返回脱敏错误摘要 |
| 结论晋升 | 每次运行先处于 `working`；Agent 调用 `finalize_backtest` 写入结论摘要和适用边界后才进入历史。同一会话至多一个 `final`，重新确认会把旧结论标记为 `superseded` |
| 策略关系 | 策略发布提案只能引用 `final` 回测；发布始终由真实用户人工批准，YOLO 不能激活策略 |
| 历史兼容 | 无会话的已完成历史记录按迁移规则保留为最终结论；页面新建表单、旧生产提交/激活入口和 `backtest_write` 已移除 |

## 九、安全与边界

- LLM API Key 只存 PostgreSQL，页面/API/日志/错误信息均不输出本体，设置页只显示“已配置/未配置”；数据库与数据卷因此属于敏感数据。扶摇 API Key 仍只在本机 `.env.local`，不入库。
- 服务仅 `127.0.0.1`；启动日志持续声明不得暴露到局域网/公网。
- datasource 模块只发起对扶摇/新浪/东财公开接口的出站请求，不引入其他外部服务。
- 写操作默认确认制；用户明确开启 YOLO 后领域写工具可直接执行。两种模式都通过对应领域 service、同一可序列化事务与 `agent_tool_audit`，YOLO 状态在设置页、顶栏、对话和系统提示词明示。
- 数据库读取不接收原始 SQL；Agent 先获得轻量表索引，按需描述相关表，再提交携带逐表 `schema_hash` 的结构化查询计划。服务端执行前重验哈希、校验标识符、绑定全部数据值并限制行数；`llm_provider.api_key` 不进入索引详情或查询结果。
- 领域写工具不接受表、列、过滤器或任意行，只接受固定业务参数；execute、确认批准入口与领域 service 均重新校验。非法参数的错误审计只保存参数哈希，不保存原始值。
- 领域写工具和 `fetch_market_data` 通过 PostgreSQL 数据库级 advisory lock 互斥业务写入；锁被其他对话持有时本次操作快速失败且零写入。确认批准同时锁定提案行和目标业务行，目标状态指纹变化时保留 pending 并要求重新查询、重提。
- 外部 CLI 桥约束见 6.4；当前按 E24 暂缓，生产不探测、不调用、不写委派审计。
- 图片附件与数据卷含个人信息，`uploads/`、`datavolume/` 均 gitignored；数据卷只在自有介质间拷贝，系统不提供网络传输入口。
- AI 不产出买卖建议；对话内容不入策略事实源；当前策略以 `strategy_*` 为准，计划与其他任务产物以 `job_run_output` 为准。
- 计划已归 `job_run_output`，当前策略已归 `strategy_*`；冻结的 `content_*` 只保留兼容读取与迁移审计，不恢复旧表写入。
- 策略批准接口不注册为 Agent 工具，也不向调度器暴露；请求必须是已认证真实用户，YOLO 分支没有调用路径。

## 十一、验收标准（二期总体验收，M 级验收在技术设计中细化）

1. 当前策略、短线/长线池、行情、持仓与归因、回测最终结论、任务和 Agent 记忆在页面可查，事实可追溯到数据库记录、版本或运行输入摘要；生产读取不依赖仓库外文件。
2. **行情唯一数据源**：全库对账后，页面/API/AI 工具的 K 线数据全部来自 `market_bar`；任一标的抽 20 个交易日与迁移前 CSV 原始行比对一致。
3. **服务端原生获取**：断开 `支撑/backtest/env` 与 `支撑/scripts` 后，datasource 作业仍能独立完成每日行情拉取落库；扶摇通道记录限流退避行为，扶摇不可用时按规范降级 AKShare 通道并留痕。
4. **CSV 停用**：对账通过后系统中无任何消费方读取 `支撑/data/` CSV。
5. **数据卷迁移演练**：在干净环境（新数据库实例）用 datavolume 快照恢复，manifest 校验与库内计数一致，页面直接可用。
6. **页面边界**：业务事实页面只读；标的入池、成交/资金、作业定义/提示词和记忆写入只能经 Agent。页面保留任务启停/立即运行/失败处理、策略真人发布、模型设置与备份治理。
7. 对话中上传图片并得到基于图片内容的回答；工具调用卡片完整展示；确认制下未经确认不入库，YOLO 下直接写入且页面明确警示。
8. 口述一笔成交时，Agent 必须复述代码、方向、数量、价格、日期与归因；确认后事件流、持仓、资金台账、策略快照、来源会话和审计在同一事务一致更新。
9. Agent 调整策略只能生成待发布提案；页面默认显示摘要并可展开统一 diff。真实用户批准后多文档原子生效，YOLO、Agent 和调度器均不能批准。
10. 调度器在测试 cron 下自动触发 datasource 与 agent_flow 作业；每个 Agent 运行在模型调用前已有独立 session，中途打开和断线重连可补齐过程，失败有日志，停机缺口记为 `missed`。
11. 回测详情可看到目的、策略状态哈希、输入摘要、工作器/SDK 版本、参数、指标、最终结论、适用边界和缺口；工作运行默认不可见，数据库、聊天、审计和备份不存在代码正文。
12. 收益曲线：历史 13 个离散点原样呈现，上线后每日新增点；命名与口径不违反 D1b。
13. 持仓、账户、持仓流水和标的池只从对应结构化表读取，内容库查询不返回这些领域的旧文档副本。
14. 数据库原生永久测试保持通过；已退役的纯前端 MVP 测试不再保留；`git status` 无密钥、上传或完整私有备份。
15. `database_schema` 可返回轻量索引并按 hash 描述相关表；`database_query` 必须携带逐表 `schema_hash`，Schema 变化时零查询并要求重新发现；不接受原始 SQL，密钥列不可见。
16. 一次 `fetch_market_data` 可处理至少 60 个混合标的请求并返回聚合进度；历史连续同名工具调用在 UI 默认只占一张摘要卡，确认卡不被折叠。
17. 领域写工具均经正式领域 service：确认制未确认零写入，YOLO 无确认直接事务执行；直接绕过 pi loop 调用 execute、批准伪造 payload 均会被再次拦截，两个会话争用写锁时至多一个写入，状态已变化的提案不得覆盖新值；旧 `database_change` 提案明确拒绝。
18. 当前策略页默认只显示最终正文和简要演进记录，没有历史全文选择器、回滚和长期 diff；内部技术修订仍可拒绝过期基线并支持故障恢复。
19. `job_write` 可维护提示词和受控作业，`trigger_job` 只执行既有定义；页面仅能通过控制接口启停既有作业并立即运行/重试，每次 `job_run` 固化实际提示词版本，运行历史不可改写。
20. 板块温度、关键位、长线估值和回测均由服务读数据库执行；源码扫描与干净目录验收证明无 `支撑/scripts`、CSV、`REPO_ROOT` 或 Python spawn 生产依赖。
21. 可移植固定资产包只含当前策略/简要演进和定时任务定义/提示词，不含 API Key、聊天/附件、确认/审计、持仓/账户/流水、标的池、行情或任务运行/结果；在空库恢复后逐表计数、策略/提示词哈希和整体校验一致。完整私有备份继续只用于自有介质灾备。
22. 旧纯前端 MVP 源码、专属测试、npm scripts、`vite-plugin-singlefile` 和一期 `/legacy/` 已删除；Vue 工作台是唯一前端入口。
23. 对话输入“总资产 151064.17、清仓收益 -27221.09、可用资金 38190.17”时，`portfolio_write.upsert_account_snapshot` 可生成待确认提案，service 推导证券市值 112874.00；批准后同日快照可查询且来源、审计和冲突保护完整。
24. 系统提示词按任务路由选择内容当前版本和结构化表，目标日计划不得覆盖策略正文；迁移证据不作为业务事实，实时资金摘要来自 `portfolio_account_state`，离散人工/券商记录来自 `portfolio_account_snapshot`。
25. 仪表盘在 1280px 桌面视口下无横向滚动或卡片内容溢出；失败/部分失败/错过任务、持仓行情缺口、资金锚点早于行情截止等状态集中进入待处理区。实时总资产/现金明确来自 `portfolio_account_state` 并显示锚点日期，持仓市值/浮动盈亏明确使用行情截止日，历史趋势只使用 `portfolio_account_snapshot` 离散记录，浅色与深色下均可读。
26. 两个会话可分别选择不同可用模型，刷新后选择保持且发送时使用各自模型；有待发送图片时不能切换到纯文本模型。输入框聚焦时只有一层强调描边，流式回答以平滑打字效果呈现。
27. 任一普通接口、SSE 建流/中断或附件上传失败都会出现全局 error message，显示友好标题、服务端错误信息与错误码；连续相同错误不刷屏。创建、保存、切换、触发、导出等成功操作显示 success，本地校验显示 warning；原位错误与重试仍可用，浅色/深色及窄屏下均可读。
28. 任务自动重试在同一 session 内形成新的 attempt 分段；任务 session 与普通对话出现在同一会话列表并带来源/状态标签，完成后可直接在原会话追问。运行中可按当前 `run_id` 中断、steering 或排队追问；过期 `run_id` 必须拒绝，归档 session 不删除领域结果。
29. 左侧导航和右侧 Agent 可独立展开收起并恢复最近布局；Agent 收起时事件流、任务和输入草稿不丢失；小于约 1100px 时使用页签或上下布局而非悬浮抽屉。
30. Agent 调用 `ui_refresh` 后，目标模块重新请求数据库并显示最新数据；同一事件幂等、同模块请求合并，未提交编辑和用户锁定记录不被覆盖或强制切换。
31. 四阶段分别有独立开关与出口证据；第一、二阶段不迁移业务事实，第三阶段不与第四阶段合并发布，第四阶段关闭时前三阶段仍完整可用。
32. 长会话超过压缩阈值后，模型上下文切换为摘要与近期原文；压缩检查点、边界和估算量可审计，工具调用/结果配对完整，`chat_message` 原始行数与内容不因压缩减少。真实停止后服务端 Agent 进入 cancelled，任务取消不自动重试，已经提交的数据库事务不回滚。
33. 同步资金快照后建立 `portfolio_account_state` 锚点；锚点后买入扣减现金、卖出回补现金，现金不足时成交/事件/台账整体回滚，完全清仓累加清仓收益，部分卖出不提前计入；更晚快照重锚，更早快照不倒退当前台账。
34. 同一轮包含多段 assistant 文本和多次工具调用时，页面只显示一张 Agent 执行轨迹卡；思考进展、工具调用和最终回答有明确视觉区分，历史恢复与实时流一致，确认卡与工具错误状态保持可操作、可追溯。
35. 一级导航不出现独立自选；行情与市场结构为两个只读入口。行情只展示日线区间对比和日线 K 线，市场结构以 Tab 区分涨跌停、连板和龙虎榜；池、板块和持仓仍可下钻同一行情详情。
36. 行情页不提供趋势线；`watchlist_*` 当前表、`chart_annotation`、自选服务/工具/前端与服务端画线 API 均已退役，历史迁移文件不改写。
37. 计划外或执行偏离成交缺少原因时零写入；持仓时间线可追溯策略哈希、计划结果和来源会话，当前持仓只显示事件归因构成。
38. 同一研究会话默认只展示一个 `final` 回测；再次确认时旧记录变为 `superseded`，策略发布拒绝引用 `working` 回测。
39. `memory_write` 拒绝密钥、临时代码、当前持仓和策略正文副本；`memory_query` 默认只返回有效记忆，页面可以查看来源、证据与最后验证时间。
40. 新会话注册 `web_search` 而不注册 `web_fetch`；搜索只通过已启用的 DeepSeek 官方配置访问固定服务端端点，返回来源域名、URL、发布时间或缺失标记、抓取时间和受限摘要。非白名单来源被丢弃，查询原文不进入成功审计，网页内容不能自动写入业务表或覆盖库内事实。

## 十二、风险

| 风险 | 影响 | 处理原则 |
|------|------|----------|
| 服务端直连接口漂移 | 扶摇/新浪/东财接口字段变化导致拉取失败 | 通道层薄封装、响应校验严格（非法即失败不猜测）；失败记录缺口并在现有 TypeScript 通道间显式降级，不恢复外部 Python 链路 |
| 扶摇限流影响每日更新 | 数据延迟 | 遵守串行 ≥3 秒与退避；失败任务标 partial 并在页面提示，不静默跳过 |
| 行情迁移期 CSV 与库不一致 | 读数来源混乱 | E9/E11 切换以全量对账为门槛；对账通过前页面标注双源状态，通过后 CSV 只作冷备份 |
| 数据卷恢复未演练 | 换机时才发现不可用 | M1 出口标准含迁移演练；每日快照滚动保留，导入强制校验 |
| 重复事实重新进入内容库 | Agent 或人工把结构化事实复制成 Markdown | 系统提示词、工具描述和内容范围同时声明领域边界；迁移副本由 0014 删除，迁移证据不向 Agent 暴露 |
| LLM API Key 管理 | 数据库或数据卷泄露导致凭据外泄 | 仅 PostgreSQL 保存；所有查询只报配置状态；响应、错误、日志和构建产物做泄漏检查；数据卷按敏感介质管理 |
| 通用数据库工具越权或误批量 | 敏感信息泄露、误改多行 | 不开放原始 SQL；服务端二次严格校验、敏感列隐藏、系统表只读、单批上限；确认制先预览，YOLO 明示风险，事务失败整批回滚 |
| 多会话同时写库或批准旧提案 | 重复执行、丢失更新、旧值覆盖新值 | 数据库级 Agent 写锁、提案行锁、目标状态指纹；忙锁/状态冲突均零写入且不自动盲重试 |
| agent_flow 作业产出质量不稳 | 每日预期内容不可靠 | agent 产出标注"AI 生成，未经确认"；不自动写入 `交易计划/` 事实目录，确认后才可导出 |
| 外部 CLI 写文件越界（M4） | 事实源被意外修改 | M4 实施前单独设计授权边界；当前生产没有 CLI 桥或文件同步器 |
| pi 内核 API 变化 | 集成返工 | 锁定依赖版本；agent 接入层薄封装，内核可替换 |
| 调度依赖 server 常驻 | 关机漏跑 | 启动补记 `missed`；不伪装已执行 |
| 分阶段兼容层长期存在 | 新旧 session、抽屉或内容 API 同时维护造成行为漂移 | 每阶段记录调用量与退役清单；旧写入口先关闭，兼容读取在零流量后才删除 |
| 临时代码回测越界或泄漏 | Agent 生成代码访问网络/文件，或补丁进入聊天与审计 | 独立进程/容器、白名单 SDK、无数据库凭据、资源上限、专用脱敏持久化和启动清理器；安全验收前工具默认关闭 |
| 页面只读后 Agent 暂不可用 | 用户无法立即登记业务事实 | 原始文字/图片只保留在当前对话草稿，不预写业务表；模型恢复后继续结构化、复述和确认 |
| 记忆污染业务事实 | 过期经验覆盖当前策略、持仓或行情 | 记忆与业务表分域、默认只取有效项、显示验证时间；冲突时始终以当前 PostgreSQL 领域事实为准 |
| 回测工作运行污染历史 | 大量试验被误当正式证据 | 默认历史查询只返回 `final`；显式晋升并记录适用边界，同会话重新确认时保留替代链 |
