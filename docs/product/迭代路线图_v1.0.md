## 一、排序原则

1. **可信数据先于丰富功能**：先保证截止时间、来源、缺失和冲突可见，再增加历史、通知或更多数据源。
2. **先闭合高频任务**：成交录入和每日计划每天影响事实源，优先于低频绩效归因和全市场研究。
3. **先在现有事实源上验证**：MVP 和 v0.2 继续使用 Markdown/CSV，避免产品价值未验证就承担迁移风险。
4. **写入必须晚于预览和审计能力**：任何正式写入都先具备冲突检测、事务恢复和人工确认。
5. **外部暴露必须晚于隐私治理**：局域网、云端、券商和付费数据需在鉴权、授权、备份和许可边界明确后再立项。

| 版本 | 产品定位 | 核心收益 | 主要成本 | 主要风险 | 状态 |

## 三、MVP v0.1：单机盘后纪律工作台

### 3.1 范围与非目标

**公共范围**：数据健康、组合与风险总览、持仓详情、只读执行位计算、成交录入和纠错、每日计划触发/草稿/确认及按 D2 发布或导出、单只股票点时分析、写入审计。

**D2 条件范围**：选择 D2-B 时，标的池研究状态变更升为 MVP P0，并按 D4 采用独立确认/事务或组合确认/事务；选择 D2-A/D2-C 时不进入 MVP，保留为 v0.2 候选。真实用户未确认前默认关闭该写入，但不视为已经选择“不进入 MVP”。

**非目标**：手机真实访问、盘中实时、主动推送、券商导入、自动下单、付费行情、云端上传、结构化迁移、自动新增标的、自动投资建议、复杂绩效归因。

### 3.2 主要用户流程

1. 打开总览确认交易日和数据健康，处理风险并核对执行位；
2. 有真实成交时录入，查看资金/持仓/约束影响，确认后受控写入；
3. 收盘后触发每日计划，核对输入和缺失，人工确认后按 D2 发布或导出；
4. 输入一只股票，查看事实、V26 条件、研究评分、组合影响和例外；选择“仅研究/角色未知”时，V26 与研究评分显示“不适用/待确定角色”，不跨策略试算。

### 3.3 事实源与写入边界

- Markdown/CSV 和正式引擎继续是唯一事实源；产品缓存和草稿可重建。
- 执行位只计算和展示，不回写。
- 成交获得 D1-A 授权后，确认只更新真实持仓/资金并追加不可变流水；更正以新事务补偿当前账面并追加事件，不改原成交。
- 计划获得 D2-A/D2-B 授权后才可发布/归档；仅 D2-B 允许按 D4 确认和事务口径更新标的池研究状态。
- 策略、正式量化配置和历史事实禁止改写。
- 成交、计划、标的池和备份能力必须先经真实用户相应决策，否则按 PRD 第 3.2 节的最小权限行为降级。

### 3.4 异常、隐私与审计

- 覆盖加载、空持仓、延迟、缺失、部分可用、来源冲突、限流、停牌、写入冲突和部分失败恢复。每日计划只使用“生成中、部分成功/缺数据、失败、待确认、已拒绝、重算中、已发布、已过期/被替代”八个状态；只有目标日有效且未被替代的最新已发布版本可作为最新正式计划。
- 仅本机回环访问；无云端行为数据和持仓上传；Token 不进入页面或日志。
- 每次正式写入记录事务编号、输入版本、前后值、确认和恢复结果；确认后纠错只追加并关联原事务。更正同时补偿数量、成本、现金、当前持仓和当月流水，失败恢复到更正确认前的一致状态。

### 3.5 验收与成功指标

- 全量验收以 `Stock_MVP_PRD_v0.1.md` 第十二章为准；其中 1A/2A/3A、计划状态机、成交校验分级、更正一致性恢复、未知角色不套策略和证据类型分离属于阻断项。
- 首轮成功指标：盘后只读核验中位数不超过 3 分钟；核心数据截止时间覆盖率、风险证据可追溯率均为 100%；无确认写入和半完成事实均为 0；成交成功率至少 95%；计划任务完成率至少 90%。

### 3.6 进入条件与退出门槛

进入开发前，项目经理、用户代表和真实用户完成 PRD 门禁，真实用户明确回复 D1-D6 六项选择。退出 MVP 阶段要求功能验收通过，并至少完成一次成交事务恢复演练、一次更正事务恢复演练、一次计划发布冲突演练、一次同日计划替代/过期演练和六类数据异常演练。

## 四、v0.2：本地可持续复盘

### 4.1 范围与优先级

| 优先级 | 能力 | 用户收益 | 依赖 |
|--------|------|----------|------|
| P0 | 历史组合、风险事件与任务时间线 | 复盘变化，不再翻月度文件 | MVP 事实源适配和口径版本 |
| P0 | 标的池入池、角色变更，以及 D2-A/D2-C 下后置的研究状态审批 | 将分析结果安全转成后续关注 | 单股分析、人工确认和角色唯一性；D2-B 时研究状态部分已在 MVP，v0.2 不重复建设 |
| P0 | 本地盘后完成/失败通知 | 用户无需持续盯任务页 | 稳定任务状态机 |
| P1 | 组合、策略层、行业、标的联动筛选 | 提高高密度信息扫描效率 | 历史索引和分类字段 |
| P1 | Markdown/CSV/JSON 导出 | 保留可读快照和外部复核能力 | 脱敏规则和导出版本 |
| P1 | 规则与口径变更对比 | 解释旧结果和新结果不可比原因 | 规则版本、板块口径清单 |

### 4.2 非目标

仍不覆盖公网/局域网访问、盘中实时、券商账户、自动下单、付费数据、自动荐股和结构化事实源切换。通知只报告盘后任务和既有规则风险，不发送刺激交易的涨跌排行榜。

### 4.3 用户流程

1. 用户从总览进入历史时间线，按策略层、行业、标的、事件类型和口径版本筛选；
2. 用户从单股分析发起“申请入池/变更角色”，并在 D2-A/D2-C 下处理后置的研究状态变更；查看影响后确认，系统写入对应标的池并保留审批记录；
3. 每日计划任务完成、部分失败或需要确认时发送本地通知，点击进入对应任务；
4. 用户选择时间范围导出带来源、截止时间和口径版本的复盘资料。

### 4.4 事实源与写入边界

- Markdown/CSV 继续是事实源；历史索引仅为可重建读取层，索引冲突时以原文件为准并重建。
- 入池和角色变更必须同时校验两个标的池、当前持仓和待发布计划；单标的只能有一个当前角色。
- 已确认的入池/角色/研究状态变更只更新当前状态并追加审计，不反向修改旧计划和旧分析；D2-B 已在 MVP 交付的研究状态写入只在 v0.2 扩展历史和筛选，不重建第二套审批。
- 导出是只读副本，不得再导入覆盖事实源；双向同步不在本版本范围。

### 4.5 异常状态

- 完整继承 MVP 的加载、空数据、延迟、缺失、部分可用、来源冲突、权限/额度和系统错误状态；新增能力不能用自己的成功状态覆盖底层数据异常；
- 历史文件缺月、口径不一致或解析失败时按时间段标“部分可用”，不补造净值曲线；
- 索引版本落后时显示“正在重建”，原始文件仍可查看；
- 标的池/持仓角色冲突时阻止审批，列出受影响文件和当前角色；
- 本地通知权限关闭时仅降级为站内状态，不阻断任务；
- 导出中存在缺失或估算字段时在清单和文件内同时标记。

### 4.6 隐私与审计

- 延续单机本地边界；通知正文默认不显示持仓金额和具体交易动作，避免锁屏泄露。
- 记录筛选/查看行为不是必需项，不采集；只审计入池、角色变更、导出和通知投递结果。
- 导出前显示包含的敏感数据和保存位置；默认不写入云同步目录。

### 4.7 验收标准

1. 对至少跨两个月且包含 13/15 板块口径切换的夹具，时间线不静默连线，能查看每段口径；
2. 模拟缺少一个月流水时，其余月份仍可查看，累计结果明确标“部分数据”；
3. 入池或角色变更发生源文件冲突时不写入；成功时两个标的池、当前持仓引用和审计一致；
4. 通知权限关闭、任务部分失败和任务成功三种情况均进入正确状态，关闭权限不重复弹错；
5. 导出文件包含来源、截止时间、规则版本、缺失和估算标记，且不包含 Token；
6. 任一历史事件可返回原始事实和当时规则版本，不用新规则重写旧结论。

### 4.8 成功指标

- 80% 的历史复盘会话可在一次筛选内定位目标事件；
- 100% 的角色变更有人工确认和审计，角色冲突写入为 0；
- 本地通知点击可到达正确任务的比例 ≥99%；
- 索引和事实源抽样一致率 100%；
- 因口径不明导致的用户复核返工次数较 MVP 下降，目标值在 MVP 观察后确定。

## 五、v1.0：可选服务化与数据升级

v1.0 不是一个已经承诺的固定功能包，而是四条互相独立的候选能力。每条都必须由真实用户单独选择、立项和验收；未选择的能力保持关闭。

### 5.1 候选范围与决策

| 候选 | 选项 | 收益 | 成本与风险 | 建议 |
|------|------|------|------------|------|
| 多端访问 | A 继续单机；B 局域网；C 私有云 | 手机/远程便利 | 鉴权、网络暴露、运维、持仓隐私 | 先验证 MVP 使用频率，再在 B/C 中立项 |
| 盘中数据 | A 仅盘后；B 现有源轮询；C 合规实时源 | 提高盘中风险时效 | 额度、持续费用、许可、SLA、诱导交易 | 默认 A；真实需求和付费意愿明确后再评估 |
| 事实源 | A 继续 Markdown/CSV；B 结构化库为主并生成快照；C 双写 | 提高查询、事务和扩展性 | 迁移、冲突、回滚、长期维护 | 倾向 B 而非长期双写，但须先迁移演练 |
| 成交获取 | A 手工录入；B 券商文件导入；C 券商接口 | 降低录入成本 | 对账、授权、格式变化、凭据安全 | 先做 B；C 需合规和安全专项 |

自动下单和自动生成新投资建议不因上述任何选择而自动进入 v1.0，必须另立需求并获得明确授权。

### 5.2 非目标

- 不默认成为公共 SaaS，不做多租户、社区、广告或资讯推荐；
- 不承诺全市场毫秒级行情；
- 不把券商导入等同于券商下单；
- 不以迁移为由删除 Markdown 可读快照或历史审计；
- 不以盘中数据改变日线 V26 的收盘确认规则。

### 5.3 用户流程

1. 用户在设置中查看已授权能力、数据费用、部署位置和最近同步状态；
2. 多端方案启用后，用户通过明确身份验证访问，敏感操作再次确认；
3. 盘中数据启用后，页面同时显示盘中时间和最近完整交易日，盘中事实不得生成日线收盘信号；
4. 券商导入先进入对账预览，用户确认后复用成交事务流程；
5. 事实源迁移先运行只读影子校验，差异清零并通过回滚演练后才切换主源。

### 5.4 事实源与写入边界

- 未通过结构化迁移验收时，Markdown/CSV 仍为主事实源；影子库无权覆盖。
- 迁移方案必须定义逐字段主源、冲突优先级、事务边界、历史不可变约束和快照生成方式。
- 不允许无限期双写而无一致性指标、修复责任和退出日期。
- 盘中缓存、券商导入原文件和云端副本必须有保留周期、加密和删除规则；不得改变策略事实源。

### 5.5 异常状态

- 完整继承 MVP 和 v0.2 的加载、空数据、延迟、缺失、部分可用与冲突状态，并按数据源、设备和迁移批次展示影响范围；
- 多端离线、会话过期、权限不足、设备时间偏差和并发编辑冲突；
- 实时源断流、许可过期、行情延迟和盘中/收盘字段混用；
- 券商文件重复导入、字段不兼容、成交缺失和对账差异；
- 迁移影子差异、双写积压、回滚失败和快照生成失败。

任一异常只影响对应能力；不能用旧盘中值冒充实时，也不能在迁移不一致时继续正式写入。

### 5.6 隐私与审计

- 局域网或云端必须有身份验证、最小权限、传输加密、会话失效、敏感日志脱敏和安全更新策略；
- 云端部署必须明确数据位置、备份、删除、访问者和事件响应，用户可导出并删除自己的数据；
- 券商凭据禁止进入仓库；导入和同步记录来源文件哈希、账户脱敏标识和对账结果；
- 迁移记录每批次校验、差异、批准者、切换和回滚结果。

### 5.7 验收标准

1. 多端方案在未认证、会话过期和网络暴露扫描下均不能读取持仓；敏感写入需要再次确认；
2. 实时源延迟超过约定阈值时自动降级并显示延迟，不生成日线收盘信号；
3. 同一券商文件重复导入不重复记账，差异未确认时不更新持仓；
4. 结构化迁移对全部当前持仓、历史成交、计划和规则引用逐字段校验一致；随机回滚后 Markdown/CSV 可继续独立使用；
5. 双写方案若被选择，故障注入后能检测差异、停止写入、恢复一致，并有明确退出方案；
6. 未授权的付费源、云端、券商连接、自动下单和投资建议能力保持关闭。

### 5.8 成功指标

每条候选能力单独设指标，不用交易收益衡量：

- 多端：认证成功率、敏感数据未授权访问 0、远程任务完成率；
- 盘中：数据时延达标率、旧值冒充实时 0、盘中事实误生成收盘信号 0；
- 券商导入：自动匹配率、重复入账 0、对账差异发现率 100%；
- 迁移：逐字段一致率 100%、回滚恢复目标达成、未解决双写差异 0。

目标数值须在供应商 SLA、样本规模和部署选择确认后补充，本文不虚构。

## 六、依赖顺序与阶段门禁

```text
PRD 完整性评审
  -> 用户代表复审与真实用户写入授权
  -> MVP 交互/数据/事务/测试设计
  -> MVP 开发与独立测试
  -> 用户代表最终验收
  -> MVP 使用观察
  -> v0.2 单独立项与验收
  -> v1.0 候选逐项决策，不打包默认启用
```

### 6.1 MVP 不能提前依赖后续版本

- 不以未来数据库为由跳过 Markdown 冲突检测；
- 不以未来云端为由在 MVP 保存云凭据；
- 不以未来实时行情为由将盘后页面标“实时”；
- 不以未来券商导入为由弱化手工成交审计；
- 不以未来 AI 能力为由把 MVP 计划草稿包装成自动建议。

### 6.2 版本复盘触发条件

每个版本只在以下条件同时满足后进入下一阶段：阻断验收全过、无未恢复写入事故、数据新鲜度可识别率 100%、用户确认核心流程产生持续价值、下一阶段授权事项已明确。单纯因为功能已经排入路线图不能触发开发。
