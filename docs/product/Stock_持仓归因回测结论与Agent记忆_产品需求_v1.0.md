## 一、产品结论

本阶段建立“交易事实—策略归因—验证结论—可复用经验”的闭环：归因记录在每次持仓事件上，回测历史只展示一次研究过程最终确认的结论，Agent 记忆只保存历史执行过程中有长期复用价值的产物。

三类数据必须分开：

- 持仓和成交是不可改写的业务事实；
- 回测结论是对一次验证过程的最终研究产物；
- Agent 记忆是可复用的方法、模板、数据经验或故障处理，不是价格、持仓或策略事实的副本。

## 二、成交级持仓归因

### 2.1 为什么不用持仓布尔值

同一持仓可能由策略建仓、计划内加仓、做 T、临时调整和计划外操作共同形成。把“是否根据策略录入”放在当前持仓上会覆盖历史、无法解释部分卖出，也会造成胜率统计偏差。因此归因必须绑定每次 `portfolio_position_change`。

### 2.2 归因字段

| 字段 | 取值/含义 |
|------|-----------|
| 决策来源 | 策略信号、计划内主观、计划外例外、仅事实校正、未知 |
| 执行符合度 | 符合、偏离、不适用、未知 |
| 策略状态 | 发生事件时的策略整体哈希和变更序号 |
| 关联计划 | 可选的 `job_run_output` |
| 关联 Agent 会话 | 产生提案的会话 |
| 偏离原因 | 偏离或计划外操作时必填 |
| 归因说明 | Agent 基于用户原话形成的简要说明 |

买入、卖出和调整必须提供决策来源；旧迁移记录使用“未知”，不得用当前策略反推历史。备注事件可以使用“不适用”。

### 2.3 展示与统计

- 持仓页在事件时间线展示归因徽标、关联策略/计划和偏离原因；
- 当前持仓只展示由事件流聚合出的归因构成，不保存单一“策略持仓”布尔值；
- 胜率统计按完成的交易批次计算，未闭环持仓不计胜负；
- 计划内、计划外和未知样本分开统计，不允许混为策略胜率；
- 样本数、时间范围、费用口径和未归因数量必须随结果展示。

## 三、回测最终结论

### 3.1 两层记录

| 层级 | 用途 | 页面可见性 |
|------|------|------------|
| 工作运行 | Agent 在同一研究会话中的试验、失败和中间验证 | 默认隐藏，仅用于当前会话继续研究和技术审计 |
| 最终结论 | Agent 比较证据后明确选定的一次最终结果 | 进入回测历史和策略演进引用 |

临时代码继续在每次运行结束后删除。数据库只保留代码哈希、输入摘要、指标、结论、缺口和终态。

### 3.2 最终结论晋升

1. 每次 `run_backtest` 产生工作运行并关联当前 Agent 会话。
2. Agent 可以在同一会话继续修改、反证或比较，不自动进入历史结论。
3. Agent 认为证据完整时调用“确认回测结论”领域动作，指定最终运行、结论摘要和适用边界。
4. 同一研究会话只能有一个当前最终结论；重新确认时旧结论标记为已替代。
5. 策略发布提案只能关联已确认的最终回测结论。
6. 回测页面默认只列最终结论，失败和工作运行不污染历史列表。

## 四、Agent可复用记忆

### 4.1 定位

Agent 记忆用于保存历史执行中已经验证、以后可能复用的产物，而不是自动记录所有对话。允许的首期类型：

- 研究方法与分析步骤；
- 可复用的评估模板或检查清单；
- 数据源特性、字段口径和稳定降级经验；
- 已验证的任务编排方法；
- 故障原因与恢复步骤；
- 用户明确确认的长期工作偏好。

禁止保存：当前价格、当前持仓、策略正文副本、API Key、完整工具结果、临时代码、未经验证的推测和一次性对话闲聊。

### 4.2 记忆对象

每条记忆包含：标题、类型、摘要、正文、标签、适用范围、来源会话、来源运行或工具、证据说明、创建时间、最后验证时间、状态和替代关系。

状态为：

- 有效：当前可复用；
- 待复核：环境或依赖变化后需要验证；
- 已替代：有更新产物；
- 已废弃：不再使用但保留最小审计。

### 4.3 写入与读取

- Agent 只有在本轮产生明确可复用产物时才调用记忆写工具；
- 默认确认制下由用户确认，YOLO 下可自动写入但仍记录来源和审计；
- 重复主题优先更新或替代，不创建大量同义记忆；
- 每轮只注入轻量记忆索引，Agent 按任务检索相关正文；
- 记忆与业务事实冲突时，始终以 PostgreSQL 领域事实和当前策略为准；
- 用户要求纠正或删除记忆时仍通过 Agent 领域工具执行。

## 五、工具与页面

### 5.1 新增领域工具

- `memory_query`：按类型、标签和关键词检索有效记忆；
- `memory_write`：创建、更新、替代或废弃记忆；
- `finalize_backtest`：把同一会话中的一个工作运行晋升为最终结论；
- `portfolio_write`：扩展成交级归因字段和校验。

### 5.2 页面

- 持仓页继续只读展示当前持仓、资金和带归因的事件流；
- 回测页默认只展示最终结论，可从详情打开来源会话；
- Agent 记忆提供只读列表和详情，支持按类型、标签、状态和最后验证时间筛选；
- 所有修改、替代和废弃操作通过 Agent 发起。

## 六、验收标准

1. 新增买入、卖出或调整事件缺少决策来源时零写入并返回明确错误。
2. 计划外例外或执行偏离缺少原因时零写入。
3. 旧事件统一为“未知”，迁移不反推历史归因。
4. 持仓事件流能追溯策略哈希、计划结果和来源会话；当前持仓展示归因构成而不是单一布尔值。
5. 回测工作运行不进入默认历史；同一研究会话最多一个当前最终结论。
6. 策略发布提案拒绝关联未晋升的工作回测。
7. 记忆工具拒绝保存密钥、临时代码、当前持仓或策略正文副本。
8. 相同主题可替代旧记忆，Agent 默认只读取有效版本。
9. Agent 回答引用记忆时同时给出来源和最后验证时间；记忆不能覆盖当前业务事实。

## 七、数据保留原则

- 成交事实、归因和确认审计长期保留；
- 最终回测结论长期保留；
- 工作回测只保留现有最小运行摘要，不在用户历史中展示；
- 临时代码、补丁和工作区路径任何情况下都不持久化；
- 已替代或废弃记忆保留最小审计，不进入 Agent 默认检索结果；
- 不为本阶段保留一次性测试文件或已退役页面代码。
