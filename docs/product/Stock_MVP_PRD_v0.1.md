## 一、背景与用户问题

目标用户是有一定交易经验、时间有限、重视数据可信度的 A 股个人投资者。当前盘后工作分散在持仓、策略、标的池、行情 CSV、交易计划和历史流水中，用户需要人工完成数据核对、执行位重算、组合约束检查和次日计划整理，且历史上发生过 T-1 滞后、板块指数错配和口径变更问题。

MVP 服务四个连续任务：

1. 确认数据是否已经更新到目标交易日；
2. 看清收盘后定盘盈亏、活动风险和当前执行位；
3. 录入真实成交，或生成并人工确认下一交易日计划；
4. 对单只股票发起有证据、有截止时间、区分量化与人工判断的分析。

MVP 不承诺盘中实时，不把概率情景表述成预测事实，也不把实盘例外包装成 V26 结论。

## 二、产品目标与非目标

### 2.1 目标

- 用户在 3 分钟内完成盘后只读核验：确认新鲜度、组合变化、风险触发、市场状态和明日计划状态；3 分钟不包含数据拉取、成交录入或计划生成耗时。
- 用户可在前端完成成交录入、影响预览、校验和人工确认，减少直接编辑多份 Markdown 的错误风险。
- 用户可触发每日计划任务，看到输入快照、生成进度、缺失数据和待确认结果；未经确认的结果不成为正式计划。
- 用户可输入一只股票并获得点时分析，明确区分行情事实、V26 量化结果、研究评分、计划情景、人工判断和实盘例外。
- 每个结论均可追溯到数据来源、数据截止时间、计算时间和规则版本；任何缺失、延迟、冲突或例外都不可被正常样式掩盖。

### 2.2 非目标

- 不提供盘中异动、实时盈亏、实时风险告警或盘中交易决策。
- 不自动下单，不接券商账户，不提供融资或负现金能力。
- 不启用付费行情，不将持仓或计划上传云端，不提供手机真实访问；390×844 仅做响应式自检。
- 不自动创建未获用户批准的投资建议，不自动新增标的或改变标的角色，不自动改写策略参数。
- 不将执行位计算结果回写 `当前持仓.md`；页面关闭后可按同一输入重算。
- 不在 MVP 迁移 Markdown/CSV 事实源，不引入双写数据库，不改写历史交易事实。
- 不做资讯流、社区、全市场行情终端、券商导入、税务、复杂绩效归因或自动化投资组合管理。

## 三、已确认边界与待复审边界

### 3.1 已确认

| 决策 | MVP 口径 | 产品影响 |
|------|----------|----------|
| 终端 | 电脑单机本地 | 无远程访问；手机只做布局自检，不承诺可用 |
| 行情 | 每个交易日收盘后定盘 | 所有盈亏统一称“收盘后定盘盈亏”，必须显示交易日 |
| 执行位 | 自动计算、只读展示 | 计算结果不写入仓库；缺输入显示“实盘例外/无法重算” |

### 3.2 必须由真实用户复审

以下内容是实现前门槛，不因本文进入评审而视为已授权。第 16.2 节给出互斥选项、默认行为和产品建议，真实用户可按第 16.3 节的组合直接回复：

1. 成交确认后是否受控写入 `当前持仓.md` 并追加当月不可变流水；
2. 计划确认后是否发布/归档，以及标的池研究状态写入是否进入 MVP；
3. 成本采用券商成交后成本、费用估算还是“待核实”口径；
4. 每日计划采用整份确认还是逐条接受/拒绝，标的池状态是否始终单独确认；
5. 是否允许分析池外标的并使用现有免费/已授权源生成本地行情文件；
6. 本地备份位置、保留周期和恢复入口采用哪种体验。

未决前执行最小权限默认：成交和计划只能校验、预览及导出变更清单；标的池不写入；池外标的不拉取；不自动备份；费用未知不记为零；不向云同步目录写入。该默认只用于防止越权，不代表产品建议或真实用户选择。如成交或计划写入未获授权，不得宣称相应前端写入闭环已完成，项目经理必须据此重新评估 MVP 价值和排期。

## 四、证据类型与展示规则

页面必须使用以下互斥标签。一个结论可以引用多类证据，但其自身只能有一个主要性质。

| 类型 | 定义 | 允许的表达 | 禁止的表达 |
|------|------|------------|------------|
| 行情事实 | 已取得的价格、成交量、指标和财务原始字段 | “2026-07-29 收盘 31.99 元” | 用生成时间冒充行情时间 |
| 量化结果 | 按正式版本规则计算的状态、信号或执行位 | “V26 右侧条件 5/6，未形成信号” | 用研究评分替代硬条件 |
| 计划情景 | 对下一交易日的条件化准备 | “基准情景 55%，失效条件为……” | “明日一定上涨” |
| 人工判断 | 无法由正式量化规则直接得出的研究结论 | “人工复核：行业集中风险偏高” | 冒充 V26 回测结论 |
| 实盘例外 | 缺入场依据、角色修正或策略外执行 | “实盘例外，沿用已记录风险位” | 用 V26 指标为例外背书 |

所有金额显示人民币元，价格显示元或元/份，数量显示股或份，涨跌和占比显示百分比。单位必须随字段展示，不能只依赖页面说明。

## 五、MVP 范围与优先级

### 5.1 P0：发布门槛

| 模块 | 范围 | 价值 |
|------|------|------|
| 数据健康 | 交易日、数据源、拉取/计算时间、完整性、异常影响 | 先判断数据是否可用，防止过期值冒充今日 |
| 组合总览 | 总权益、证券市值、现金、当日/累计盈亏、策略层占用 | 回答“今天发生了什么” |
| 风险队列 | 执行位触发、持仓数/模块/行业超限、数据冲突 | 回答“现在是否需要处理” |
| 持仓与详情 | 数量、成本、定盘价、盈亏、执行位、证据和规则引用 | 完成持仓核验与下钻 |
| 执行位计算 | 按角色和规则版本自动计算，只读展示，移动位不下调 | 降低每日手工重算成本 |
| 成交录入 | 增仓、减仓、清仓、做 T；校验、预览、确认、审计、纠错 | 形成至少一个真实前端写入闭环 |
| 每日计划 | 触发、进度、输入快照、缺失状态、草稿、人工确认、按 D2 发布或导出 | 将每日任务从命令式操作变成可核验流程 |
| 单股分析 | 单标的点时分析；证据、V26 条件、研究评分、例外分离 | 覆盖用户临时研究任务 |

标的池研究状态写入不是以上公共 P0 的暗含能力。真实用户选择 D2-B 时，它才作为独立 P0 加入 MVP，确认粒度和事务关系按 D4 选择；选择 D2-A 或 D2-C 时，MVP 不提供该写入，继续留在 v0.2 候选范围。未确认前按“不进入 MVP”关闭，但不能据此替真实用户结案。

### 5.2 后续候选：不属于 MVP v0.1 P0

- 历史风险事件和任务运行时间线；
- 组合、策略层、行业和标的联动筛选；
- 计划完成后的本地系统通知；
- 分析结果导出为 Markdown；
- 新增标的入池和角色变更审批；研究状态变更仅在真实用户未选择 D2-B 时留在此范围。

### 5.3 明确后置

盘中实时、局域网/云端、多设备同步、付费行情、券商导入、自动下单、自动荐股、结构化事实源迁移、复杂绩效归因均后置，详见 `迭代路线图_v1.0.md`。

## 六、信息架构与关键交互

### 6.1 一级导航

1. **总览**：数据健康、组合、风险、持仓、市场与计划摘要；默认首页。
2. **持仓**：持仓表、持仓详情、成交录入入口、成交审计记录。
3. **每日计划**：任务触发、运行状态、草稿核验、确认发布、历史计划入口。
4. **股票分析**：单标的输入、数据截止时间、分层证据和分析历史。
5. **数据与审计**：数据集状态、来源冲突、写入事务、失败与纠错记录。

### 6.2 总览顺序

页面固定先展示“当前使用的交易日、最后成功更新时间、完整性状态”，再展示组合摘要、待处理风险、持仓、市场/板块和计划摘要。风险优先于涨跌排行；延迟或部分数据可用时，异常说明必须位于受影响结论之前。

### 6.3 下钻原则

- 风险事件一次操作进入相关持仓或组合约束详情；
- 任何执行位可查看输入、规则章节、规则版本、计算时间和生效日；
- 市场状态同时展示综合指数、慢均线及周期、20 日斜率和 15 板块口径；
- 每日计划中的动作可回到对应行情事实、量化条件、组合约束和人工判断；
- 股票分析不得把“研究评分高”和“V26 已有信号”合并成一个推荐分数。

## 七、用户流程

### 7.1 盘后核验

1. 用户打开总览；系统先读取本地事实源并展示目标交易日和各数据组状态。
2. 数据完整时计算组合、市场状态、约束和执行位；部分缺失时只计算不受影响的结果。
3. 用户先处理风险队列，再下钻执行位和规则证据。
4. 用户查看最新正式计划；草稿或过期计划必须显式标记，不能作为当前正式计划展示。

### 7.2 增减持仓

MVP 只录入已经在券商侧真实完成的成交，不接受未来订单或代用户执行下单。校验器必须保存真实事实与维护策略纪律，但两者不能混为一件事。

#### 输入

- 成交方向：买入、卖出；业务动作由系统推导为增仓、减仓、清仓或做 T；
- 标的代码和名称、策略角色、成交日期时间、成交价、数量；
- 佣金、印花税、过户费等已知费用；券商成交编号、券商成交后成本和交易后可用现金可选，最终必填条件由 D3 决定；
- 备注和“实盘例外”原因，策略外操作必填。

#### 校验

校验结果只能使用以下三级，不得把策略纪律当作券商事实错误。这里的“入账”仅指在获得 D1 写入授权后的事实源更新：

| 级别 | 含义与产品行为 | 对已发生券商事实的处理 |
|------|----------------|------------------------|
| 硬阻断 | 输入无法唯一识别成交，或写入会产生不可能/不一致账本；禁止确认入账 | 保存为“待核对成交事实”及其原始输入/券商证据，不丢弃、不改写持仓；核对或补录前置事实后重新预览 |
| 风险提示 | 事实可以一致入账，但存在需用户知悉的不确定性或纪律风险；明确展示影响 | 用户确认后可继续；提示和确认进入审计，不得自动标为实盘例外 |
| 实盘例外 | 已发生且可核实的券商事实违反产品内策略、组合或预期交易规则 | 必填券商事实证据、例外原因并二次确认后留档；持续展示违规状态，不得标为合规或 V26 结论 |

逐项口径如下：

| 校验项 | 硬阻断 | 风险提示 | 允许以实盘例外留档 |
|--------|----------|----------|----------------------|
| 基础事实与重复 | 代码/方向/交易日/价格/数量缺失，价格或数量非正，证券身份冲突，同一券商成交编号或同一幂等键重复 | 无券商成交编号时提示重复识别能力下降 | 不允许；需先补齐或去重。原始输入保留为待核对记录 |
| 可卖数量 | 卖出数量超过当前总持有量，或前置流水缺失导致无法形成非负持仓 | 本地可卖数量低于卖出量但总持仓足够时，提示可能涉及 T+1 或本地流水滞后 | 券商成交已核实且总持仓足够时，可按“本地可卖数量不一致”留档；必须同时进入对账风险队列 |
| T+1 | 未来计划/模拟交易违反适用 T+1 规则；已发生事实若会导致总持仓为负仍按可卖数量硬阻断 | 本地买入日期或品种规则不足时显示“无法确认 T+1”，不得假定合规 | 已发生券商卖出可在券商编号/凭证核实后留档，标记本地规则或流水不一致；不得反向伪造可卖数量 |
| 100 股/份交易单位 | 未来买入计划违反该标的已确认交易单位 | 品种交易单位未知，或已发生成交不是预计单位整数倍 | 已发生且有券商证据时可留档并说明原因；不能据此修改通用规则 |
| 零股清仓 | 卖出后为负数，或声称清仓但数量不等于全部剩余数量 | 卖出全部剩余零股时提示“零股清仓”，并展示清仓后为 0 | 符合全部剩余数量时属于正常清仓，无需例外；已发生的非整单位部分卖出需券商证据后按例外留档 |
| 做 T 顺序与数量 | 未来计划/模拟交易不满足所属策略的做 T 前置条件 | 不能从当日流水唯一判断先卖后买、买回数量或收盘数量时显示不确定 | 已发生事实违反先卖后买、买回不超过先卖量或收盘不增仓等纪律时可留档，单列策略外原因 |
| 策略约束 | 未来计划/模拟交易违反交易权限或所属策略硬条件 | 接近阈值、规则输入缺失或角色待核实时提示 | 已发生事实违反交易权限、角色或策略条件时可留档；不得补造信号或改写角色来伪装合规 |
| 组合约束 | 未来计划/模拟交易导致现金不成立或越过组合硬上限 | 单只市值、单笔风险、策略模块、持仓数或行业集中度接近/达到阈值 | 已发生事实导致越限但账本仍一致时可留档并持续进入风险队列；若现金/权益无法自洽则硬阻断并先对账 |

费用未知时显示“费用待核实”，不能默认为零。未来计划或模拟交易的硬约束失败不得使用“实盘例外”绕过；例外通道只接收已经发生且可核实的券商事实。

#### 预览与确认

确认前展示成交前后数量、现金、证券市值、总权益、成本口径、策略层占用、行业集中度、预计费用和受影响风险。用户必须二次确认；预览失效、源文件被修改或输入数据更新后必须重新生成。

#### 写入与纠错

- 仅在真实用户选择 D1-A 后，MVP 才允许修改 `当前持仓.md` 中的真实数量、成本、现金和由成交直接决定的当前事实，并向当月持仓流水追加成交与快照；自动计算的执行位不回写。
- 写入前比较读取时版本/哈希，冲突时停止并展示差异，不覆盖新内容。
- 多文件写入必须具有事务编号、预写日志、完整成功标记和失败恢复；任何部分失败不得留下“当前持仓已变、流水未记”或相反状态。
- 确认前可撤销草稿；确认后不得删除或改写原成交。纠错必须创建新的更正事务并关联原事务，不能在原记录上直接编辑。
- 更正预览必须同时展示原事务及券商证据、错误原因、原值、更正值、差额，以及更正后数量、成本、现金和风险影响；原事务或输入快照已变化时预览失效。
- 更正事务的补偿范围固定覆盖：`当前持仓.md` 中受影响标的的数量、成本、现金及由成交直接决定的当前事实，以及更正发生月份的持仓流水中追加的更正事件和更正后快照。跨月更正通过原事务编号指回原月流水，原月原文不改写。
- 当前持仓补偿、当月更正事件、快照和审计使用同一更正事务编号原子提交。完整成功前不展示新账面；任一写入失败时恢复到更正确认前的一致状态并记录失败。恢复失败时冻结后续事实源写入，直至完成恢复或人工对账。
- 更正成功后，当前持仓必须反映“原事务 + 全部已确认更正”的结果；审计可从当前值追溯到原事务和更正链。更正本身出错时只能再追加新的更正事件。
- 精确清仓收益缺少真实费用时标记“待券商核对”，不得用估算值覆盖历史事实。

### 7.3 询问每日计划

1. 用户选择目标交易日并发起任务；系统生成任务编号，冻结输入清单和文件版本。
2. 更新阶段仅拉取一次持仓、标的池和 15 个板块的日线，写入 `支撑/data/`；随后计算一律读取本地数据。
3. 任务依次展示：更新数据、检查持仓、扫描标的池、形成情景、生成草稿、等待确认，并始终处于第 10.2 节唯一状态机中的一个状态。
4. 草稿必须覆盖市场与板块、概率合计、全部持仓、新机会、资金约束、风险和数据缺口，并区分“明日可执行”和“预判候选”。
5. 未经确认的草稿标记“计划情景 / 待确认”，不得成为最新正式计划，也不得触发交易。
6. 用户可拒绝、要求重算或按 D4 决策确认。确认发布前再次核对输入版本；冲突时当前预览失效，状态保持“待确认”并要求基于新输入重算，不能直接发布。
7. 获得 D2-A 或 D2-B 授权后，确认发布可写入 `交易计划/明日交易计划_{YYYY-MM-DD}.md`，并按既有规则归档旧计划。选择 D2-C 时只能导出变更清单。
8. 只有选择 D2-B 时，标的池研究状态才进入 MVP；候选变更必须逐项展示，确认粒度与事务关系按 D4 执行。D4 未决时默认与计划分开确认、独立事务；拒绝标的池变更不影响独立完成的计划发布，历史计划只移动、不改写。

MVP 不能直接调用现有每日任务的全部写入步骤而跳过预览。尤其是执行位计算只展示、不回写 `当前持仓.md`，这是相对现有 `定时任务/每日交易计划.md` 的产品边界。

### 7.4 分析股票

#### 输入范围

- 必填：A 股或 ETF 代码/名称；分析截止交易日，默认最近完整收盘日；
- 必选或明确未知：短线、波段、长线、仅研究、角色未知；
- 可选：用户问题、已有持仓关系、拟观察周期；
- MVP 一次只分析一个标的，不做全市场自动筛选。

#### 输出结构

1. 数据健康：来源、复权、截止时间、缺失字段；
2. 行情与量价事实：价格、1 日/5 日涨跌、MA20 位置、量比和所属板块；
3. V26 量化结果：角色明确时按所属策略逐项展示通过/未通过/无法计算、最早可执行日和失效条件；“仅研究/角色未知”时固定显示“不适用/待确定角色”；
4. 研究评分：角色明确时按所属策略研究章节展示分项，不与 V26 信号合并；“仅研究/角色未知”时固定显示“不适用/待确定角色”；
5. 组合影响：权限、现金、模块、持仓数、行业集中度；
6. 人工判断和实盘例外：单列证据与局限；
7. 结论：继续观察、条件不足、形成信号或不适用。形成信号也不是自动投资建议或订单。

“仅研究/角色未知”时只展示可核实的行情、量价、板块、数据健康和通用组合事实，并列出计算 V26、研究评分仍缺少的角色及输入；不得试算多个策略后挑选较优结果，不得跨策略套用规则，也不得输出“形成信号”。长线缺点时基本面时必须显示“资料不足，需专项复核”；池外标的不得自动加入标的池，角色变更或入池需后续人工确认流程。

### 8.2 写入通用规则

任何已获授权的写入都必须满足：

1. 展示将修改的文件、字段和前后值；
2. 使用输入快照版本做乐观冲突检测；
3. 使用单一事务编号覆盖全部相关写入和审计记录；
4. 在完整成功前不暴露半完成状态；失败时恢复到写入前状态并保留失败审计；
5. 历史事实只追加，不能通过“撤销”删除；
6. 策略参数、量化配置和已发布历史计划禁止由业务页面修改；
7. 自动计算执行位只读展示，不属于可写字段。

结构化迁移或双写不属于 MVP。未来若提出，必须先完成全量校验、冲突优先级、可逆迁移、双写一致性监控和回滚演练，并经真实用户单独批准。

### 10.1 通用页面与写入状态

| 状态 | 用户看到的内容 | 系统行为 |
|------|----------------|----------|
| 首次加载 | 稳定布局、模块级加载状态 | 不显示 0，不用旧值冒充今日 |
| 空持仓 | “暂无持仓”，市场和分析仍可用 | 组合盈亏不计算，成交录入可用 |
| 延迟 | 最后有效交易日、受影响模块、原因 | 可查看旧值；风险和计划标“待更新” |
| 部分可用 | 每个数据组独立成功/失败 | 仅计算输入完整的结果，不全页阻断 |
| 数据缺失 | 缺失字段、文件或标的及影响 | 不推测价格、指标、信号或执行位 |
| 来源冲突 | 来源、时间、差异和冲突字段 | 冻结相关衍生结论和写入 |
| 节假日/停牌 | 交易日历或停牌说明 | 不作为系统错误，不伪造新数据 |
| 401/403 | 认证或权限/额度说明 | 停止任务，保留最近成功时间 |
| 429 | 限流和可重试时间 | 按规范最多重试，不能无限等待 |
| 5xx/网络失败 | 失败阶段、最近成功时间 | 最多重试 1 次后停止，支持重新发起 |
| 写入冲突 | 源版本已变化和可查看差异 | 取消旧预览，要求基于新版本重试 |
| 写入部分失败 | 事务失败、恢复结果、审计编号 | 不暴露半完成事实；恢复失败需阻断后续写入 |

### 10.2 每日计划唯一状态机

每日计划任务和计划版本只能使用下表八个状态。阶段进度（更新数据、检查持仓等）不是状态，不能另建“排队、完成、取消”等同义状态。系统重启或页面刷新后必须恢复原任务编号和状态，不得重复发布。

| 状态 | 进入条件 | 允许操作 | 恢复/退出条件 | “最新正式计划”资格 |
|------|----------|----------|---------------|----------------------|
| 生成中 | 新任务已冻结输入快照，至少一个生成步骤正在执行，且尚无可复核草稿 | 查看阶段、取消本次运行并记为“已拒绝”；不能确认或发布 | 全部发布门槛数据与草稿生成成功 -> 待确认；存在缺数据但保留可核验结果 -> 部分成功/缺数据；无可用草稿或不可恢复错误 -> 失败 | 无 |
| 部分成功/缺数据 | 至少一个步骤成功且结果可查看，但任一发布所需数据、全部持仓覆盖、正式市场状态或概率校验不完整 | 查看成功/失败范围、补数据后重算、拒绝；不能确认或发布 | 补齐后发起重算 -> 重算中；用户放弃 -> 已拒绝 | 无；部分结果只能作为带缺口的草稿证据 |
| 失败 | 无可复核草稿，或任务因权限、网络、解析、规则冲突等错误终止 | 查看失败阶段/错误/最近成功输入，修复后重新发起；可拒绝 | 重新发起同目标日的新任务 -> 生成中；用户结束 -> 已拒绝 | 无 |
| 待确认 | 发布所需字段、数据截止时间、情景概率、持仓覆盖和证据校验均通过，形成冻结草稿 | 按 D4 确认、拒绝、要求重算、查看差异；不能修改草稿后绕过重算 | 确认且写入成功 -> 已发布；拒绝 -> 已拒绝；重算 -> 重算中；输入冲突则保持待确认但旧预览失效 | 无 |
| 已拒绝 | 用户明确拒绝草稿、结束失败/部分结果，或取消尚未形成草稿的运行 | 查看拒绝原因、复制为新任务 | 再次生成创建新任务 -> 生成中；原任务保持已拒绝 | 无，终态 |
| 重算中 | 用户从部分成功/缺数据或待确认要求重算，并冻结新的输入版本 | 查看新旧输入差异和阶段；取消本次重算并记为已拒绝；不能确认旧预览 | 完整成功 -> 待确认；仍缺数据 -> 部分成功/缺数据；无可用草稿 -> 失败 | 无；被重算的旧草稿仍非正式 |
| 已发布 | 用户按 D4 完成确认，输入版本复核通过，计划写入/归档事务完整成功 | 查看正式版本、证据和确认记录；基于新输入发起新任务；不得编辑已发布正文 | 目标交易日结束或不再可执行 -> 已过期/被替代；同目标日新版本完整发布 -> 已过期/被替代 | 有，但仅限目标交易日尚有效、未被同目标日更新版本替代的最新一个已发布版本 |
| 已过期/被替代 | 已发布计划超过目标交易日有效期，或同目标日更高版本已发布 | 只读查看、下钻替代版本/历史证据；可发起新任务 | 终态，不允许恢复为已发布 | 无；历史入口保留，不出现在“最新正式计划”位置 |

状态转换不得覆盖历史事件。任一时刻至多一份计划满足“最新正式计划”资格；若没有符合条件的已发布版本，总览必须显示“当前无正式计划”，不能回退展示待确认、部分成功、失败、已拒绝或已过期版本。D2-C 未授权发布时，任务即使校验完整也只能停在待确认并导出，不能伪造“已发布”。

## 十一、隐私、安全与审计

- MVP 仅监听本机回环地址，默认不向局域网或公网暴露；持仓、计划、策略和审计数据不上传云端。
- Token 不进入页面、URL、日志、导出文件或仓库；产品只显示数据源状态，不显示凭据内容。
- 所有写操作要求本地用户主动确认；无自动下单、无券商凭据、无后台自动投资建议。
- 审计最少记录：事务/任务编号、操作类型、本地操作者、时间、输入版本、前后值摘要、受影响文件、确认结果、失败和恢复结果。
- 审计记录追加保存；敏感字段导出前提示。日志不得记录 Token，不应重复保存完整持仓快照之外的无必要隐私副本。
- 规则或板块口径变更后，旧结果保留原版本；不得用新规则反向改写旧计划和历史成交结论。

## 十二、可验证验收标准

### 12.1 数据与总览

1. 使用 2026-07-29 仓库快照，总览显示总权益约 148,573.4 元、证券市值 123,193.4 元、现金约 25,380 元、当日盈亏 -159.4 元，并可下钻到 8 个持仓；误差只允许来自明确标记的费用估算。
2. 同一快照列出半导体设备 ETF 减仓观察已触发、波段持仓数/模块超限、同行业集中度超限；相关例外不能显示为 V26 退出信号。
3. 市场状态同时显示交易日、15 板块口径、综合指数、慢均线、20 日斜率和计算来源。目标日任一必要板块缺失时，不生成新的正式状态。
4. 每个价格、执行位、量化信号和计划动作都能查看来源、截止时间、计算/生成时间、规则版本和证据类型。

### 12.2 执行位

5. 对规则输入完整的短线、波段和长线测试持仓，系统按对应策略生成结果、生效日和计算明细；不得跨角色套用规则。
6. 缺少入场日期、原始买入价、信号日或股性字段时，相关执行位显示“无法重算”或“实盘例外”，并沿用值与新计算值严格分栏。
7. 关闭并重新打开页面后，仓库中不出现由执行位自动计算产生的修改；相同输入和规则版本得到相同结果。
8. 任何移动保护位计算低于已生效保护位时，展示值保持原位并说明“只能上移”。

### 12.3 成交录入

9. 用户可完成增仓、减仓、清仓和先卖后买做 T 四种夹具流程；确认前看到数量、成本、现金、费用、策略层和集中度的前后差异。
10. 对可卖数量、T+1、100 股/份交易单位、零股清仓、做 T 顺序、策略和组合约束的测试夹具，系统逐项给出第 7.2 节规定的硬阻断、风险提示或实盘例外，未来计划不能通过例外绕过硬约束。
11. 对卖出超过总持有量、卖出超过本地可卖量但不超过总持有量、全部剩余零股清仓三种夹具，系统分别进入硬阻断、核实后实盘例外、正常清仓；任一已发生券商事实及其证据均可在待核对或例外记录中找到，不因入账被阻止而丢失。
12. 模拟确认前源文件变化时，写入被阻止并展示冲突；模拟第二个文件写入失败时，当前持仓和流水恢复一致，且保留失败事务审计。
13. 更正预览列出原事务、原值、更正值、差额及数量/成本/现金/风险的更正后结果；确认后当前持仓与更正当月流水在同一事务中一致更新，原月原文保持不变并可沿事务链追溯。
14. 在当前持仓补偿写入后、当月更正事件完成前注入失败，系统恢复到更正确认前的数量、成本和现金；恢复失败时阻止后续写入。重复提交同一更正事务不得重复补偿。

### 12.4 每日计划

15. 用户可触发一次盘后计划任务，并看到更新数据、检查持仓、扫描、生成和待确认阶段；行情只在更新阶段拉取一次，阶段名称不被当作任务状态。
16. 以八个状态各一份夹具验证第 10.2 节的进入条件、允许操作、退出条件和刷新/重启恢复；系统不得产生表外状态或因恢复重复发布。
17. 模拟单标的行情缺失、HTTP 429、单板块日期滞后和来源冲突时，任务显示影响范围并进入“部分成功/缺数据”或“失败”；未受影响模块仍可查看，但不能伪造信号、正式市场状态或已发布计划。
18. 草稿区分“明日可执行”和“预判候选”；后者显示仍缺条件和最早执行日。情景概率不合计 100%、全部持仓未覆盖或发布必需数据缺失时不能进入可发布的待确认结果。
19. 未确认、部分成功、失败、已拒绝和重算中的任务均不出现在正式计划入口；同一目标日两个版本先后发布后，只有后者为最新正式计划，前者自动成为“已过期/被替代”。超过目标日后总览显示当前无正式计划。
20. 确认发布发生版本冲突时旧预览失效并要求重新生成，不覆盖新内容；发布后只新增目标日计划并按规则移动旧文件，历史计划内容不改变，执行位计算结果不回写 `当前持仓.md`。
21. 在 D2 未决、D2-C 或标的池变更未按 D4 完成确认的夹具中，产品不写标的池；选择 D2-B/D4-A 或 D2-B/D4-B 时，拒绝标的池变更不影响独立完成的计划发布事务；选择 D2-B/D4-C 时任一写入失败则组合事务整体回滚。

### 12.5 股票分析与边界

22. 对同一角色明确标的，页面分栏展示行情事实、V26 条件、研究评分、组合影响、人工判断和例外；研究评分不能改变 V26 条件通过数。
23. 对“仅研究”和“角色未知”各一份夹具，V26 与研究评分均显示“不适用/待确定角色”，页面只展示可核实事实和缺失条件，不试算或推荐任一策略。
24. 长线点时基本面缺失时，不输出“可执行”，而显示缺失字段、影响和专项复核要求；池外标的不会自动入池。
25. 390×844 视口无横向滚动且文字不重叠，仅作为响应式自检；产品不宣称手机可通过单机地址访问。
26. 未获用户确认前，系统不得发起付费订阅、云端上传、盘中实时、自动下单、结构化迁移或自动生成未获批准的投资建议。

## 十三、成功指标

MVP 上线后以连续 20 个交易日或至少 10 次有效使用为首轮观察窗口：

| 指标 | 目标 | 采集边界 |
|------|------|----------|
| 盘后只读核验时长 | 中位数不超过 3 分钟 | 从数据已就绪到用户完成风险核验，不含任务运行 |
| 数据新鲜度可识别率 | 100% 的核心模块显示截止交易日 | 本地审计统计，不上传行为数据 |
| 无确认写入 | 0 次 | 所有正式写入都有确认记录 |
| 写入一致性事故 | 0 次半完成事实 | 事务和恢复测试 + 实际审计 |
| 风险证据可追溯率 | 100% | 每项风险可到来源与规则版本 |
| 成交录入成功率 | ≥95%，排除用户主动取消和规则拦截 | 本地任务结果 |
| 每日计划任务完成率 | ≥90%，数据源不可用单列 | 不把部分数据伪装为成功 |
| 人工直接编辑次数 | 较基线下降，目标由用户复审时确认 | 只记录产品内完成任务，不监控外部编辑行为 |

这些指标衡量效率和可信度，不衡量收益率、胜率、交易频率或推荐采纳率，避免产品诱导交易。

## 十四、依赖、风险与缓解

| 风险/依赖 | 影响 | MVP 要求 |
|-----------|------|----------|
| Markdown 结构变化 | 解析或写入错位 | 版本/哈希校验、固定字段契约、冲突即停止 |
| 多文件非原子写入 | 持仓和流水不一致 | 事务日志、预写、恢复和失败演练 |
| iFinD 额度、缓存和 T-1 | 今日结论失真 | 目标日校验、最多重试、最后有效值不冒充今日 |
| 13/15 板块口径变更 | 历史不可比 | 保存口径版本，禁止静默连线 |
| 实盘例外缺输入 | 执行位无法重算 | 显式例外、缺失字段和沿用值，不推测 |
| 费用和成本口径不明 | 盈亏与现金偏差 | 区分券商事实和估算，待用户复审 |
| 生成计划被误当建议 | 误交易风险 | 草稿/正式状态、条件与失效、人工确认、无下单 |
| 本地故障或误删 | 历史丢失 | 按 D6 执行备份/快照、追加审计和恢复验证；不得默认写入云同步目录 |

## 十六、评审门禁与开放问题

### 16.1 开发启动门禁

1. 项目经理确认本文、路线图和设计模板字段完整；

无论选择哪项，云同步默认禁止。未来若要将备份放入云同步目录，必须另行说明数据位置、访问者、删除和恢复风险，并取得真实用户明确授权。

### 16.3 简短回复格式与组合约束

真实用户可直接回复六项组合，例如：`D1-A / D2-A / D3-C / D4-A / D5-B / D6-A`。该示例是产品建议组合，不是预选结果。

- D4-C 仅与 D2-B 兼容；其他 D2 选择下，标的池没有同屏确认对象。
- D1-B 或 D2-C 会使对应流程停留在预览/导出，项目范围和成功指标需在设计前同步调整。
- D2-B 会把标的池研究状态写入升为 MVP P0；D2-A/D2-C 则保留在 v0.2。
- D3-B 的“2 个交易日”是该选项的一部分；不接受该时限时应选择 D3-A/D3-C，或提出新选项后再评审。
- D6 只决定备份体验，不授权云同步，也不改变 Markdown/CSV 的事实源地位。
