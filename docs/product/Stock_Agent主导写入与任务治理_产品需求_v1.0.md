## 一、产品结论

系统由“GUI 优先、Agent 增强”调整为“Agent 主导业务写入、页面负责查询与治理”。凡是由用户发起、会改变投资业务事实的操作，都必须先由 Agent 理解上下文、完成校验并调用领域工具；页面不再维护一套并行业务录入逻辑。

页面继续承担以下职责：

- 查询、筛选、对比、下钻和结果解释；
- 确认或拒绝 Agent 生成的领域变更提案；
- 当前策略的真人批准或拒绝；
- 定时任务的启停、立即运行和失败处理；
- 模型、执行模式、数据备份等系统治理操作。

脚本型定时任务不进入本阶段。任务类型继续限定为数据源任务、结构化分析任务和 Agent 任务。

## 二、目标与非目标

### 2.1 目标

1. 新标的进入短线池或长线池前，必须由 Agent 完成完整评估。
2. 成交、调整、备注和资金快照只允许 Agent 通过组合账户领域工具写入。
3. 新定时任务及 Agent 任务提示词只允许 Agent 创建或修改。
4. 页面不保留可绕过 Agent 的业务写入表单和 HTTP 写入口。
5. Agent 工具直接表达业务动作，减少“发现表结构—拼装查询—理解结果”的重复链路。
6. 领域 service、确认制、YOLO、数据库写锁、状态冲突检测和审计继续生效。

### 2.2 非目标

- 不允许 Agent 直接写表、执行原始 SQL 或绕过领域 service。
- 不把行情同步、指标计算等系统自动事实伪装成 Agent 决策。
- 不改变当前策略必须由真实用户批准的门禁。
- 不建设任意命令、任意脚本路径或用户参数执行器。
- 不因为页面只读而删除任务控制、策略审批和确认卡。

## 三、业务写入权限矩阵

| 业务动作 | Agent | 页面 | 系统任务 |
|----------|-------|------|----------|
| 新增、更新、结束标的池角色 | 提案或 YOLO 执行 | 仅查看、确认 | 禁止 |
| 记录成交、调整、备注 | 提案或 YOLO 执行 | 仅查看、确认 | 仅允许已定义的结算沉淀 |
| 维护资金快照 | 提案或 YOLO 执行 | 仅查看、确认 | 允许受控券商/任务快照 |
| 创建、修改任务定义与提示词 | 提案或 YOLO 执行 | 禁止直接创建或编辑 | 禁止自我改写 |
| 启停、立即运行、处理失败 | 可执行 | 保留直接入口 | 调度器按定义执行 |
| 发布当前策略 | 只能创建待审提案 | 真实用户批准或拒绝 | 禁止 |
| 行情、板块、指标同步 | 可触发受控任务 | 可触发既有任务 | 领域任务直接写入 |

## 四、新标的进入标的池流程

1. 用户向 Agent 提出标的名称或代码及预期角色。
2. Agent 使用标的检索工具确认标准代码、资产类型和行情能力。
3. Agent 查询当前策略、池内角色、板块关系、行情、财务估值和已有分析。
4. 数据不足时先使用受控数据获取或分析工具补齐；无法补齐必须列明缺口。
5. Agent 输出角色、分级、研究评分、股性、阶段、标签、所属板块和评估依据。
6. 同一标的不能同时拥有两个当前策略角色；角色变化必须结束旧角色后原子建立新角色。
7. Agent 调用标的池领域工具生成确认提案；确认或 YOLO 执行后进入池。
8. 未完成评估、所属板块缺失或关键数据不足时，不允许进入池。

## 五、持仓事实录入流程

1. 用户通过文字、结构化描述或图片告诉 Agent 成交或资金事实。
2. Agent 必须复述标准代码、方向、数量、价格、日期、归因和金额。
3. 缺少必填字段时先追问，不猜测成交价格、数量或日期。
4. Agent 调用组合账户领域工具生成结构化确认卡。
5. 确认后由组合账户 service 原子维护事件流、当前持仓和实时资金台账。
6. 页面只展示事实、来源、归因、审计和更正入口；更正仍通过 Agent 发起。

模型或服务暂不可用时，可以把用户原始文字或图片保存在当前对话草稿中，但不得提前改变持仓事实。恢复后由 Agent 继续解析和确认。

## 六、定时任务治理

### 6.1 创建与修改

- Agent 可创建或修改 `datasource`、`analysis`、`agent_flow` 三类受控任务。
- Agent 任务必须绑定版本化提示词；运行固化实际提示词版本和当前策略快照。
- 页面删除创建任务、编辑 cron、编辑任务类型和直接编辑提示词的入口。
- 创建或修改仍经过 `job_write`、状态基线校验和审计。

### 6.2 页面保留能力

- 查看任务定义、下次运行、运行历史、输出和失败原因；
- 启用或暂停任务；
- 立即运行既有任务；
- 针对失败任务重试或打开来源 Agent 对话；
- 不允许页面直接改变任务正文、cron、类型或提示词。

## 七、Agent工具与提示词原则

- 系统提示词只维护系统全貌、事实源映射、权限边界、任务路由和工具选择原则，不复制全部表结构。
- 高频动作使用独立领域工具：标的检索、标的池完整评估与写入、组合账户写入、任务写入、板块查询、行情与指标查询。
- 每个工具描述必须说明适用场景、必填字段、来源、数据截止时间、失败语义和写入边界。
- 通用 `database_schema` / `database_query` 继续作为低频与未知查询兜底，不作为高频业务动作默认路径。
- Agent 不得根据模型记忆猜测表字段、价格、指标、角色或策略结论。

## 八、验收标准

1. 页面不存在添加标的、记录成交、创建任务或编辑任务提示词的业务表单。
2. 对应旧 HTTP 写入口返回 404，Agent 领域工具仍可完成同一业务结果。
3. 新标的缺少角色、评分、阶段或板块时，领域工具拒绝入池且零写入。
4. 一笔成交由 Agent 提案、真人确认后，事件流、当前持仓、资金台账和审计在同一事务一致更新。
5. 任务中心可启停、立即运行和查看失败，但不能直接创建或改写任务定义。
6. Agent 创建的任务只能属于三类受控任务，任意命令或脚本配置被拒绝。
7. 确认制、YOLO、策略真人发布门禁和数据库写锁回归通过。
