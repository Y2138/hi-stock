# 期货行情页改版交互设计

2026-11-23。推荐方案为「行情工作台」，交 DM 实现。目标页面 `/futures`，保留现有入口。

## 目标与现状

用户在做 A 股研究时打开期货页，第一眼要看清选中的品种、价格走势、数据日期，再按需查看换月、仓单和缺口。首期按桌面查单品种优先设计，窄屏保持可用。这个使用优先级来自当前任务与页面用途，尚无操作频次数据。

| 已核对项目 | 设计依据 |
| --- | --- |
| 浏览器现页 | 打开本机 `/futures` 后默认没有行情，先看到两个下拉框和覆盖表。选沪金主连后走势仍是表格，映射和仓单以原始数据块展示 |
| 现有路由与组件 | `web/src/views/FuturesView.vue`；沿用市场结构页的标题、面板、页签及状态标签。`web/src/components/KlineChart.vue` 可复用 ECharts 渲染与缩放交互，现有格式器固定使用元和手，期货需提供单位配置或单独适配 |
| 现有接口 | `GET /api/futures` 提供目录、最近数据日和同步覆盖。`GET /api/futures/:code?limit=100` 提供日线、映射、仓单。详情默认按日期倒序，图表需升序。目录不提供各合约最新价格，品种列表不为展示涨跌另发批量详情请求 |
| 数据约束 | 覆盖目标日和当前系列最后一根日线可能不同。主连、真实合约、其他序列需清晰区分。仓单按详情接口实际命中的代码展示，空响应不能解释成零仓单 |

## 主路径与数据映射

1. 进入页后读一次目录。优先恢复仍存在的上次品种和系列，无可用记录时选沪金，目录没有沪金则选首个品种。只保存选择偏好。选品种时清掉上一个品种的详情，默认选择目录声明的供应商主连。若无主连，选最新有日线的真实月份合约，同日按代码排序。无数据的主连仍可选，空状态可建议手动查看可用合约，不自动换系列。目录中的加权或无法可靠识别的代码单列「其他系列」，不当真实月份合约默认选中。
2. 详情请求只针对当前系列，默认取最近100条日线，30/60/100日按钮按最近有效日线行数裁切，显示实际条数和日期范围，不额外拉取。以最新一根为收盘指标，走势图按日期升序、明细最新在前。日涨跌为相邻交易日收盘比较，日期相邻性无法核验时用「较上一条日线」或留空；结算与持仓只读当前合约同日字段。
3. 页首显示当前系列代码、类型、实际行情日及来源。覆盖目标日晚于行情日时，明确写出两者；过期价格仍可作为历史走势查看。日线空时直接显示缺口，图表不挂演示序列。单位来自目录或源的明确标记，使用最小变动价位或有效精度；不明的单位标「单位未披露」。
4. 数据区设四个页签。日线明细展示日期、OHLC、成交量、结算、持仓、来源；换月映射展示日期、实际合约、方法和来源，真实合约显示「真实合约无换月映射」；仓单展示报告日、数量、原单位与来源，未命中就说明「当前系列无已存仓单记录」；数据覆盖按当前品种展示类型、目标日、最新日和写入／应有数，缺口展开成原因列表，禁止直接显示 JSON。供应商主连可显示「换月规则未披露」且映射不全时不推断。

## 状态与交互验收

| 状态或场景 | 用户看到的处理 |
| --- | --- |
| 目录加载、空或请求失败 | 首屏骨架保留布局；空目录说明暂无已存期货；失败提示「读取期货目录失败」并提供重读按钮，页面不触发取数任务 |
| 快速切合约 | 立即更新标题和加载状态。使用取消或请求序号保护，迟到响应不得把旧品种价格填到新标题下；重读只请求当前系列 |
| 部分缺数、陈旧和零值 | 有效图表和表格继续可用，按字段显示「缺失」「未披露」「不适用」。真实零可显示为 0。不会用收盘替结算、用昨天的柱子补今天、用仓单推总库存或从相邻合约补行情 |
| 权限与键盘 | 只读页面，无交易、写入或同步按钮；遇到访问限制就提示。可用 Tab 完成品种与合约选择，页签按方向键切换并有焦点样式，加载和错误支持读屏。走势数据可从明细表逐日读取 |
| 桌面与窄屏 | 在桌面、Agent 面板展开及约390px窄屏下验证。品种名、价格日期和当前系列可读，页面本身不横向溢出，图表和表格容器可独立缩放或滚动 |

## 交接与最小验收

DM 主改期货视图，按需最小扩展现有图表的单位格式化，保留其他页面既有默认格式。沿用现有导航、API 和主题。首期只处理行情浏览和缺口表达，无新行情源、数据库迁移或同步流程改动。若现有响应缺名称或单位等字段，先按缺失展示，避免扩大后端改造。

在本机浏览器核对三个场景：首次进入自动显示有效系列或明确空状态；一个真实合约与一个主连之间切换，实际数据日、映射和单位都能辨认；一个部分缺数品种仍可查看历史走势，并能在两步内找到缺口原因。再覆盖快速切换、空目录、空详情和失败重读。运行 `npm run web:typecheck` 与 `npm run web:build`，交付桌面和窄屏截图。PM 已走查原页与接口代码，本稿为设计交付，尚无改版页面可验证。

## 期货行情查看与每日入库实施口径

### 状态与边界

2026-11-16 PM定稿，供DM做能力核验与实施清单；不表示接口能力已验证或数据已入库。目标是服务A股研究的期货查看、目录与日线日更，不做期货下单、账户或保证金系统。不同时改股票策略与分析师提示词。

复用现有commodity-service领域service、market_instrument、market_bar、market_futures_contract、market_futures_daily_detail、market_futures_roll及market_factor系列。已有service不足只新增字段/迁移，不另造数据库或外部Runner。当前合约输入已有交易所、品种、合约类别/月、乘数、价格单位、币种、最后交易日；tick与上市日期等尚须DM核对schema并补齐。

### 首批范围

日线与目录首批固定13个国内品种：CU铜、AL铝、AU金（上期所）；SC原油（上期能源）；LH生猪、I铁矿石、J焦炭、PP聚丙烯（大商所）；RB螺纹钢（上期所）；MA甲醇、TA精对苯二甲酸、UR尿素（郑商所）；LC碳酸锂（广期所）。CU/LC纳入统一验收，不因已有任务就跳过。

每品种包含全部目标交易日已上市未退市的真实合约与一条主力连续引用（展示如CU0/LC0，以内部稳定代码与外部别名映射处理）。不把主连当成可交易合约。首批不扩海外、不要求全商品全市场，但目录设计不写死13个；后续通过配置增加品种。

日更实际活跃合约不只取主力；目录有合约但无成交仍保留身份并标明状态。零成交可以是真实0，不等于OHLC和结算可填0。无成交无正式日线时记录缺数/不适用依据，不用前收伪造当日K线。

### 字段与单位

- 目录：内部代码、外部代码/别名、名称、交易所、品种、真实/主连类别、合约月份、上市日、最后交易日/退市日、乘数、最小变动价位、报价单位、成交量/持仓量单位、币种、状态、元数据来源、来源更新时间和抓取时间。未知为null并注明缺口，不猜默认乘数/日期。保证金及手续费非首期必需，不用静态目录替代实际费率。
- 日线market_bar（freq=futures_day）：交易日、OHLC、成交量、成交额（有则存）、来源、抓取时间、价基/调整口径。真实合约原始价，不套股票复权。
- 每日明细：结算价、前结算、持仓量、涨跌停价（可取得则存），source与fetched_at；可取得的持仓变化等保留为有单位的明细。收盘与结算分列，绝不互相替代。日线和明细按同合约同交易日关联，实际存储唯一键与修订由DM确认。
- 合约粒度必须含交易所，外部简写月份需依据目录解析为YYYYMM，不能把郑商所三位码凭当前年份推断后永久落错。
- 时间：trade_date以交易所为准，夜盘归下一交易日，不按采样自然日切K线；source_as_of、published_at/available_at（能取得时）、fetched_at分别保存，未知发布时间不拿抓取时间伪装。
- 原始摘要仅保存必要公开数据与来源标识，不含密钥、鉴权URL或请求头。

### 主连与换月

主连优先使用来源明确提供的主力连续及其实际成分映射；必须记录method_code、来源、交易日、真实合约和调整方法。来源未披露换月规则就标source_defined/规则未披露，不编一条官方算法。不得混用不同供应商主连序列拼接而不标版本。

如供应商主连滞后，可构建单独标识的本地研究连续序列，而不是把真实合约价格冒充供应商主连：以目标交易日正式持仓量最大的合约为当日研究主力，持仓量并列保留前主力，再按成交量及合约代码确定。标method=local_oi_eod、未调整拼接、available_at不早于该日收盘资料可得时间，不能用于当日开盘前已知信号回测。真正用于前瞻换月须使用上一可得交易日数据，另标生效日与方法；不得混成一条方法。

LC0晚一天必须查清是接口落后、缓存/请求截止、调度时间还是映射问题：同一目标日真实合约与主连分别校验。可用本地研究主连时明确来源与方法，不覆盖旧供应商历史、不伪造其更新；若映射或数据不齐，报stale/缺口，不宣称日期一致已修复。

验收允许两种清晰结果：供应商主连与真实合约同目标日且映射完整；或供应商主连明确滞后、本地研究连续当日可用且独立标识。后者须主管认可其展示选择后才称LC缺口关闭；仅把旧日期改成今日不合格。

### 库存与仓单

首批13品种逐个登记是否支持，优先交易所公开仓单与库存；第三方转载必须保存原来源与单位。数据落现有market_factor_series/observation，区分inventory、warehouse_warrant、cancelled_warrant，不把仓单等同总库存。

原单位可能是手、张、吨等，原值原单位保留；只有明确且版本可追溯的换算系数才换算。发布周期可日/周，不要求周库存伪装当日日更；每条含统计日、发布时间、可得时间和抓取时间。没有交易所库存或该品种不适用就记unsupported/not_applicable及依据；不以0替代。

本期“能取全部落库”指首批品种逐项能力清单中可用的数据，不要求为填满字段无限新增付费源。源不可达/缺数显式报告。

### 日更、状态与补数

建议独立任务每日17:10 Asia/Shanghai启动（17点股票任务之后；具体共享限流与错峰由DM核对），按各交易所已完成交易日与资料发布时间确定目标。17:10资料未发布记not_yet_published，限次补跑：建议18:10、20:10；不在首轮就无限等待，不擅改分析师既有任务排期。分析师已到执行时间而数据未齐应看到缺口而非旧数充今日。

流程：更新目录→按目标日全活跃合约日线/明细→主连/映射→库存仓单→输出覆盖清单。相同目标日可重跑，幂等，源正式更正可更新但保留来源修订痕迹。一个品种失败不回滚其他已验证数据，整体不能标全部成功。

单字段/品种状态：ok、not_yet_published、missing、stale、unsupported、not_applicable、invalid、upstream_failed。字段带scope（品种/合约/数据种类）、target_date、latest_available_date、source、reason、attempt、next_retry_at（有则）。缺数不是零、不是“没有机会”。

任务聚合：success仅在承诺核心目录/行情/主连全部满足目标日且其他能力状态列全；部分品种或核心字段缺失为partial（若调度状态不支持则failed并带已完成计数）；全部0行或上游失败为failed。unsupported库存可以作为已声明非核心能力缺口，不把整个行情任务一票否决，但前台与摘要必须显示。过早执行可以延迟重试，补跑截止后核心缺数不得仍success。

### 查看与分析师取数契约

至少提供品种清单、真实合约/主连切换、日线、结算与持仓量、主连映射、库存/仓单与来源时间、最近同步覆盖和缺口查看；复用现有行情页/领域只读接口，不另建重UI。主连跳空/换月应可识别，不能把拼接收益当合约真实收益。

分析师数据读取先系统PG对应只读service/系统接口，只有该字段缺失、过期或不支持才走第三方API；外部补取结论标来源/统计期/取数时间，不把外部结果说成本库事实。外部取得的可持久化数据应交现有受控数据service写库，分析师不裸写SQL。凭据从PG设置服务使用，提示词仅引用配置状态/能力，不要求分析师读取明文密钥。

DM数据层落地后给实际schema与只读字段清单、来源能力与缺口；内容维护再协调两位分析师逐任务更新取数提示词及版本，记录任务编号/时间。此spec不提前修改任何任务或提示词。

### 验收与停止条件

1. 独立库验证新增迁移、目录与交易所/月份解析、幂等修订、夜盘交易日、零成交、非法OHLC和上游code非0场景，类型与相关定向/迁移/调度/前端验证按变更范围跑；不得在生产库测试。
2. 一次真实日更提供13品种×数据种类覆盖清单：应有/写入/更新/跳过/失败数、目标日和最新日，不能仅全库max(bar_date)掩盖单品种缺口。
3. 每个品种全活跃合约目录与日线覆盖有分母；OHLC与单位、结算/持仓独立校验。未上市/到期不误报缺当天行情；无交易日期按交易所日历不补造。
4. LC主连滞后给根因与处理证据；全部主连展示其方法、映射与实际数据日。库存仓单逐品种列支持/不可用及周期。
5. 同一目标日重跑不多记录；一个源限流/失败不把0行记成功，补数不覆盖正确来源为null。
6. 查看入口可读上述字段和缺口；真实部署按流程验证服务重启与接口，没部署不报已生效。
7. 核心日更、查看、缺口与LC处理验收后收口，不顺带加分钟采样、期货交易、海外全市场、全自动产业链映射或新策略。再由内容维护启动分析师提示词接入，不要求本轮补造所有历史数据。
