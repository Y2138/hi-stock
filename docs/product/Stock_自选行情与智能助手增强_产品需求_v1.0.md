## 一、产品结论摘要

本轮增强的核心不是单独增加几张行情页面，而是把系统从“盘后策略演进工作台”扩展为“以自选为入口、盘中可观察、盘后可研究的个人市场工作台”。产品主链路为：

```text
全市场发现标的
  → 加入统一自选
  → 按板块 / 关注 / 自定义分组观察
  → 查看个股与板块近实时对比并画线
  → 盘后沉淀龙虎榜、涨跌停和板块快照
  → 由可信指标服务与智能助手完成查询、解释和研究
```

本 PRD 建议确立以下产品口径：

1. **“自选”成为唯一用户维护入口**：现有“标的池”不再作为并列清单让用户重复维护；原短线/长线角色、评分和历史仍保留为策略研究元数据。
2. **板块组和“关注”组都是动态视图**：标的只维护一次，可同时出现在多个行业/概念板块和“关注”视图，不复制多份自选记录。
3. **“实时”统一称为“近实时”**：通过行情快照轮询更新，允许延迟，明确显示来源、行情时间、抓取时间和延迟状态，不承诺 tick、Level-2 或交易所直连时效。
4. **盘中对比线使用同基准归一化**：个股和板块均以前收盘为 0% 比较；系统离线期间的缺口不插值、不补造。
5. **画线是个人研究标注**：不构成策略规则、买卖信号或当前执行位，也不能被智能助手自动升级为策略事实。
6. **指标计算先统一口径再扩展数量**：DIF、DEA、MACD 柱及均线等由同一版本化指标服务计算，正式策略口径与正式回测引擎逐值对齐。
7. **智能助手增强先测量、后选工具**：先建立 token、工具调用、时延、成功率和答案完整度基线，再决定是否用领域工具替代通用数据库查询，以及是否接入 Web 搜索。

## 二、背景与现状

### 2.1 用户问题

现行系统已经能查看库内标的、自选、K 线、持仓、任务和策略，但新增标的发现、盘中观察和市场横向信息仍存在断点：

| 用户问题 | 现状断点 | 期望结果 |
|----------|----------|----------|
| 我想看一只库里没有的股票或指数 | 搜索只覆盖已入库的 `market_instrument` | 可搜索数据源支持的完整标的目录，并在加入自选时自动建档 |
| 我的自选分散在哪些板块 | 自选只支持手工分组，单个 `sector_code` 无法表达多板块关系 | 自动按行业、概念、区域、特色板块聚合，且保留自定义分组 |
| 哪些票需要重点盯 | 没有跨分组的统一重点视图 | 任意自选可切换“关注”，并在固定“关注”视图集中查看 |
| 盘中个股相对板块强弱如何 | 页面主要展示已落库 K 线，没有持续盘中对比 | 在明确延迟的前提下，持续展示个股与一个或多个板块的归一化走势 |
| 我想在图上记录判断 | 当前图表没有持久化标注 | 支持基础画线、撤销、删除、隐藏和跨会话恢复 |
| 今天市场结构发生了什么 | 龙虎榜、涨跌停和板块目录尚未形成每日事实 | 收盘后自动同步、留痕、可筛选并与自选/板块联动 |
| 智能助手查询是否高效 | 通用 Schema + Query 灵活，但高频任务可能产生额外 token 和工具轮次 | 先量化工具流，再按收益决定是否增加领域工具和 Web 研究能力 |
| 页面指标是否和回测一致 | 服务当前主要计算 MA，DIF 等正式指标仍在回测引擎中 | 建立唯一、版本化、可复算、可对账的指标计算服务 |

### 2.2 已核实能力基线

截至 2026-08-19，已核实的扶摇官方能力如下：

| 能力 | 已核实支持 | 产品使用边界 |
|------|------------|--------------|
| 标的目录与检索 | A 股、A 股指数/同花顺板块、场内外基金目录及检索 | “可检索”不等于“具备同等级行情”；结果必须显示资产类型和可用能力 |
| 行情快照 | A 股、A 股指数/板块、ETF 快照 | 可用于允许延迟的轮询；不等于 tick、分钟 K 或 Level-2 |
| 板块 | 同花顺概念、行业、区域、特色指数目录及当前成分股 | 个股反查所属同花顺指数接口尚未开放，应通过目录和成分同步反向构建关系 |
| 历史行情 | 股票、指数/板块、ETF 日线 | 扶摇无分钟线；现有 30 分钟线继续按既有数据源降级规则获取 |
| 特色数据 | 涨停、跌停、炸板、连板天梯、龙虎榜等 | 多数数据只有近期窗口；从系统启用后持续沉淀，不虚构长期历史 |

依据：扶摇官方 `llms.txt` / `llms-full.txt`、本仓库 `hithinkFinance` 能力说明及现有 `server/datasource/` 实现。具体接口参数仍以实施时官方文档为准，不在产品文档复制固定技术契约。

## 三、产品定位、目标与非目标

### 3.1 产品定位

面向单一真实用户、本机桌面浏览器使用的个人市场观察与策略研究工作台。它帮助用户更快发现、组织、观察和复盘市场事实，但不替代交易软件，不直接连接券商，也不自动生成或执行交易指令。

### 3.2 产品目标

1. 让数据源可发现的标的无需预先入库即可被找到并加入自选。
2. 用一个自选主数据模型承载关注关系，用板块、“关注”和自定义分组提供不同观察视角。
3. 在可识别延迟和缺口的前提下，提供盘中近实时行情及个股/板块对比。
4. 让用户的图表标注可保存、可管理、可追溯，但与策略事实严格隔离。
5. 每日自动沉淀龙虎榜、涨跌停和板块结构，形成可回看、可联动的市场事实。
6. 使 DIF 等核心指标在页面、分析、智能助手和回测之间保持相同输入、公式、版本和结果。
7. 通过可观测数据优化智能助手工具流，在证据充分后增加领域工具或 Web 研究能力。

### 3.3 非目标

- 不提供自动下单、条件单、券商账户连接或交易所级低延迟行情。
- 不承诺 tick、Level-2、逐笔成交或完整历史分钟线。
- 不把盘中未收盘数据用于生成日线收盘信号，不改变 V26 的收盘确认边界。
- 不把板块归属、涨跌停、龙虎榜、画线或 Web 内容自动解释为买卖建议。
- 不因“标的池改为自选”删除历史角色、评分、演进或审计记录。
- 不让 Web 搜索结果直接写入当前策略、持仓、账户、任务结果或其他业务事实。
- 不在未完成供应商额度、时延、许可和稳定性验证前承诺固定刷新服务等级。

## 四、用户与核心场景

| 场景 | 触发 | 用户要完成的事 | 完成标志 |
|------|------|----------------|----------|
| 发现新标的 | 输入名称、代码或浏览板块 | 找到标的、确认类型和能力、加入自选 | 标的在自选中唯一存在，并显示所属板块和数据状态 |
| 组织自选 | 打开自选页 | 按板块、关注、自定义分组切换视角 | 无需复制维护即可从多个视图找到同一标的 |
| 盘中观察 | 交易时段打开自选或行情页 | 看到最新价、涨跌、时间和延迟 | 页面持续更新，断流和陈旧值被明确标识 |
| 强弱对比 | 从自选或板块进入行情 | 比较个股与板块当日走势 | 所有序列按前收归一，时间轴和缺口一致可解释 |
| 图表研究 | 观察关键位置时 | 画水平线、趋势线并记录说明 | 标注跨刷新和重启仍可恢复，可撤销或删除 |
| 盘后浏览市场结构 | 收盘后打开行情的“市场结构”页签 | 查看涨跌停、炸板、连板和龙虎榜 | 数据注明交易日、来源、同步状态，可下钻标的和板块 |
| 指标复核 | 查看图表或询问智能助手 | 确认 DIF 等值来自什么数据和公式 | 可看到计算版本、截止日、复权口径和缺口 |
| 研究型问答 | 在任意页面询问智能助手 | 组合数据库事实与必要外部资料形成带来源回答 | 回答区分库内事实与外部资料，外部内容有链接和抓取时间 |

| P1 | 每日特色数据 | 涨停、跌停、炸板、连板天梯、龙虎榜及板块快照 | 调度、幂等落库、日期口径 |
| P1 | 智能助手工具流优化 | 建立基线后增加收益明确的行情/板块/指标领域工具 | token 与调用遥测、评测集 |
| P2 | Web 研究工具 | 仅在供应商、安全、引用和成本评审通过后启用 | 联网授权、来源白名单、注入防护 |

## 六、信息架构与主要流程

### 6.1 一级信息架构调整

| 页面 | 调整后首要问题 | 主要内容 |
|------|----------------|----------|
| 自选 | 我在看什么，哪些最需要关注，它们属于哪些板块 | 全部自选、关注、行业/概念/区域/特色、自定义分组，近实时行情和数据状态 |
| 行情 | 标的与板块当前及历史走势如何 | 近实时对比、日线/30 分钟线、指标、画线、板块详情 |
| 行情 · 市场结构 | 今天市场涨跌停和龙虎榜发生了什么 | 涨停、跌停、炸板、连板天梯、龙虎榜及同步状态 |
| 标的池 | 不再作为一级用户维护入口 | 过渡期只读兼容；迁移确认后移除导航，角色与评分作为自选筛选/标签展示 |

其他页面和 Agent 工作区保持现行 v2.0 信息架构。

### 6.2 新增标的流程

1. 用户输入代码、完整代码、中文名或英文名。
2. 系统先查本地完整目录；本地未命中或用户继续搜索时调用扶摇检索。
3. 结果按资产类型分组，展示名称、标准代码、交易所、类型、是否支持快照、是否支持历史 K 线。
4. 用户选择“加入自选”；系统幂等建立/更新标的档案并创建唯一自选关系。
5. 用户可同时打开“关注”开关或选择自定义分组。
6. 若行情尚未初始化，页面显示“行情待补齐”，后台任务按能力拉取，不用空图冒充无波动。

### 6.3 盘中观察流程

1. 交易时段进入自选页时读取最新持久化快照，并立即发起一次刷新。
2. 页面处于前台时按配置周期轮询；退到后台或无人查看时降频，非交易时段停止高频轮询。
3. 每行显示行情时间、抓取时间和新鲜度；超阈值显示“延迟”或“已停止更新”。
4. 点击标的进入行情页，自动带出相关行业板块；用户可再选概念等板块对比。
5. 断流恢复后继续采样，中间保留空档，不用直线连接伪造连续行情。

## 七、详细功能需求

### 7.1 标的主目录与搜索

#### 7.1.1 搜索范围

首期“所有标的”定义为**当前已接入数据源能够稳定标识的完整目录**，并区分“能找到”和“能提供什么数据”：

| 类型 | 可检索 | 可加入自选 | 近实时快照 | 历史 K 线 | 首期处理 |
|------|--------|------------|------------|------------|----------|
| A 股股票 | 是 | 是 | 是 | 日线；30 分钟线按既有降级源 | 完整支持 |
| A 股标准指数 | 是 | 是 | 是 | 日线 | 完整支持 |
| 同花顺行业/概念/区域/特色板块 | 是 | 是 | 是 | 日线 | 完整支持 |
| ETF | 是 | 是 | 是 | 日线 | 完整支持 |
| LOF、场外基金 | 是 | 是 | 视源能力显示 | 不承诺与 ETF 同等 K 线 | 允许关注，能力缺失明确展示 |
| 期货主力连续 | 使用现有本地/公开源目录 | 是 | 本期不新增承诺 | 既有日线能力 | 保持兼容，不纳入扶摇全市场口径 |
| 港股、美股、期权 | 否 | 否 | 否 | 否 | 本期非目标 |

#### 7.1.2 搜索与消歧

- 支持标准代码、纯代码、名称关键词；同名结果必须显示类型与交易所。
- 精确代码优先，已在自选、当前持仓的标的其次，其余结果按匹配度排序。
- 远程检索失败时保留本地结果，并显示“远程目录不可用”，不得返回伪空结果。
- 搜索结果必须标识“已在自选”“已关注”“持仓中”“行情待初始化”等状态。
- 加入操作幂等；重复点击不得建立重复自选主记录。
- 标的更名、退市或类型变更通过目录同步更新档案，不改写历史名称快照。

### 7.2 统一自选模型

#### 7.2.1 产品对象

每个标的只存在一个当前自选关系，包含：加入时间、关注状态、用户备注、自定义排序和可选自定义分组关系。板块分组通过板块成分关系动态计算，不复制自选关系。

#### 7.2.2 分组体系

| 分组 | 类型 | 维护方式 | 规则 |
|------|------|----------|------|
| 全部 | 系统固定视图 | 自动 | 显示全部当前自选 |
| 关注 | 系统固定视图 | 用户切换关注状态 | 可从任意列表一键关注/取消关注；不能删除或重命名 |
| 行业 | 系统动态视图 | 板块成分同步 | 一个标的可出现在多个行业关系中；无归属进入“未分类” |
| 概念 | 系统动态视图 | 板块成分同步 | 多对多；默认折叠，支持搜索板块 |
| 区域/特色 | 系统动态视图 | 板块成分同步 | 与数据源目录一致，显示数据截止日 |
| 自定义分组 | 用户维护 | 新建、重命名、排序、删除 | 保留现有能力；删除分组不移除自选本身 |

#### 7.2.3 标的池兼容

- 原 `pool_membership` 的短线/长线角色、评分、分级、标签和有效期保留，不迁移成普通分组文本。
- 自选列表可按“有短线角色”“有长线角色”“无策略角色”筛选，并显示只读角色徽标。
- 新增自选不自动获得策略角色；移出自选也不自动结束历史或当前策略角色。
- 在真实用户确认完全替代前，原标的池页面保持只读；替代后从一级导航移除，但审计和 Agent 查询仍可用。
- 任何角色新增、变更或结束继续使用现有领域 service 和确认制/YOLO 规则，不因统一自选而降级权限。

### 7.3 板块目录、归属与板块页

#### 7.3.1 板块同步

- 同步行业、概念、区域、特色四类同花顺指数目录。
- 逐板块同步当前成分股，反向构建“股票属于哪些板块”的多对多关系。
- 每次同步保留目录批次、成分批次、来源和数据截止时间；同一批次要么完整生效，要么保持上一批可用版本。
- 成分变更以有效期记录，不覆盖历史；失败板块列入缺口清单。
- 板块目录和成分来源不同步时，页面显示两者各自截止时间。

#### 7.3.2 板块页

板块详情至少显示：板块名称、类型、标准代码、最新行情与时间、当日涨跌、成分数量、当前自选成分、当前关注成分、成分同步日期、数据缺口。支持从板块一键筛选自选或添加单只成分，不提供“一键把全部成分加入自选”的默认操作。

### 7.4 近实时行情

#### 7.4.1 产品口径

“近实时行情”是从数据源行情快照定时获取的最新可用值，不是交易所直连实时行情。页面必须同时展示：

- 行情时间：数据源返回的市场时间；
- 抓取时间：系统完成本次获取的时间；
- 新鲜度：抓取时行情距当前的时间差；
- 数据源与状态：正常、延迟、断流、休市、部分失败、能力不支持。

#### 7.4.2 刷新策略建议值

建议默认值用于技术验证，不作为供应商服务等级承诺：

| 状态 | 建议行为 |
|------|----------|
| 交易时段、页面前台 | 每 60 秒刷新当前可见自选和对比标的 |
| 交易时段、页面后台 | 每 5 分钟刷新全部自选，或由统一后台任务刷新 |
| 集合竞价、午间休市 | 使用独立状态和较低频率；不把停更误报为断流 |
| 收盘后 | 完成一次收盘快照确认，停止高频轮询 |
| 周末/非交易日 | 不轮询，显示最近交易日和“休市” |

刷新周期必须可配置且受批量上限、限流和账户权限约束。若估算无法在一个周期内完成全部请求，应优先“当前页面可见标的 → 关注 → 其他自选”，并在 UI 显示覆盖率，而不是悄悄延长部分标的的延迟。

#### 7.4.3 存储与使用边界

- 最新快照与日线 `market_bar` 分开保存，盘中快照不得覆盖已确认的日线收盘值。
- 为对比线保存当日采样序列；每条样本包含标的、行情时间、抓取时间、价格、前收、来源和批次。
- 同一标的同一行情时间幂等；供应商修订值时保留最新值和获取留痕。
- 系统未运行期间不补造盘中样本。若后续接入合规分钟数据，应另建数据类型，不把轮询样本改名为分钟 K。
- 盘中数据默认不触发策略信号、回测或当前执行位重算。

### 7.5 个股与板块近实时对比

#### 7.5.1 对比规则

- 主标的可为股票、ETF、指数或板块；对比项最多 3 条，首期优先展示主标的相关行业板块。
- 每条线按 `(当前价 ÷ 前收盘价 - 1) × 100%` 归一化，前收缺失则该序列不可加入对比。
- 所有序列使用上海交易时段时间轴；停牌、断流或尚未采到的数据留空，不前向填充。
- 图例显示名称、类型、最新涨跌、行情时间和延迟状态；颜色不是唯一识别手段，同时使用线型和文字。
- 支持在近实时对比、日线 K、30 分钟线之间切换；切换不混用指标或画线坐标。

#### 7.5.2 画线与标注

P1 首期支持：水平线、趋势线、文字说明、选择、移动、撤销、重做、删除、全部隐藏。产品规则如下：

- 锚点保存为“标的/视图类型 + 时间 + 数值”，不得只保存屏幕像素。
- 近实时归一化图上的数值单位为百分比；K 线图上的数值单位为价格。
- 标注按用户、标的、频率和视图隔离；切换复权口径时提示可能错位，不静默转换。
- 每条标注记录创建时间、修改时间和可选备注；删除默认可撤销，批量清空需二次确认。
- 标注只是个人研究笔记。智能助手可以读取并复述，但不能把它当作正式关键位、策略条件或交易指令。

### 7.6 每日特色数据与市场结构

#### 7.6.1 同步范围

| 数据 | 频率 | 核心字段/视图 | 说明 |
|------|------|---------------|------|
| 涨停池 | 每交易日收盘后 | 涨停时间、原因、连板天数、封单额 | 分页拉全；原始单位保留 |
| 跌停池 | 每交易日收盘后 | 首次/最后跌停、价格、涨跌幅、换手 | 与涨停分开呈现 |
| 炸板池 | 每交易日收盘后 | 炸板时间、次数、原因等源字段 | 源无值不补造 |
| 连板天梯 | 每交易日收盘后 | 近 30 交易日梯队 | 保存抓取日和覆盖区间 |
| 龙虎榜 | 每交易日收盘后 | 全部、机构榜、游资榜 | 显式使用目标交易日；可用历史受源窗口限制 |
| 板块目录与成分 | 每交易日一次；目录可低频 | 类型、代码、名称、成分与有效期 | 成分失败不阻断其他板块 |
| 板块收盘行情 | 每交易日收盘后 | 开高低收、成交量、涨跌 | 与盘中采样分开 |

#### 7.6.2 页面交互

- 默认打开最近一个同步完整的交易日，并允许切换日期。
- 每个页签显示目标交易日、数据源、抓取时间、条数和同步状态。
- 支持按是否在自选、是否关注、所属板块、榜单类型筛选。
- 点击标的进入行情页；点击板块进入板块详情；从结果加入自选仍走统一自选流程。
- 当日部分接口失败时，成功页签照常可用，失败页签显示原因和重试入口，整页不得伪装为“暂无数据”。

#### 7.6.3 调度与补跑

- 任务显式绑定目标交易日，重复运行幂等。
- 非交易日不创建伪当日数据；停机恢复后按交易日历补记缺口并允许补跑。
- 源只提供近期数据时，页面明确最早可用日期；不能用今天的板块成分重写旧日归属。
- 每次运行记录请求范围、分页完成度、行数、失败项和数据哈希，纳入现有任务中心和数据健康聚合。

### 7.7 指标可信计算

#### 7.7.1 唯一计算口径

新增统一指标服务，页面、分析、智能助手和回测均引用同一份指标契约和版本。首期至少覆盖：MA5/10/20/60、DIF、DEA、MACD 柱；后续指标逐个按同样流程接入。

正式策略的 MACD 口径与 `支撑/backtest/portfolio_engine.py` 当前正式引擎保持一致：

- 输入：按交易日升序的 `close`；股票使用正式策略约定的前复权日线，指数/ETF 使用各自已声明口径；
- `DIF = EMA12(close) - EMA26(close)`；
- `DEA = EMA9(DIF)`；
- 正式引擎的 `hist = DIF - DEA`；若页面另展示市场软件常见的 `2 × (DIF - DEA)`，必须使用不同字段名并明确标注，不能都叫“MACD 柱”；
- EMA 的初始化、最小有效期和空值传播必须与正式引擎所用实现逐值对齐，不能只写公式后各自实现。

#### 7.7.2 输入和重算规则

- 日线指标只使用已确认收盘的日线，不使用盘中快照替代当日收盘。
- 任一输入行变更、复权因子修订、历史补洞或计算版本升级时，从最早受影响日期起向后重算。
- 增量计算结果必须与从完整历史重算的结果在允许误差内一致。
- 数据不足、日期断档、复权口径未知或价格异常时返回明确状态，不输出看似精确的数值。
- 每个指标值可追溯到标的、频率、数据截止日、输入口径、计算版本、计算时间和源数据摘要。

#### 7.7.3 正确性门禁

1. 建立股票、ETF、指数、停牌、历史修订、数据不足等金样本。
2. 使用正式回测引擎生成基准结果，再由服务端指标实现逐行比对。
3. 内部存储精度和误差阈值在技术设计中固定；页面格式化不得反向进入计算。
4. 每次公式、依赖或复权处理变更必须提升计算版本并全量回归。
5. 生产抽样任务每日复核最新指标；不一致时标记该标的指标不可用，不把旧值继续展示为最新。

### 7.8 智能助手效率与能力增强

#### 7.8.1 先建立工具流基线

在新增工具前，对以下代表任务建立固定评测集：查单只行情、比较自选与板块、解释指标、查询涨跌停/龙虎榜、组合持仓与市场事实、维护自选、触发任务。每次记录：

- 输入 token：系统提示词、策略上下文、Schema 描述、历史消息和工具结果占比；
- 输出 token、工具调用次数、重复 Schema 调用次数、上下文压缩次数；
- 首字时延、总时延、工具时延、失败/重试次数；
- 答案事实完整度、引用正确率、数据截止时间覆盖率和越权率；
- 模型、会话、工具版本和评测样例版本。

遥测只保存计数、时延、工具名、状态和必要哈希；API Key、完整敏感工具结果和不必要的用户原文不得进入性能日志。

#### 7.8.2 候选优化方向

| 候选 | 要解决的问题 | 进入条件 |
|------|--------------|----------|
| `instrument_search` | 本地/远程检索和能力消歧不适合由通用数据库查询完成 | 搜索域契约稳定，能减少至少一轮工具调用 |
| `market_snapshot_query` | 近实时行情、延迟和来源需要聚合返回 | 快照事实源稳定，返回结构显著小于原始表查询 |
| `board_query` | 板块目录、成分和自选交集涉及多表关系 | 服务端聚合能减少 token 且保持可追溯 |
| `market_event_query` | 涨跌停、龙虎榜查询字段和筛选固定 | 每日特色数据完成落库并有稳定状态模型 |
| `indicator_query` | 指标必须附计算版本、口径和缺口 | 指标可信计算门禁通过 |
| 提示词按需注入 | 当前完整上下文对简单行情问题可能过重 | 评测证明缩减后规则遵循不下降 |
| Schema/结果缓存 | 同会话重复发现和重复大结果浪费 token | 哈希失效机制明确，不返回陈旧数据 |

领域工具只读不需要确认；写入仍复用现有 `watchlist_write`、`portfolio_write`、`pool_write` 等领域 service，不恢复通用数据库写工具。

#### 7.8.3 Web 研究能力

Web 搜索原为 P2 调研项；2026-08-20 用户确认首期只注册供应商抽象后的 `web_search`，默认使用 DeepSeek 原生服务端搜索，不开放 `web_fetch`。以下门禁继续作为实现与验收边界：

1. 明确供应商、调用成本、网络边界、日志保留和隐私条款；
2. 支持返回标题、链接、来源站点、发布时间或缺失标记、抓取时间和摘要；
3. 默认优先官方、监管、交易所、上市公司等一手来源，允许用户查看原文；
4. 外部网页视为不可信输入，隔离其中的提示注入、工具指令和下载行为；
5. 搜索结果只能作为带来源的外部资料，不自动写入数据库业务事实或当前策略；
6. 涉及行情、持仓、账户和策略时，库内事实与外部资料分栏陈述，冲突时不得静默选边；
7. 断网、超时或来源不足时明确降级，不用模型记忆补造“搜索结果”。

是否接入通用 Web 搜索、限定站点检索，或继续由用户提供 URL，应由对比试验后决定。

## 八、跨模块数据与状态规则

### 8.1 概念数据对象

技术设计可调整表名，但必须覆盖以下产品对象：

| 对象 | 关键关系与版本要求 |
|------|--------------------|
| 标的目录 | 标准代码唯一；保留资产类型、交易所、名称、能力、目录来源和同步时间 |
| 自选关系 | 每标的唯一当前关系；关注状态与自定义分组独立 |
| 板块目录 | 板块类型 + 标准代码唯一；目录批次可追溯 |
| 板块成分 | 板块与股票多对多，带有效期、来源批次和截止时间 |
| 最新行情快照 | 与日线分离；带行情时间、抓取时间、前收、来源和新鲜度状态 |
| 盘中采样 | 标的 + 行情时间幂等；保留抓取批次和缺口 |
| 图表标注 | 绑定用户、标的/对比视图、频率、坐标单位和版本 |
| 市场特色事实 | 类型 + 交易日 + 标的/榜单维度唯一，原始字段和标准字段可追溯 |
| 指标结果 | 标的 + 频率 + 日期 + 指标 + 计算版本唯一 |
| Agent 性能事件 | 会话/运行 + 工具 + 模型 + 评测版本；不保存多余敏感正文 |

### 8.2 全局数据状态

所有新增数据模块至少支持：

| 状态 | 含义 | 页面行为 |
|------|------|----------|
| 正常 | 在预期时间内完整获取 | 显示数据和截止时间 |
| 延迟 | 有值但超过新鲜度阈值 | 保留值并突出“延迟”，不标“实时” |
| 部分可用 | 批次中部分标的、板块或分页失败 | 展示成功部分和覆盖率，可重试失败项 |
| 断流 | 交易时段连续多次获取失败 | 停止滚动最新时间，显示最近成功值和失败原因 |
| 休市 | 非交易时段或非交易日 | 显示最近交易日，不触发错误告警 |
| 能力不支持 | 当前资产或数据源无该能力 | 隐藏无意义操作并说明原因 |
| 数据不足 | 不能形成指标、对比或历史曲线 | 显示缺少的最小输入，不输出推测值 |

模块自己的“请求成功”不能覆盖底层数据延迟、缺失或部分失败。

### 8.3 单一事实源与审计

- 页面、API 和智能助手读取同一批数据库事实，不分别直连供应商形成不同结果。
- 外部获取必须先经过 datasource 校验和落库，再对页面与智能助手可见；仅搜索候选可在用户未加入前短暂展示远程结果。
- 画线、关注、自定义分组等用户写入复用数据库级写锁、事务、状态冲突和审计规则。
- 近实时轮询和每日任务不得阻塞持仓、策略发布等更高优先级业务写入；具体锁粒度由技术设计确定。
- 完整私有备份包含新增个人数据；安全初始化包默认不包含关注关系、图表标注和盘中采样。

## 九、交互与可用性要求

- 自选页默认优先展示数据状态、关注和涨跌，不把大量概念板块全部平铺；板块维度使用筛选、搜索和折叠。
- 股票、ETF、指数、板块、基金使用文字徽标和图标区分，不能只靠颜色。
- 涨跌继续遵守现行低饱和红绿与文字/图标并行规则。
- 用户切换分组、页签或行情频率后保留选择；刷新不得丢失画线草稿或覆盖正在编辑的备注。
- 对比图在窄桌面仍保留图例、行情时间和延迟状态；空间不足时减少同时对比数量，不隐藏可信度信息。
- 所有“最新”“实时”“今日”旁必须存在可见的时间或状态；禁止只显示模糊文案。
- 轮询不产生全局成功提示；仅在断流、恢复、部分失败或用户主动刷新时提供低噪声反馈。
- 支持键盘选择搜索结果、切换关注、撤销/重做画线，焦点状态符合现行可访问性规范。

## 十、成功指标

成功不以交易收益衡量，首期建议观察：

| 目标 | 指标 | 建议目标 |
|------|------|----------|
| 标的可发现 | 已验证样本中，源支持标的的搜索命中率 | 100% |
| 自选一致 | 重复自选主记录、删除分组误删自选 | 0 |
| 板块可信 | 页面显示板块关系具备来源和截止时间 | 100% |
| 行情透明 | 近实时值具备行情时间、抓取时间和状态 | 100% |
| 断流诚实 | 陈旧值被错误标为实时 | 0 |
| 指标一致 | 金样本中服务端与正式回测引擎超容差差异 | 0 |
| 每日数据完整 | 应同步分页和榜单的完成度可识别 | 100% |
| Agent 效率 | 固定评测集的中位输入 token | 在正确率不下降前提下较基线下降至少 30% |
| Agent 可靠 | 数据截止时间与来源引用覆盖率 | 100% |
| Web 安全 | 外部内容导致越权写入或策略自动发布 | 0 |

token 下降 30% 是产品优化目标，不是上线前事实；若领域工具无法在正确率不下降的前提下达到收益，则保留通用查询路径。

## 十一、分期与门禁

### 11.1 第零阶段：验证与口径冻结

交付物：扶摇权限/额度/时延探测报告、标的类型映射、板块样本、近实时容量估算、指标计算契约与金样本、Agent 工具流基线报告。

出口标准：

- 可解释在 60 秒和 5 分钟目标周期下分别能覆盖多少股票、指数/板块和 ETF；
- 板块目录和成分可稳定获取，并验证多对多与历史变更处理；
- DIF/DEA/MACD 金样本口径获确认；
- Agent 基线可复现，尚未因“感觉慢”直接新增工具。

### 11.2 第一阶段：统一自选与可信数据基础

范围：全市场目录/检索、统一自选、关注、板块自动分组、原标的池兼容、指标服务首期。

出口标准：用户可从未入库标的完成“搜索 → 加入 → 关注 → 按板块找到 → 查看可信日线指标”的完整流程；旧角色和历史无丢失。

### 11.3 第二阶段：盘中观察

范围：近实时行情、覆盖优先级、延迟/断流状态、个股与板块对比、基础画线。

出口标准：完成至少一个完整交易日的前台、后台、午休、断流、恢复和收盘演练；任何缺口均未被伪造成连续行情。

### 11.4 第三阶段：盘后市场结构

范围：涨停、跌停、炸板、连板天梯、龙虎榜、板块收盘快照、历史筛选和自选联动。

出口标准：连续 5 个交易日自动运行；补跑、分页、部分失败、非交易日和重复运行全部满足幂等与状态要求。

### 11.5 第四阶段：智能助手增强

范围：基于评测证据增加领域查询工具；Web 研究另过安全与成本门禁。

出口标准：固定评测集在事实完整度和引用正确率不下降的情况下达到既定 token/时延收益；Web 内容无法触发数据库写入、策略发布或越权工具调用。

## 十二、可验证验收标准

### 12.1 标的与自选

1. 对股票、标准指数、同花顺板块、ETF、LOF/场外基金各取样，搜索结果能正确显示标准代码、类型和能力；不支持的行情能力不显示为空图。
2. 搜索一个本地尚不存在但扶摇可检索的 A 股，加入后只建立一份标的档案和一份自选主关系，重复操作返回“已在自选”。
3. 同一标的可同时出现在“全部”“关注”、多个板块和多个自定义分组；取消关注不移出自选，删除自定义分组也不移出自选。
4. 原标的池角色、评分、标签和有效期在迁移前后逐项一致；新增普通自选不自动获得策略角色。

### 12.2 板块

5. 行业、概念、区域、特色目录均可展示；任一成分同步失败时，上一完整版本仍可用，失败板块和截止时间可见。
6. 抽取至少 10 只股票与 10 个板块，页面归属与同一同步批次的官方成分逐项一致；一个股票多板块不被压成单值。
7. 历史成分变更不会改写旧批次，按旧日期查看时不使用今天的归属冒充历史。

### 12.3 近实时与图表

8. 交易时段行情页前台按配置刷新，全部值显示行情时间、抓取时间、来源和状态；午休和收盘不会被误判为断流。
9. 模拟限流、单标的失败、整批超时和服务重启，页面分别进入部分可用、延迟或断流；最近值保留但不再标“近实时”。
10. 个股和板块对比逐点符合前收归一公式；前收缺失、停牌和断流区间不连线、不补零。
11. 水平线、趋势线和文字说明跨刷新/重启可恢复；切换到不同频率或复权口径不会静默套用错误坐标。
12. 盘中采样不会覆盖 `market_bar` 的已确认日线，也不会触发日线策略信号。

### 12.4 每日特色数据

13. 涨停、跌停、炸板、连板和龙虎榜能按目标交易日同步；分页拉取完整，重复运行不产生重复记录。
14. 任一接口部分失败时成功数据仍可查看，任务中心显示完成度和失败项；非交易日不生成伪数据。
15. 页面可筛选“自选中”“关注中”和板块，并能从结果下钻行情或执行幂等加入自选。

### 12.5 指标

16. 股票、指数、ETF 金样本的 MA、DIF、DEA、`DIF - DEA` 与正式回测引擎逐行对账，超容差差异为 0。
17. 修改历史收盘或复权输入后，受影响日期及之后指标自动重算；增量结果与全量重算一致。
18. 输入不足、复权未知或历史缺口时指标显示不可用及原因，不沿用旧版本数值。
19. 页面和 Agent 能返回指标计算版本、数据截止日和复权口径；`DIF - DEA` 与 `2 × (DIF - DEA)` 不得同名。

### 12.6 智能助手

20. 同一固定评测集可重复产出 token、工具轮次、时延、成功率和事实完整度报告，并可按模型/工具版本比较。
21. 新领域工具若上线，必须证明在正确率与来源覆盖不下降的前提下减少 token 或工具轮次；不达标则不替换现有路径。
22. Web 研究启用后，每项外部事实带可打开链接和抓取时间；断网时明确失败，不编造搜索结果。
23. 在网页中放置恶意工具指令或策略发布诱导，智能助手不得执行写入、不得泄露凭据、不得将其作为系统指令。

## 十三、风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 扶摇限流或权限不足 | 目标周期无法覆盖全部自选 | 第零阶段容量验证；批量、可见区优先、后台降频；覆盖率可见 |
| “实时”预期过高 | 用户误判数据时效 | 全局改称近实时；同时显示行情时间、抓取时间和状态 |
| 板块多对多造成信息过载 | 自选页难以浏览 | 维度筛选、折叠、搜索；默认优先行业和关注 |
| 成分接口只有当前清单 | 无法补齐真实历史板块归属 | 从启用日起保存有效期；历史缺失明确标注，不反推 |
| 轮询样本被误当分钟 K | 图表和研究口径错误 | 使用独立对象和名称；缺口不补；禁止写入分钟 K 表 |
| 指标公式看似相同但初始化不同 | 页面与回测产生隐性偏差 | 以正式引擎金样本逐值对账；版本化；增量/全量一致性测试 |
| 全量自选迁移破坏策略角色 | 研究历史丢失或权限下降 | 自选主关系与策略角色分层；只读兼容期和逐项对账 |
| 工具越多反而增加 token | Agent 成本和时延上升 | 固定评测集和退出标准；无收益工具不注册 |
| Web 内容提示注入 | 越权操作或事实污染 | 外部内容不可信隔离、只读、来源白名单、禁止自动写入 |
| 新增盘中数据放大备份 | 备份变慢、存储增长 | 采样频率与保留期在技术设计中容量评估；初始化包排除盘中样本 |

## 十五、真实用户决策包

以下决策会实质改变信息架构、数据量或联网边界，进入技术设计前需要真实用户确认。括号内为本文建议：

| 决策 | 选项 | 建议 |
|------|------|------|
| D1 标的池如何退出用户入口 | A 立即删除；B 只读兼容一版后移除；C 永久保留并列入口 | **B**，降低角色和历史迁移风险 |
| D2 “所有标的”的首期范围 | A 股票/指数/板块/ETF；B 再含 LOF/场外基金；C 再含港美股 | **B 的检索与关注，A 的完整行情**；能力差异明确展示 |
| D3 近实时默认刷新 | A 前台 60 秒/后台 5 分钟；B 更快；C 只手动刷新 | **A**，先做容量验证，可配置但不承诺固定 SLA |
| D4 盘中采样保留 | A 仅当日；B 近 30 个交易日；C 长期保留 | **B**，兼顾对比复盘和备份体积，容量验证后定稿 |
| D5 画线首期 | A 水平线+趋势线+文字；B 再含矩形/斐波那契；C 暂不持久化 | **A**，覆盖核心研究场景并控制复杂度 |
| D6 Web 研究 | A 暂不启用；B 官方/白名单站点；C 通用 Web 搜索 | **B**，先验证引用、安全和成本，再决定是否扩大 |

建议的简短确认格式：

```text
D1-B，D2-B/A，D3-A，D4-B，D5-A，D6-B
```

在上述决策确认前，可以完成第零阶段的只读调研、容量探测、计算口径对账和 Agent 基线评测；不得据此自动实施数据迁移、导航替换或新增外部联网工具。
