# Stock 独立部署说明

本文是部署 Agent 的执行契约。部署目标是：只用本 Git 仓库和 Docker Compose 启动 Stock；同步当前策略与定时任务固定资产，不同步个人业务数据。

## 一、部署边界

Git 可以包含：源码、迁移、产品与技术文档、测试，以及人工确认的当前固定资产包。

Git 不得包含：`.env.local`、任何 API Key、PostgreSQL 数据卷、`datavolume/` 私有备份、附件、持仓与账户、持仓流水、标的池、行情、任务运行结果、聊天、分析或回测结果。当前允许提交的固定资产是：

- `bootstrap/stock_init_2026-08-21_135650.ndjson.gz`
- `bootstrap/stock_init_2026-08-21_135650.manifest.json`

该包只包含当前策略正文、策略演进摘要、策略使用的评分基准、定时任务定义、提示词及其版本，不包含历史策略版本。恢复命令只允许用于没有 `schema_migrations` 的空数据库。

> **固定资产包版本**：策略域已取消历史修订，可移植包格式由 v4 升到 v5（`strategy_document` 直接携带当前正文，不再有 `strategy_document_revision` 表）。恢复时按格式版本严格校验，v4 旧包会被明确拒绝（提示“不支持的初始化包格式”）。上述已提交的包是 v4，**不能**用于新电脑空库恢复；需要在真实用户确认后重新导出并提交一份 v5 包作为正式固定资产（届时同步更新本节的包名与 `.gitignore`/`.dockerignore` 白名单）。既有数据库不受影响：普通代码更新由启动迁移自动应用尚未执行的向前迁移。

## 二、目标电脑要求

- Docker Desktop，或支持 Compose v2 的 Docker Engine
- 可访问 npm、扶摇和所选 LLM 服务的网络
- 至少 2 GB 可用内存和足够的 PostgreSQL 持久化空间

无需在宿主机安装 Node.js、npm 或 PostgreSQL。服务无登录认证，只允许通过 `127.0.0.1` 访问，不得改成局域网或公网暴露。

## 三、首次部署

`git clone` 会自动下载源码和固定资产包，但不会自动修改目标电脑或写入数据库。以下步骤必须由目标电脑用户执行一次，因为它们涉及本机密码、空库确认和私有凭据。

```bash
git clone https://github.com/Y2138/hi-stock.git
cd hi-stock
cp .env.local.example .env.local
```

编辑 `.env.local`：至少把 `POSTGRES_PASSWORD` 改为仅含字母、数字、点、下划线、波浪线或连字符的本机专用密码，并让宿主机 `DATABASE_URL` 使用同一密码。不得在该文件填写扶摇或 LLM API Key。

先构建镜像并只启动数据库，再在应用容器中把固定资产恢复到空库：

```bash
docker compose --env-file .env.local build app
docker compose --env-file .env.local up -d postgres
docker compose --env-file .env.local run --rm app \
  npm run portable:restore -- bootstrap/stock_init_2026-08-21_135650.ndjson.gz
docker compose --env-file .env.local up -d app
```

不要在恢复前启动 `app`；应用启动会自动执行迁移，使数据库不再满足空库恢复条件。

首次部署的用户动作如下：

| 动作 | 是否必须 | 原因 |
|------|----------|------|
| 克隆仓库 | 是 | 获取源码与当前固定资产包 |
| 创建 `.env.local` 并修改数据库密码 | 是 | 本机私有配置不得由 Git 代填 |
| 执行一次固定资产空库恢复 | 是 | Git 只携带包，不自动写数据库 |
| 在设置页填写扶摇和 LLM Key | 使用对应功能时必须 | 密钥不随 Git 或固定资产同步 |
| 初始化行情与板块数据 | 按需 | 配置扶摇后手动运行数据任务，或等待定时任务；不会从旧电脑复制 |
| 初始化全市场历史日线（回测/研究需要时） | 按需 | 仅首次部署一次性引入：安装登录 `hithink-finance` CLI，`data init` 拉取批量导出，再 `npm run market:backfill -- --source duckdb`；之后日常更新由 `daily_data_update` 与 `market:fetch` 负责 |
| 复制持仓、流水或标的池 | 否 | 这些数据明确不跨电脑同步 |

结论：新电脑需要用户执行一次固定资产空库恢复，并在本机配置密码和所需 API Key；持仓、持仓记录、标的池等业务数据没有同步步骤，也不会自动从旧电脑带入。

## 四、验收

```bash
docker compose --env-file .env.local ps
curl --fail http://127.0.0.1:8787/api/health
docker compose --env-file .env.local logs --tail=100 app
```

浏览器打开 <http://127.0.0.1:8787/>，确认当前策略和七个定时任务存在，持仓、账户、流水、标的池和行情为空。随后在“设置 → 数据源凭据”填写扶摇 API Key，在“设置 → AI 模型与厂商”配置 LLM；接口不会回显密钥正文。

## 五、更新现有部署

现有数据库不得再次恢复固定资产包。普通代码更新执行：

```bash
git pull --ff-only
docker compose --env-file .env.local build app
docker compose --env-file .env.local up -d app
```

服务启动时自动应用向前迁移。两台已运行实例之间不做自动双向同步；策略或定时任务固定资产更新时，应在源实例重新导出并人工审阅新 manifest，再为新电脑初始化。需要给已运行实例增加受控导入时，必须另行设计冲突检测与真实用户确认，不能复用空库恢复命令。

## 六、数据持久化与回滚

Compose 使用 `pgdata`、`uploads`、`backups` 三个本机 Docker 卷，分别保存数据库、附件和私有备份。删除容器不会删除这些卷；禁止执行 `docker compose down -v`，除非真实用户明确确认要永久删除本机全部数据。

完整数据卷会包含密钥、持仓和运行历史，只能留在本机 `backups` 卷或另行加密保存，不得复制进 Git。固定资产包不能替代完整私有备份。

## 七、停止与诊断

```bash
docker compose --env-file .env.local stop
docker compose --env-file .env.local logs --tail=200 app postgres
```

Agent 临时代码回测开关默认开启（应用代码与 Compose 均为启用）。自由代码回测需要应用容器内可调用 Docker CLI 并访问 Docker 守护进程；当前镜像未安装 Docker CLI，也不挂载 Docker Socket，因此容器部署下该功能无法创建隔离容器、会明确失败，而行情、策略、任务和普通 Agent 功能不受影响。如需运行自由代码回测，优先在受控本机环境直接运行服务；不要为了便利把 `/var/run/docker.sock` 暴露给应用容器。

### 标准化日频研究回测

标准路径提供只读预检、不可变输入、异步运行、事件与每日结算、进度和取消、研究最终化及同口径比较；工作台通过 Agent 发起，HTTP 仍只读。标准回测不需要 Docker CLI 或 Socket，不执行自由源码。

维护者在本机 `.env.local` 设置 `STANDARD_BACKTEST_ENABLED=true`，按普通代码更新流程构建并重启后启用；默认关闭，页面和预检工具会提示开关状态。现有 `AGENT_BACKTEST_WORKER_ENABLED` 仍默认开启，独立控制自由源码研究，不受标准开关影响。不得为了自由源码运行挂载高权限 Docker Socket。

使用顺序：从回测页“标准回测”入口明确标的、区间、注册规则与费用 → Agent 调用 `preflight_backtest` → 数据可执行且开关开启时调用 `start_standard_backtest` → 在工作运行页或通过 `get_backtest_status` 查看 → 按需 `cancel_backtest` 或成功后 `finalize_backtest` 固化研究结论。提交立即返回运行编号，不能把排队成功说成回测完成；修改预检后的数据或计划须重新预检。取消写入终态后旧工作器无权继续落库。

全市场历史同步由用户外部流程维护，本功能不触发回填脚本或新增同步任务。当前消费 `market_bar`：原价研究优先读取完整的 `open_raw/high_raw/low_raw/close_raw`，没有原价时只允许显式未复权行；前复权研究必须显式选择并披露近似。成交量须明确为股数（`volume_unit` 为 `shares`、`share` 或 `股`），日历须覆盖研究起点前六年至结束日且包含非交易日。缺失、未知停牌和单位不会自动补零或推断。原始价列并不代表历史交易制度和公司行为已经被完整模拟。

首期研究预算为一百只股票、股票与环境/基准合计五十万行、压缩输入一百二十八兆字节；超预算拒绝，不静默裁样本。固定为收盘决策、后续开盘执行；可选基准复用指数日线，以正式窗口首个收盘归一，展示价格收益及收益差。费用/滑点为显式实验参数，不是系统确认的历史费率。每次只运行一个标准任务，子进程不继承数据库或供应商凭据。

`backtest_input_set`、`backtest_input_chunk`、`backtest_event`、`backtest_equity_daily` 只进入完整私有备份，不进入 Git 固定资产。冻结输入不可更新；最终化和取消均不删除运行材料。工作器与输入制品不齐时不能声称精确重放。

当前固定样本、成本、交易制度与公司行为近似统一为 `research_only`；成功或最终化不等于发布证据合格。新的策略提案若提供回测证据，必须满足完整结算和 `qualified` 资格；现有旧记录继续可读，但不自动取得该资格。不提供回测支持的人工策略发布仍须真实用户审核，不能宣称已经回测验证。

## 八、飞书任务结论推送

设置页按“模型、Agent、数据源、消息推送、外观”分区显示，默认收起右侧 Agent 工作区；需要对话时仍可展开。在“消息推送”中配置接收群与任务范围，通知历史从“通知记录”进入独立页面。

在飞书目标群的“群设置 → 群机器人”添加自定义机器人，开启签名校验，复制 Webhook 和签名密钥。在 Stock“设置 → 消息推送”填写并保存，点击“发送测试消息”，到“通知记录”查看状态，确认目标群收到连接测试后开启自动推送。若机器人同时设置关键词，需允许 `Stock`。

- Webhook 只接受 `https://open.feishu.cn/open-apis/bot/v2/hook/` 下的官方地址，禁止重定向，无需公网回调地址。
- 推送总开关默认关闭。任务范围默认“全部 Agent 任务”，包含以后新增的 Agent 任务，也可选择具体任务。每日计划、竞价复核、周中检查、周复盘等均可发送；同一任务的定时与手动运行遵循相同规则。数据同步等非 Agent 任务不推送。
- Agent 任务最终正文应包含“结论摘要”二级标题，用三至六条、不超过六百字概括最终判断，保留条件、风险与数据缺口。没有结论时写“暂无结论”。除每日计划外，服务只对成功且有明确结论的结果排队；每日计划在结论摘要、持仓预案、池内标的信号或打板机会预案至少一类有内容时排队，并固定分组展示这四类信息。标的信号取本轮近期关注全量对账结果，打板机会取本轮已激活结构化预案，各组为空时明确说明。每日计划通知最多 3200 个字符；内容较多时，各组只展示预算内的完整条目和剩余数量，不截断条件语义，完整内容回 Stock 工作台查看。失败结果和中间进度不推送。
- 任务结果与待发送通知在同一事务保存，后台约每五秒检查一次。通知失败独立重试，不重新运行 Agent 任务。不同任务的结果不会互相取消；同一任务、同一目标日期的新结果会阻止旧通知继续补发。
- “预览任务结论”仅在本机展示指定任务的最新成功结果，不发送消息。连接测试不含业务数据。结论可能包含持仓信息，请限定接收群成员。
- “通知记录”按任务、状态筛选，每页二十条，正文按需读取；历史记录保留，不随设置页展开。失败记录可补发原结论。
- 临时故障最多尝试三次，两次自动重试分别至少间隔一分钟、五分钟。机器人关键词等配置错误可在飞书修正后补发；本机凭据变更会取消旧队列，需等待新的任务结果。
- 关闭推送或取消某任务订阅会暂停相应待发送结果，连接测试不受影响。凭据变更、通知超过二十四小时或已有同任务同日期更新结果时停止发送。开启后不补推开启前的历史结果。
- 已开始的请求不能撤回；飞书已接收但本机未收到响应时，重试可能重复通知。“飞书已接收”不代表用户已读。
- 推送配置、订阅任务、密钥、结论及通知历史是本机私有数据，完整备份包含这些数据，Git 固定资产包不包含。新电脑恢复固定资产后推送关闭，需重新配置。
- 手机通知不附带不可达的 `127.0.0.1` 详情链接。完整结论回到 Stock 工作台按结果编号查看，不得为消息跳转暴露无认证服务。

普通代码更新启动时自动应用新增迁移，不要对已运行数据库执行固定资产空库恢复。

## 九、任务级模型与夜间板块筛选

`agent_flow` 定时任务可独立绑定模型。任务未指定模型时，在创建本次运行会话时继承系统当前模型；指定后，本次运行及其自动重试都固定使用该模型。数据同步和分析类任务不能指定模型。模型不存在、被停用、所属厂商被停用或缺少 API Key 时任务明确失败，不自动切换到其他模型。

“夜间板块机会筛选”在工作日 23:00（`Asia/Shanghai`）执行，固定使用 DeepSeek V4 Pro。任务完整扫描本地 881 一级行业，筛选最有机会的 1–3 个板块，每个板块最多保留 2 只优质标的；没有合格机会时允许输出“暂无符合条件机会”。完整报告保留在任务工作台，飞书只发送 `结论摘要`，摘要最多 600 个中文字符，超限时仅提示回工作台查看，避免截断触发条件和风险。

实际运行前，必须在“设置 → AI 模型与厂商”为 DeepSeek 厂商配置有效 API Key，并确认厂商与 DeepSeek V4 Pro 模型均已启用。任务模型绑定属于固定资产：导出时记录稳定的 `provider_key/model_key`，恢复时映射到目标实例的模型主键，不携带 API Key。

当前 Git 正式固定资产包仍是旧版本，尚未包含夜间任务。既有数据库升级后会通过迁移获得该任务；如需新电脑执行空库固定资产恢复后也直接具备夜间任务，必须在真实用户确认后重新生成、审阅并替换正式固定资产包。
